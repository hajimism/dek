# PowerPoint で開いて確かめること

[English](./README.md)

`dekc pptx` は、PowerPoint がどう描くかを見越して文字を組み直します。PowerPoint が実際にどう描くかは、確かめずに仮定しています。評価は Quick Look と Chromium で測りますが、どちらも PowerPoint ではないからです（[ADR 98](../../../adr/0098-space-a-pptx-s-characters-as-the-browser-s-features-did-name-a-face-a-script-and-deflate-the-file.md)）。このプロジェクトは、仮定したことをひと目で確かめられる 3 枚のスライドです。文字の組み方を変えたときと、それを含むリリースの前に、ファイルを作って PowerPoint で開いてください。

```bash
cd evals/pptx/hand-check
bun ../../../src/cli.ts pptx
```

ファイルは `decks/hand/dist/hand.pptx` です。どのスライドも PowerPoint の図形と文字だけでできていて、下に画像はありません。画面に見えているものは、すべて PowerPoint が描いたものです。黄色い帯は、その上の行をブラウザが組んだ幅と同じ幅の図形です。

## 最初に: ファイルが開く

PowerPoint が修復を提案せずにファイルを開くことを確かめます。Quick Look は、PowerPoint なら修復するファイルも開いてしまいます。CI も ECMA-376 のスキーマでは検証していません。PowerPoint が読める形になっているかを確かめられるのは、この確認だけです。修復を提案されたら、表示された内容と PowerPoint のバージョンを教えてください。

## 1 枚目: 行は帯の終わりで終わる

| 行 | 正しい状態 | 違っていたら |
| --- | --- | --- |
| 「台本」から、（発表）まで。 | 行が帯の左端から始まり、右端で終わる。かっこが隣の文字に重ならない。 | PowerPoint は、ランの字間を各文字の後ろ（最後の文字の後ろも）に足していません。 |
| 覚える書き方は三つだけです。… | 行が帯の右端で終わる。 | 長ければ同上。短ければ、PowerPoint はかなをカーニングしています。その分は字間にすでに入っています。 |
| AVATAR To We Type 1,234.56 | 行が帯の右端で終わる。 | 帯より長ければ、PowerPoint は、カーニングを始める大きさを指定していないランをカーニングしていません。行を選び、書式 → フォント → 文字幅と間隔で「カーニングを行う」を 1 ポイント以上にして、行が帯の終わりで終わるようになるかを、PowerPoint のバージョンと OS と一緒に教えてください。その結果で、`dekc pptx` が `kern` を書くかどうかを決めます（[ADR 98](../../../adr/0098-space-a-pptx-s-characters-as-the-browser-s-features-did-name-a-face-a-script-and-deflate-the-file.md)）。 |
| 字間をあけた行 SPACED | 行が帯いっぱいに広がる。 | 字間の付き方が `letter-spacing` と違います。 |
| 右に寄せた行。 | 行が帯の右端で終わる。 | PowerPoint は、最後の文字の字間を行の幅に含めていません。 |
| （中央に寄せた行） | 行が帯の中央にある。 | 同上か、始めかっこの左のアキの数え方が違います。 |

## 2 枚目: 段落はブラウザが折り返した位置で折り返す

- カードの段落は 1 行目が「持っている。」で終わり、文字がカードの中に収まっている。
- リストは 1 つのテキストボックスで、行頭記号が 3 つある。2 つ目の項目は 2 行になっている。行頭記号が `dekc shot hand blocks` の画像と同じ位置にあり、カードの文字がそれより下にずれていない。Quick Look は行頭記号を 20 ピクセルほど左に描きますが、PowerPoint がそうでなければ、Quick Look だけの癖です。
- カードの横の段落は 1 つのテキストボックスで、どの行も文節で終わっている。`dekc shot hand blocks` の画像と同じ位置で折り返している。
- スライドの見出しがタイトルになっている。アウトライン表示（表示 → アウトライン表示）に名前が出て、アクセシビリティチェック（校閲 → アクセシビリティ チェック）がスライドタイトルの不足を報告しない。
- 右下の「02 / 03」が、選択できる文字になっている。
- カードの横の段落の途中に何語か打ち込むと、ボックスの幅で折り返す。

## 3 枚目: 文字種ごとのフォントと、ブラウザと同じ太さ

- 1 行目の `code:` が Menlo、「台本」が Hiragino Sans で描かれ、ダッシュ、矢印、乗算記号が `dekc shot hand faces` の画像と同じ形に見える。
- 「Weight 600」と「Weight 700」の行が、それぞれ帯の終わりで終わる。終わらない行があれば、PowerPoint がそのファミリーの太字を、ブラウザとは違うウェイトで描いています。Chromium は Hiragino Sans の 600 を W6、700 を W7 で描きます。

## 同じファイルを Quick Look で測る

リポジトリのルートで次を実行すると、3 枚を Quick Look に描かせ、各行がブラウザからどれだけ離れているかを出します。

```bash
bun scripts/pptx-eval.ts --deck evals/pptx/hand-check/decks/hand
```

Quick Look は、ランの指定にかかわらず必ずカーニングします。そのため「AVATAR」の行の結果からは、PowerPoint がどうするかは分かりません。
