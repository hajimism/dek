# エージェント評価の記録

[English](./README.md)

ここにあるファイルは、エージェント評価 1 回分の記録です。AI エージェントが dek をどれだけ正確に扱えるかを、リリース間で比較するために残しています。リリースのコミットが入ったあと、そのチェックアウトで次を実行して記録します。

```bash
bun scripts/agent-eval.ts --runs 3 --record evals/agent/results
```

出力された `<日付>-v<バージョン>.json` はそのままコミットしてください。日付は評価開始日の UTC、バージョンは `package.json` の値（バージョンを上げるのはリリース PR のみ）が使われます。リリースコミットより前に計測した記録には、ひとつ前のリリースバージョンが付きます。同じ日付・同じバージョンで 2 回目以降を実行すると `-2`、`-3` と連番が付き、過去の記録は上書きされません。

各ファイルには、計測対象のコミット `commit`（`git rev-parse --short HEAD`。git チェックアウト外なら `null`）に加えて、シナリオごとの実行数・成功数・スキップ数、所要時間・`dekc` 実行回数・リトライ数・残存エラー数・残存警告数の中央値、および全実行を通じて hint なしで出たエラー数が記録されます。最後の lint で診断一覧を得られなかった実行は「残存エラー 1 件」と数え、残存警告の集計からは除きます（全実行で lint を取得できなかった場合、残存警告は `null`）。ファイルパス、トランスクリプト、エージェントが生成した文章はここには含めず、`.cache/agent-eval/` の完全レポートに残します。

1 回だけの結果は偶然に左右されます。一度成功したエージェントが次は失敗することもあります。3 回以上走らせた記録を使い、同じエージェント・同じ種類のマシンで計測した記録どうしを比べてください（マシンに入っているフォントの違いで行の折り返しが変わり、`DEK035` や `DEK036` の結果も変わるためです）。記録ファイル自体にはエージェント名もマシン環境も含まれないため、使ったエージェントのバージョンとマシン構成はコミットメッセージに書き残してください。
