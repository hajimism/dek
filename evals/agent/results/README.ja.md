# エージェント評価の記録

[English](./README.md)

ここにあるファイルは、それぞれエージェント評価の記録 1 回分です。エージェントが dek をどれだけうまく扱えるかを、リリースごとに比べるために残します。リリースのコミットが入ったあとで、そのチェックアウトで次を実行します。

```bash
bun scripts/agent-eval.ts --runs 3 --record evals/agent/results
```

書き出されたファイル `<日付>-v<バージョン>.json` は、そのままコミットします。日付は評価を始めた日を UTC で数えたもの、バージョンは package.json のもので、これを上げるのはリリースのプルリクエストだけです。そのコミットより前に作った記録には、ひとつ前のリリースのバージョンが付きます。同じ日、同じバージョンの 2 回目以降は `-2`、`-3` と続き、先の記録を上書きしません。

記録には、測ったコミット `commit`（`git rev-parse --short HEAD`。git のチェックアウトでなければ null）と、シナリオごとに、実行・成功・スキップの回数、時間・`dekc` の実行回数・繰り返し・残ったエラー・残った警告の中央値、そして全実行でヒントなしに dek が示したエラーの数が入ります。最後の lint が診断の一覧を出せなかった実行は、残ったエラー 1 件と数え、残った警告からは除きます。どの実行の lint も見られなかったときは、残った警告は null です。パス、トランスクリプト、エージェントが書いた文は入りません。それらは `.cache/agent-eval/` の完全なレポートに残ります。

1 回の実行は逸話にすぎません。1 度成功したエージェントが次は失敗することもあります。3 回以上の実行の記録を読み、同じエージェントで、同じ種類のマシンで作った記録どうしを比べてください。マシンにあるフォントで行の折り返しが変わり、DEK035 と DEK036 が見つけるものも変わります。記録にはエージェントの名前もマシンも入らないので、どのエージェントのどのバージョンか、どのマシンかはコミットメッセージに書いてください。
