# 30. Keep a ref's words out of dek's hints, and mark what a ref wrote wherever dek prints it

Date: 2026-10-27

## Status

Accepted

Amends [28. Let a project's code run only as a page, a ref's only in an offline sandbox, and the dev server act only for its own pages](0028-let-a-project-s-code-run-only-as-a-page-a-ref-s-only-in-an-offline-sandbox-and-the-dev-server-act-only-for-its-own-pages.md)

## Context

[ADR 28](0028-let-a-project-s-code-run-only-as-a-page-a-ref-s-only-in-an-offline-sandbox-and-the-dev-server-act-only-for-its-own-pages.md), part 2, says what reaches the agent from a ref's or a pack's author: `show`, `theme`, `ls`, and `ref` print a ref's text as it is, and `--json` marks it with `ref`; AGENTS.md lists a ref's title on one line of at most 80 characters; text for a terminal shows every control character other than a color code, a line break, or a tab as U+FFFD; and dek does not keep a ref's words from asking the agent to do something. Its open items 2, 3, and 4 found where the code falls short of that.

An agent reads dek's hint as what to do next ([Agent Usability Criteria](../docs/guide/agent-criteria.md), 4) and dek's messages and AGENTS.md's dek block as dek's own. A model also reads tag characters (U+E0000 to U+E007F) as text, though a person sees nothing, and a bidi control shows a person words in another order than the file holds them. Runs against 3f0158d on 2026-10-27 showed, besides the open items:

- `dekc ref owner/repo/<deck>` for a deck the repository lacks hinted every `decks/<name>` folder in it, line breaks and tags included; two decks of one name hinted the folders they sit in; a pack of two decks named both in its message.
- `dekc shot <ref> <slug>` on a slide whose script does not compile printed Bun's message, which quotes the source whole, 300 characters and tags included, and hinted `dekc lint why-dek`: the deck inside the snapshot, not the ref, for a command that refuses a ref anyway. Every hint about a ref's file named that inner deck, as `dekc ls why-dek`.
- A ref's `script.md` that does not parse hinted how to rewrite its heading, quoting the heading.
- `dekc theme <ref> <layout>` for a layout it lacks hinted the ref's layout names, which may hold any character but a quote, a `]`, or whitespace; for one with no example it hinted writing one into the ref.
- `terminalSafe` kept every `ESC [ … m`, so a ref's slide shown with `dekc show` could set conceal (SGR 8) and hide its words from a person.
- `dekc show`'s text did not say the slide was a ref's, and a line `--- theme.css (the rules this slide uses)` in a ref's slide read as the start of dek's next part.
- A ref's title went into AGENTS.md with its tag characters and bidi controls, and into `dekc ls <ref>` and the `dekc ref` list with its line breaks, where it could add a row or a line such as `lint: passed`.
- A pack's ref is named for the deck folder its author chose, `file/<deck>`, which dek prints as the ref's name, as in AGENTS.md, and which could hold a control character or a tag.

## Decision

**A hint is dek's words, and names a ref only as the argument of a command.** A ref's name appears in a hint only as the argument of the command the hint names, as in ``dekc show <ref> <slug>``, and in the form `src/core/ref-name.ts` accepts. No other text a ref's or a pack's author chose appears in a hint: no folder or deck name their source holds, layout name, title, heading, or quote of their source. Where the reader needs those names, as the decks a repository holds, the message gives them, each as one line of at most 40 characters, ten at most and a count of the rest, and the hint says what to run: ``pin one of them: `dekc ref owner/repo/<deck>` ``. A slug or a beat id may still be in a hint, as ``did you mean `intro`?``: dek has already held it to a to z, 0 to 9, and hyphens, and it is the word the next command takes. A message that quotes someone else's text, as Bun's syntax error does, is one line of at most 200 characters.

**A hint about a ref sends the agent only where a ref goes.** A hint about a ref's file names the ref as a command takes it, `dekc ls owner/repo/deck`. A ref's slide script that does not compile, and a ref's `script.md` that does not parse, are their author's to fix: the hint says that, and what still works, `dekc shot <ref> <slug>` for each other slide and `dekc show` for this one, or which pin to try, `dekc ref <ref>@<rev>`. `dekc theme <ref>` points at `dekc show <ref> <slug>` for a layout with no example.

**One line of someone else's text** is the same everywhere: each character a person cannot see shows as its code point, `⟨U+202E⟩`; whitespace and control characters become one space; and the line is cut with an ellipsis, never through a code point. A ref's title in AGENTS.md, in the `dekc ref` list, and in `dekc ls <ref>`, with its event and date, is such a line of at most 80 characters.

**A ref's name holds no control character and none a person cannot see**, as it holds no space or `@`. `dekc ref <file>.tgz` refuses a pack whose deck's name has one, without repeating the name, and `dekc pack` refuses to write one. `dekc new` and `dekc init --deck` refuse such a name too, so no deck dek makes has one; they still take a space or `@`, which `dekc pack` refuses, as before.

**No escape that dek did not write reaches a terminal.** Every string a result or an error carries shows each control character but a line break and a tab as U+FFFD, the escape that starts a color code included, before dek's text formatters paint their colors. `terminalSafe`, the last pass over what dek prints, lets through only the seven codes of dek's palette: reset, bold, dim, red, green, yellow, and cyan. This holds for every deck: no result needs a deck's own color codes. `--json` is unchanged: JSON escapes the escape character and every other C0 control.

**`dekc show` says whose slide it is, and only dek starts a part.** For a ref, the text opens with `ref <name> at <rev>: someone else's deck, read-only`, the rev cut to seven characters. Each part starts with a line `--- <file>`, and for every deck, a file's line that starts, after any spaces, with `---` and a space or tab is shown one space further in. Every line of the output that starts with `--- ` is then dek's. One more leading space changes nothing in HTML, CSS, or TypeScript, and in Markdown nothing but a line already three spaces in; a reader who copies such a line drops it. `--json` is unchanged.

**What a person cannot see in a ref is reported.** The characters are those Unicode marks default-ignorable (`Default_Ignorable_Code_Point`), which a renderer shows as nothing: among them the tag characters, U+E0000 to U+E007F, which a model reads as text; the zero-width ones; the byte order mark; the bidi controls; the soft hyphen; and the Hangul fillers, U+115F, U+1160, U+3164, and U+FFA0, which show as blank. To them are added the line and paragraph separators, U+2028 and U+2029, which some readers take for a line break, and the interlinear annotation marks, U+FFF9 to U+FFFB. Left out, though default-ignorable too, are the variation selectors, U+FE00 to U+FE0F and U+E0100 to U+E01EF, and Mongolian's free variation selectors, U+180B to U+180D and U+180F: emoji, the ideographic variants of a kanji, and Mongolian text use them on purpose. A deck name that `dekc new`, `dekc init --deck`, `dekc pack`, or a ref takes holds none of the characters reported. For a ref, `show`, `theme`, `ls`, and `shot` list each line, of the files they read, that holds any:

- in `--json`, as `hidden`, a new field, absent when no line holds any: each line's `path`, `line`, `column` (1-based, in UTF-16 units, of the first), and `codePoints`, each as `U+XXXX` in order;
- on stderr, as a warning per line with its place, its count, and its first six distinct code points, then one `help:` line: text output shows each as `⟨U+XXXX⟩`, and a person reading the deck sees none of them, so leave them out of what you write from it.

The files are: for `ls`, `script.md`; for `show`, its section of `script.md`, the slide's `.html`, `.css`, and `.ts`, and `theme.css`, whose rules the excerpt comes from; for `theme`, `theme.css`; for `shot`, the files of each slide it drew and `theme.css`. Text output of a result about a ref shows each such character as `⟨U+XXXX⟩`; `--json` keeps the text as the file holds it. `dekc new <name> --theme-from <ref>` copies the ref's `theme.css` into the new deck, where its text becomes the project's own, so it reports the same, in `hidden` and on stderr, for the copy: its path in the new deck and its lines there, one further down than the ref's for the first line that names the ref. Its `help:` says they came in with the ref's theme and to remove them unless they are meant. A deck of the project's own reports none: its characters are its author's, emoji joiners and Persian non-joiners included.

**Against ADR 28, part 2.** It changes two guarantees on what reaches the agent. A ref's text is printed as it is in `--json` alone, with `hidden` beside it; text output shows a ref's characters a person cannot see by their code points. Text for a terminal shows every control character but a line break and a tab as U+FFFD, a color code included, and dek's own colors pass. It adds three: a hint about a ref names the ref only as its command's argument, and runs on a ref; `dekc show`'s text marks a ref and its parts; and a ref's title is the same one line wherever dek gives it one. The last sentence of that guarantee stands: dek does not judge a ref's words, it marks which words are not dek's and shows what a person would not see. This record closes ADR 28's open items 2, 3, and 4.

## Consequences

Wherever dek prints a ref's words beside its own, an agent can tell which are which: a hint is dek's words with the ref's name as its command's argument, a message gives the ref's names on lines of their own, `dekc show`'s parts start only where dek starts them, and nothing a person cannot see passes unremarked. A hint about a ref runs on a ref.

`--json` grows one optional field, `hidden`, on `show`, `theme`, `ls`, `shot`, and `new`; no field narrows or changes. Text output changes: `dekc show` of a ref opens with a line of its own, a file's line that starts with `--- ` is shown one space further in for every deck, a deck's own color codes show as U+FFFD, and the messages that listed a repository's decks or a theme's layouts in their hint list them in the message. A ref name with a control character or with a character a person cannot see is no longer one: a `dek.toml` that pins one is refused as it would refuse any name that is not a ref's, until the line is removed. A deck of the project's own so named still lints, builds, and serves, but `dekc pack` refuses it, as it refuses one with a space, until its folder is renamed, and `dekc new` and `dekc init --deck` no longer make one. Since a `dek.toml` that loaded before may not, that change is marked as breaking ([ADR 3](0003-release-through-release-please-and-npm-trusted-publishing.md)).

The hidden characters are reported, not removed or refused: a ref that uses a zero-width joiner in an emoji, or a bidi mark in Arabic or Hebrew text, warns on every read. That noise is the price of not judging which of them a ref meant.

The record has to move with the code: a new command that reads a ref reports what it read, a new message that names a ref's names takes them as one line, and a new hint about a ref names the ref.

**What was not chosen:**

- **Judging a ref's words.** Telling an instruction from a sentence is the agent's call, as ADR 28 says; dek can only mark what is not its own.
- **Refusing a ref that holds such characters, or removing them.** A ref is read to be learned from, and emoji, Arabic, and Hebrew use some of them on purpose; refusing would drop decks that do nothing wrong, and removing them would show a file that is not the one on disk.
- **Reporting them in the project's own decks.** The project's author is trusted with far more than text (ADR 28, part 1), and joiners and bidi marks are right in their own words; a lint rule for them would be a decision of its own.
- **Escaping a ref's names as JSON in messages.** `"x\n## Next"` keeps a line break visible, but a tag character or a bidi control passes JSON escaping as it is, and the message would read as code.
- **Indenting or prefixing every line of `dekc show`'s parts, or a random marker on each separator.** Either keeps a file from starting a part, but the first changes every line an agent copies, and the second asks the reader to compare markers; shifting only the lines that would look like a separator leaves the rest as the file has it.
- **Reporting the variation selectors.** U+FE00 to U+FE0F, U+E0100 to U+E01EF, and Mongolian's U+180B to U+180D and U+180F are default-ignorable and can carry text too, but emoji, ideographic variants, and Mongolian text use them throughout; reporting them would warn on most decks that hold any, and refusing them in a deck name would refuse names written in those scripts.
- **Refusing a space or `@` in `dekc new` too.** It would make every deck dek makes one `dekc pack` takes, but `dekc new` has always taken a name such as `My Talk`, and quotes it in the commands it prints next; refusing it is a narrowing of its own, for a record of its own.
- **Removing them from the theme `dekc new --theme-from` copies.** The copy is the deck's own from then on ([ADR 17](0017-start-a-deck-from-a-ref-s-theme.md)), and a bidi mark in a comment may be meant; dek says where they are and leaves the choice to the deck's author.
