# はじめる

このページでは、何もない状態から発表できるデッキを作るところまで進めます。やることは 3 つです。

1. プロジェクトと最初のデッキを作り、dek を導入する
2. 台本を書き、生成されたスライドをブラウザで確認する
3. 会場用の HTML を 1 ファイルに書き出す

HTML は書きません。声も動画も触りません。ゴールは、同梱テーマの骨格スライドを使って喋れる状態にすることです。

## 前提

[Bun](https://bun.sh) 1.4.3 以上が必要です。dek は Bun 専用なので、`npx` ではなく `bunx` を使ってください。

## プロジェクトを作る

dek のリポジトリの外に、トーク用のプロジェクトを作ります。

```bash
bunx @hajimism/dek init my-talks --deck 2026-04-vite
```

`init` を実行すると、作成したファイルとインストールしたパッケージの一覧に続けて、次に打つコマンドが表示されます。

```
installed:
  bun add -d --ignore-scripts @hajimism/dek@<version>

next:
  cd my-talks/decks/2026-04-vite
  $EDITOR script.md
  bunx dekc
```

`init` は実行中のバージョンの dek をプロジェクトにインストールします。以降は `bunx dekc` でその dek を動かせます。固定されるのは CLI のバージョンだけで、デッキの HTML が `node_modules` を参照することはありません。`--browser` を付けると Playwright と Chromium も一緒に入り、`--visual`・`dekc shot`・`dekc pdf` が使えます。付けなかった場合は、最後にその導入手順が表示されます。dek をインストールせずプロジェクトのファイルだけ作りたいときは `--no-install` を指定します。

`init` は bun を `--ignore-scripts` 付きで実行するため、`package.json` のライフサイクルスクリプトは走りません。また、dek をインストールするのは `init` 自身が作成した `package.json` に対してだけです。もともと `package.json` があったフォルダではインストールを自動実行せず、その旨を表示して手動インストールを案内します。Chromium のダウンロードが途中で止まった場合は、もう一度 `init --browser` を実行すれば続きから再開できます。

オフライン環境や、`bunfig.toml` の `minimumReleaseAge` が公開直後のバージョンを拒否した場合など、インストールに失敗しても生成したプロジェクトはそのまま残ります。その際は `dek: not installed` と理由を表示し、`next` の先頭に `cd my-talks` と `bun add -d @hajimism/dek` を添えるので、上から順に実行してください。

::: warning コマンドは `dek` ではなく `dekc`
パッケージ名は `@hajimism/dek`、コマンド名は `dek` ではなく `dekc` です。npm 上の `dek` は無関係の別パッケージで、`bunx dek` を実行するとそちらがダウンロードされてしまいます。プロジェクト内では `bunx dekc`、プロジェクトの外では `bunx @hajimism/dek` を使ってください。
:::

プロジェクトの作成は最初の一度だけです。最初のデッキも同時に作られ、2 本目以降は `dekc new <name>` で追加します。`init` は何度実行しても安全で、足りないファイルだけを補い、既存ファイルは上書きしません。`init` のテンプレートと内容が異なるファイルには `(kept)` と表示されます。既存プロジェクトの中で実行した場合は 2 つ目のプロジェクトを作らず、`dekc new` を使うよう案内します。

## 何ができたか

```
my-talks/
├── package.json        # init が作成。dek のバージョンを固定する
├── dek.toml            # プロジェクト設定。既定値を変えるまでは空
├── AGENTS.md           # AI エージェント向け規約。sync のたびに更新される
├── .gitignore          # dist/ .cache/ .dek/server.json node_modules/ refs/
├── .rumdl.toml         # script.md 用の Markdown ルール
├── theme.css           # 新しいデッキの出発点になるテンプレート
├── tsconfig.json       # スライドスクリプト用のエディタ設定
├── assets/             # 共通の素材置き場。各デッキは使うものをコピーする
├── decks/
│   └── 2026-04-vite/
│       ├── script.md   # 順序・喋り・尺の元になる台本
│       ├── theme.css   # このデッキ専用のコピー
│       ├── slides/     # 1 スライド 1 HTML。最初は骨格
│       └── assets/
└── .dek/
    ├── schema.json     # frontmatter のスキーマ（エディタ用）
    └── slide.d.ts      # スライドスクリプト用の DekSlide 型
```

デッキが 1 つだけでも `decks/` は必ず作られます。プロジェクト直下の `theme.css` はテンプレートで、`dekc init` や `dekc new` が新しいデッキの中へコピーします。

## 台本を書く

`script.md` を開きます。`init` が短いお手本の台本を用意しており、その中身自体が使い方の説明になっています。セクションがスライドに、`###` の見出しがビートに対応し、1 分の `duration` が入っているため、`bunx dekc ls` を実行すれば最初から見積もり時間と持ち時間が並んで表示されます。これを自分のトークに書き換えます。`##` の見出しひとつが 1 枚のスライドです。

```markdown
---
# yaml-language-server: $schema=../../.dek/schema.json
title: HTML スライドツールを作った話
event: Tokyo Frontend Meetup #42
date: 2026-04-18
duration: 20m
---

## intro

こんにちは。今日は、スライドツールを自分で作った話をします。

> 自己紹介は短く。時計を見ない。

## 今日持ち帰ってほしいこと {#architecture}

さて、ここが今日いちばん覚えて帰ってほしいところです。

### script.md が親 {#script-parent}

まず script.md がいて、

### スライドがぶら下がる {#slides-hang}

その下にスライドがぶら下がっている。逆ではありません。
```

覚えるルールは少しだけです。`##` が 1 枚のスライド、`###` が **ビート**（喋りの区切りであり、画面が進むタイミング）、通常の段落が実際に喋る言葉です。`>` の引用は自分用のト書きで、音声合成にも尺の見積もりにも含まれません。

見出しの文言が画面に表示されるテキスト、`{#id}` がスライドのファイル名になります。`## intro` のように id だけを書いた見出しは `slides/intro.html` になりますが、スライド自身のタイトルとしては使われません。先頭セクションには代わりにデッキの `title` が入り、2 枚目以降で id だけの見出しにするとタイトルのないスライドになります。タイトルを表示したい見出しには、`## 今日持ち帰ってほしいこと {#architecture}` のように文言と id を両方書いてください。

## 開発サーバーを起動する

デッキのディレクトリで次を実行します。

```bash
bunx dekc
```

見出しごとに骨格スライドが生成されます。先頭セクションはデッキの `title` を見出しに使い、「今日持ち帰ってほしいこと」はビートを箇条書きにした 1 枚になります。ファイルを保存するたびに再同期・再描画・lint が自動で走ります。表示された URL をブラウザで開いて右矢印キーを押し、ビートが順番に現れるのを確かめてください。

開発サーバーが動いている間は、`dekc sync` や `dekc lint` を手動で実行する必要はありません。

## 会場用に書き出す

```bash
bunx dekc build
```

`decks/2026-04-vite/dist/2026-04-vite.html` が出力されます。この 1 ファイルをブラウザで開くだけで発表できます。プロジェクト直下の `dist/` にまとめて書き出したい場合は `--root-dist` を付けてください。
