# スライド

スライドは `slides/` ディレクトリに置く 1 つの HTML ファイルです。ファイル名がセクションの id に対応し、ルート要素は `<section class="slide">` ひとつだけ。スタイルはテーマで定義されたクラスで付けます。

```html
<section class="slide" data-layout="two-col">
  <h2 class="slide-title">script.md が親</h2>
  <div class="col">
    <p class="node">script.md</p>
    <p class="node node-parent" data-step="script-parent">script.md ← 親</p>
  </div>
  <div class="col" data-step="slides-hang">
    <p class="node">intro.html</p>
    <p class="node">architecture.html</p>
  </div>
</section>
```

## ルール

- **ルート要素は 1 つだけ。** ファイルは `<section class="slide">` のフラグメントです。1 つもなければ何も描画されず（`DEK007`）、2 つ目以降は無視されます（`DEK009`）。id はファイル名から決まり、`data-slug` は `dekc build` が自動で付与します。手動で書く場合はセクション id と一致させてください（`DEK006`）。
- **HTML の書き方は自由。** 終了タグを閉じても省略しても、属性を引用符で囲んでも囲まなくても、正しい HTML5 であれば受け付けます。`<html>` と `<body>` で包んだ完全な文書でも構いません。ビルド時にまとめて minify されます。
- **レイアウトは `data-layout` で選ぶ。** 同梱テーマには `title`・`default`・`two-col`・`full-bleed`・`quote` があります。テーマにもそのスライド専用の CSS にも定義のないレイアウトを指定すると `DEK019` エラーになります。`default` は上詰めレイアウトなので、ビートで要素が増えても見出しの位置が上下しません（動画にしたときに見出しがガタつくのを防ぐためです）。
- **キャンバスは 1280 × 720。** `4:3` のデッキは 1024 × 768 です。プレイヤーがスライド全体を `transform: scale()` でビューポートに合わせて拡大縮小します。
- **使えるのはテーマのクラスか、そのスライド専用のクラスだけ。** テーマにも `slides/<id>.css` にも定義のないクラスは `DEK010` です。HTML 内の `<style>`、`style=` 属性、`<script>`、`onclick=` などのイベントハンドラ、スクリプトを実行する URL（`javascript:`、`vbscript:`、HTML を含む `data:`）は `DEK011` になります。
- **見た目はトークンで制御する。** 色・書体・余白・アニメーション時間は、テーマまたはスライド専用 CSS の `var(--*)` から参照し、生の値は書きません。
- **スクリプトは HTML の外に置く。** CSS で表せない動きは横の `slides/<id>.ts` に書きます（[スクリプトで動かす](./steps#スクリプトで動かす)を参照）。
- **デッキの中で完結させる。** 画像などは `assets/name.png` のように参照し、`../` は使いません。リモート URL は `DEK020`、存在しないファイルは `DEK021`、デッキの外に出るパスは `DEK022`、`assets/` で始まらないローカルファイルは `DEK023` です。`srcset`、`poster`、`<video>`・`<audio>`・`<source>`・`<track>`・`<iframe>` の参照先も `<img src>` と同様に検査します。

`<html>` などの外枠、frontmatter 由来の `lang` 属性、プレイヤーはレンダラーが補います。1 枚だけ確認したいときは開発サーバーを使うか、次のコマンドを実行してください。

```bash
dekc check architecture --shot
```

## 骨格

`dekc sync` や開発サーバーは、まだ HTML がないセクションに対して骨格スライドを自動生成します。中身は空ではなく、見出しの文言を `<h2>` に入れ、各ビートを `data-step` 付きのリストに並べた HTML です。

```html
<section class="slide" data-layout="default">
  <h2 class="slide-title"></h2>
  <ul>
    <li data-step="script-parent">script.md が親</li>
    <li data-step="slides-hang">スライドがぶら下がる</li>
    <li data-step="3">id のないビート</li>
  </ul>
</section>
```

ビートがないセクションには `data-layout="title"`、ビートがあるセクションには `default` が選ばれます。どちらもデッキの `theme.css` にそのレイアウトが定義されている場合だけ付与するため、カスタムテーマを使っていても新しいデッキがそのまま lint を通ります。id のあるビートは id で、ないビートは 1 始まりの位置番号で紐づきます。

`## recap` のように id だけの見出しには表示用の文言がないため、骨格の `<h2>` は空になります（先頭セクションだけは例外でデッキの `title` が入ります）。英語のスラッグがうっかり投影画面に出てしまうのを防ぐ仕様です。空の見出しは lint が `DEK024` で警告するので、文言を出したい場合は `## まとめ {#recap}` のように書いてください。

`sync` は、あなたが一度でも手を入れたスライドには触れなくなります。台本にビートを足しても手書きの HTML は自動更新されず、紐づけは `data-step` で管理します。骨格はビートの id を使うため、HTML を書き始める前にビートへ `{#id}` を付けておけば、後から途中にビートを挿入しても対応がずれません。id のあるビートをあえて数字で指すと `DEK025` の警告になり、hint に対応する id が表示されます。

一方、まだ誰も手を入れていない骨格は `sync` が管理し続けます。デッキの `title` を変えたりビートを増やしたりすると、未編集の骨格も自動で書き直されます（`dekc sync` では `(updated)` と表示されます）。見出しを 1 文字打ち直しただけでも、一度編集すれば以降は自動更新の対象から外れます。

骨格が未編集かどうかは、`.cache/skeletons` に記録した生成時のバイト列ハッシュで判定しています（見出しを書き換えても HTML の構造自体は変わらないため、構造だけでは見分けられません）。この記録は `.cache/` 内の他のデータと同じキャッシュです。もし消えても、`sync` がいま生成する骨格とバイト単位で一致するファイルだけを未編集とみなし、それ以外はすべて手書きスライドとして保護します。自動更新が効かなくなるだけで、編集内容が失われることはありません。

## スライドごとの CSS

1 枚のスライドでしか使わない装飾は、共通の `theme.css` には入れず、HTML の横に `slides/<id>.css` として置きます。

```css
/* slides/usb.css */
.slide { --mark-size: 96px; }
.usb-mark { width: var(--mark-size); color: var(--accent); }
.slide.is-current .usb-mark { animation: pop var(--step-transition); }
@keyframes pop { from { transform: scale(0.9); } }
```

レンダラーはすべてのルールをそのスライドだけにスコープするよう書き換えます。`.usb-mark` は `.slide:where([data-slug="usb"]) .usb-mark` に、先頭の `.slide` は `.slide:where([data-slug="usb"])` に変換され、`@keyframes pop` も他スライドと衝突しないようリネームされます。スコープ化で増える詳細度は `.slide` ひとつ分だけなので、ここに書いたルールは `theme.css` の末尾に置いた場合と同じ強さで効きます。テーマの `.slide .x` には勝ちますが、レイアウト用の `.slide[data-layout="split"] .x` やビート状態の `.slide.is-current [data-step]` のような詳細度の高いルールには負けます。それらを上書きしたい場合は、同じセレクタを書いてください。

上の `pop` に `from` しか書いていないのには理由があります。`.usb-mark` の基本スタイルを「完了後の状態」にしておき、アニメーションは別の状態から始まってそこへ着地する形にしておくと、アニメーションが再生されない環境でも完成形が表示されます。スライド一覧のサムネイルや発表者ビューのプレビューは `.is-current` を付けた複製なので、そこでも一度再生されて同じ完成形に落ち着きます。逆に `to` 側へ完成形を書くと `forwards` に依存することになり、アニメーションが動かない場面で崩れてしまいます。

スライド専用の CSS にもテーマと同じ規約が適用されます。

- 値はトークンから参照します（`DEK014`）。このスライドでしか使わない値なら、上の `--mark-size` のようにそのスライドの `.slide` にトークンとして定義して構いません（`DEK014` の hint でもこの書き方が案内されます）。
- ここで定義したクラスはそのスライド内でのみ有効とみなされ（`DEK010`）、テーマのクラス上限 `max_classes` には数えません（`DEK013`）。
- スライドの外に影響するルール（`::view-transition-*`、`@font-face`、`@import`、スライド内には一致しない `:root`・`html`・`body`）は `theme.css` に置きます（`DEK012`）。
- `url()` の規則は HTML と同じで、デッキ起点の `assets/...` のみ使え、リモート URL は不可です（`DEK020`・`DEK023`）。
- `dekc mv` はこの CSS も HTML と一緒にリネームします。対応するセクションがない CSS は `DEK002` になります。同じクラスを複数のスライドで使うようになったら、`theme.css` へ移してください。

## 密度はテーマが決める

1 枚のスライドにどれだけ情報を載せられるかは、`theme.css` のフォントサイズと余白が決めます。字数上限のような任意のルールは設けていません。文字を大きく設計しておけば、情報を詰め込んだ時点ですぐにキャンバスからはみ出し、`dekc lint --visual` が `DEK030` として検出します。幾何学的な判定なので好みの議論になりません。もっと多く載せたい場合はテーマの文字サイズを下げます。その判断は `theme.css` の差分として残り、レビューの対象にできます。
