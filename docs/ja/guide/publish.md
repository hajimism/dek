# dek.pub で公開する

[dek.pub](https://dek.pub) はトークをオンラインで見せます。スライド、共有した相手にはその横に台本、そしてスライドや台本の一節へのコメントです。`dekc pub` は、`dekc build` がファイルに書くのと同じようにプロジェクトからデッキをそこへ載せ、コメントをその対象のファイルへ持ち帰ります。

## サインインする

```bash
dekc pub login
```

dek が標準エラーに URL とコードを出します。URL を開いて dek.pub にサインインし、コードを承認してください。dek はそれを待ち、dek.pub がくれた API キーを OS のキーチェーンに保存します。キーチェーンがなければ、あなただけが読める `~/.config/dek/credentials.json` に保存します。`dekc pub whoami` は誰としてサインインしているかを示し、`dekc pub logout` はキーを失効させて手元から消します。

dek.pub は今のところ招待制です。アカウントを作れるのは、dek.pub に招待されたメールアドレスか GitHub アカウントと、デッキを共有されたメールアドレスだけです。一度作ったアカウントには、その後もサインインできます。

初めてサインインしたときは、何より先にハンドルを決めます。プロフィールとトークの URL に入る名前で、`/@ハンドル/<slug>` のようになります。誰も使っていなければ、GitHub のログイン名か、メールアドレスの `@` より前を候補に出します。決められるのは一度だけで、あとから変えることはできません。名前と、プロフィールに出す 5 件までのリンク（GitHub、X、自分のサイトなど）は、dek.pub の設定ページ `/settings` で変えられます。GitHub で作ったアカウントには、GitHub のプロフィールへのリンクが最初から入っています。

エージェントはあなたのためにブラウザを開けないので、`--json` ではサインインが 2 回の実行に分かれます。1 回目はすぐに返ります。

```json
{ "ok": true, "action": "login", "status": "pending", "url": "https://dek.pub/device?user_code=WDJB-MJHT", "code": "WDJB-MJHT", "expiresAt": "…", "next": "dekc pub login --json", "server": "https://dek.pub" }
```

エージェントは URL とコードをあなたに見せてから `next` を実行します。これはあなたが承認するまで待ち、`"status": "signed-in"` を返します。その実行が止められても、次の実行がコードの期限まで同じコードを待ちます。

CI では代わりに `DEK_TOKEN` に API キーを設定します。サインインはいりません。dek がそれを送るのは `https://dek.pub` か、`DEK_TOKEN_SERVER` が指すサーバーだけです。

## バージョンを公開する

```bash
dekc pub publish -m "通し練習 1 回目"
```

publish は、トークを共有する前に手でやることをこなし、手でやるなら止まるところで止まります。

1. `dekc lint` と同じようにデッキを lint します。error があれば診断と終了コード 1 を返して止まり、何も送りません。warning はバージョンと一緒に送ります。
2. トークを 3 通りにビルドします。あなた用に台本をすべて含むもの、台本を見せるときの読み手用に `dekc build --public` と同じく読み上げる部分だけのもの、見せないときの読み手用に `dekc build --no-script` と同じく台本のまったくないもの。dek.pub は読み手ごとに、読んでよいビルドを出します。
3. Playwright が入っていれば、台本記事に載せる各スライドの画像を `dekc shot` と同じく最後のビートで撮り、リンクプレビュー用に 1 枚目の画像も撮ります。
4. `dist/` と `.cache/` を除いてデッキのソースをまとめます。`dekc pub status` が、いまのバージョンが手元のものと同じかを見分けられるようにです。

初めての公開で dek.pub にデッキを作り、その ID を `script.md` に書き込みます。

```yaml
---
title: HTML スライドツールを作った話
pub: d_k2m9x4q7w1
---
```

この行はコミットしてください。どのチェックアウトから公開しても同じデッキが更新されます。デッキの slug（URL の末尾）はフォルダ名の小文字です。別のものにするなら、初めての公開で `--slug <slug>` を渡します。すでに持っている slug は断られるので、別のデッキからコピーしたデッキや `pub:` の行を消したデッキは、自分の `--slug` を付けたときだけ新しく作られます。

公開するたびに新しいバージョンになり、読み手にはすぐにそのバージョンが見えます。前のバージョンは dek.pub から消えます。トークのこれまでの状態はすべてあなたのリポジトリにあるので、戻すときはそのソースをもう一度公開します。前のバージョンのあと `dekc mv` で名前を変えたセクションには、コメントも付いていきます。古いバージョンを開いたままのページからコメントすると、ページを読み込み直すよう伝えられます。

## 共有する

新しいデッキはチームだけのものです。開けるのは、あなたと、デッキを共有した人のうちチーム側の人です。ゲストや誰にでも見せる準備ができたら、`dekc pub share` で公開範囲を広げます。ほかの設定もここで選びます。

```bash
dekc pub share --visibility link --script shown --comments signed-in
```

| フラグ | 値 |
| --- | --- |
| `--visibility` | `team`: あなたと、共有した相手のうちチーム側の人、`private`: あなたと、共有した相手の全員（チームとゲスト）、`link`: リンクを知る誰でも、`public`: 全員 |
| `--script` | `shown`: 読み手はスライドの横に、ト書きとコメントを除いた台本を見る。`hidden`: スライドだけ |
| `--embed` | `on` でほかのサイトがデッキを埋め込める |
| `--comments` | `link` か `public` のトークの下にコメントを書ける人: `off` は誰も書けない、`signed-in` は dek.pub にサインインしている人 |
| `--new-link` | `link` のトークの URL の鍵を作り直す。それまでに渡した URL では開けなくなる |

`link` のトークの URL には、`/@you/talk?key=…` のように推測できない鍵が付きます。`dekc pub share` と `dekc pub status` がこの URL を出力し、鍵を持たない人には存在しないページに見えます。デッキを共有した相手は鍵なしで開けます。トークを `private` にして戻しても鍵は変わらず、変わるのは `--new-link` か、管理画面の「リンクを作り直す」を使ったときだけです。

`link` か `public` のトークの下では、読み手がトーク全体へのコメントを書き、いいねを付けられます。いいねは 1 アカウントに 1 つです。コメントを書ける人は `--comments` で決まり、書けるのはいつも dek.pub にサインインしている読み手だけです。スライドへのレビューのスレッドは、`--comments` によらず、デッキを共有した人のためのものです。デッキを人と共有するには、dek.pub のデッキの管理画面か `dekc pub grants add` を使います。ハンドルかメールアドレスで、閲覧かコメントかと、チームの側かゲストの側かを選んで招待します。チームはすべてのスレッドを読み、ゲストは公開されたスレッドだけを読み、ほかのスレッドがあることも分かりません。ゲストがデッキを開けるのは、公開範囲が `private` 以上のときだけです。`team` のデッキは、ゲストには存在しないページと同じに見えます。あなたやチームが始めるスレッドは、「ゲストにも公開」にチェックしない限りチームだけのものです。チームだけのスレッドはあとからゲストにも公開できますが、公開したものをチームだけに戻すことはできません。

```bash
dekc pub grants add @sato --role comment --side team
dekc pub grants add client@example.com
dekc pub grants
dekc pub grants remove client@example.com
```

新しく共有した相手は、`--role` と `--side` で指定しなければ、ゲストの側で閲覧だけができます。変えるときはもう一度 `grants add` を実行します。指定しなかったものは元のままです。

共有した相手には、デッキへのリンクがメールで届きます。メールアドレスで招待された人に GitHub のアカウントはいりません。dek.pub のサインイン画面でリンクをメールで受け取れます。リンクが届くのは、デッキを共有されたアドレス、dek.pub に招待されたアドレス、前にサインインしたことのあるアドレスだけです。スレッドを始めた人、返信した人、デッキのオーナーには、そのスレッドへの返信と解決がメールで届き、オーナーには自分のデッキに始まったスレッドも届きます。トークのコメントの見出しの横にあるベルで、そのトークのメールを止められます。トークのページの全画面ボタンを押すと、トーク名とページ番号を出すヘッダー付きでデッキを全画面で見られ、ヘッダーのレビューボタンか `c` で、スライドの横にレビューを開けます。

`dekc pub status` は設定、読み手に見えるバージョン、それがプロジェクトにあるソースと同じかを出します。`dekc pub open` はデッキをブラウザで開きます。

## コメントに答える

```bash
dekc pub comments
```

各コメントは、それがどこにあるかを示します。台本の一節なら、いまの `script.md` での行と列。スライドの要素なら、そのスライドのファイル。エージェントは `dekc annotations` を読むのと同じように `--json` で読み、`shot` がコメントのあるスライドを見るコマンドです。デッキのチームだけで読むスレッドは別に番号が振られ、`T2` のように T が付きます。対応したら、ID か番号で返信し、解決済みにします。

```bash
dekc pub comments reply 3 "次のバージョンで言い換えました"
dekc pub comments resolve 3
```

`--status resolved` や `--status all` でほかのものも一覧にでき、`dekc pub comments reopen <id>` で開き直せます。

## 別のサーバー

どのサブコマンドも `--server <url>` を受け付け、`DEK_PUB_SERVER` はシェル全体に同じことを設定します。開発中に手元で動かす dek.pub などに使います。キーは HTTPS か、このマシンへの平文の HTTP でだけ送り、サーバーごとに別のキーを持ちます。フラグとフィールドはすべて [CLI リファレンス](/ja/reference/cli#公開) にあります。
