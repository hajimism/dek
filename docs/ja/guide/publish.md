# dek.pub で公開する

[dek.pub](https://dek.pub) はトークをオンラインで共有・レビューするためのサービスです。スライド本体に加えて、許可した相手には隣に台本を表示でき、スライドの要素や台本の一節にコメントを付けられます。`dekc pub` を使えば、`dekc build` でローカルへ書き出すのと同じ感覚でプロジェクトからそのまま公開し、付いたコメントをローカルの対象ファイルと紐づけて確認できます。

## サインインする

```bash
dekc pub login
```

標準エラーに URL と確認コードが表示されます。ブラウザでその URL を開いて dek.pub にサインインし、コードを承認してください。承認が終わると、dek.pub から発行された API キーが OS のキーチェーンに保存されます。キーチェーンが使えない環境では、所有者のみ読み取り可能な `~/.config/dek/credentials.json` に保存されます。現在のサインイン先は `dekc pub whoami` で確認でき、`dekc pub logout` でキーを失効させて手元から削除できます。

dek.pub は現在招待制です。アカウントを作成できるのは、dek.pub に招待されたメールアドレスまたは GitHub アカウントと、誰かからデッキを共有されたメールアドレスに限られます。招待されたメールアドレスにはサインイン用リンクが届くため、そのリンクからサインインしてください。一度アカウントを作れば、以降は通常どおりサインインできます。

初回サインイン時には、最初にハンドルを決めます。プロフィールやトークの URL（`/@ハンドル/<slug>`）に使われる名前で、空いていれば GitHub のログイン名かメールアドレスの `@` より前が候補に出ます。ハンドルは一度決めると後から変更できません。表示名とプロフィールに載せるリンク（最大 5 件：GitHub、X、個人サイトなど）は設定ページ `/settings` からいつでも変更できます（GitHub で登録した場合は GitHub プロフィールが初期登録されます）。

AI エージェントはユーザーの代わりにブラウザを開けないため、`--json` 指定時のサインインは 2 段階に分かれます。1 回目はすぐに次の JSON を返して終了します。

```json
{ "ok": true, "action": "login", "status": "pending", "url": "https://dek.pub/device?user_code=WDJB-MJHT", "code": "WDJB-MJHT", "expiresAt": "…", "next": "dekc pub login --json", "server": "https://dek.pub" }
```

エージェントは URL とコードをユーザーへ提示してから `next` のコマンドを実行します。2 回目は承認されるまで待機し、完了すると `"status": "signed-in"` を返します。待機中に中断しても、コードの有効期限内であれば次の実行で同じコードの承認を待ち続けられます。

CI 環境では、サインインの代わりに環境変数 `DEK_TOKEN` へ API キーを設定します。`dekc` がこのトークンを送信するのは `https://dek.pub` か、`DEK_TOKEN_SERVER` で明示したサーバーだけです。

`dekc pub login` を実行するたびに、そのマシン名が付いた有効期限 1 年のキーが新しく発行されます。`/settings` の「CLI キー」画面では作成日時と最終利用日時を確認でき、個別の失効も一括失効も可能です。キーが漏洩した恐れがある場合（とくに CI から漏れた場合）は、サインイン済みのマシンから `dekc pub logout --all` を実行してください。`DEK_TOKEN` 用も含めてアカウントの全キーを失効させ、手元のキーも削除します。そのうえで必要なマシンからサインインし直し、CI には新しいキーを設定してください。なお API キーでは、キー一覧の参照、他キーの個別失効、アカウント設定の変更はできません。これらはブラウザから操作します。

## バージョンを公開する

```bash
dekc pub publish -m "通し練習 1 回目"
```

`publish` は、トークを共有する前に本来手動で確認すべき手順を一通り実行し、問題があれば途中で止まります。

1. `dekc lint` と同様にデッキを検証します（描画系ルールは除く）。`error` があれば診断と終了コード 1 を返して中断し、何もアップロードしません。`warning` はバージョン情報と一緒に送信されます。
2. トークを 3 通りにビルドします。台本公開時の閲覧者向けに読み上げ部分だけを残した `--public` 相当、台本非公開時の閲覧者向けに台本を含まない `--no-script` 相当、そして将来の用途向けに台本全文入りの `full.html` の 3 つです。dek.pub はデッキの `--script` 設定に応じて `public` または `bare` のビルドを配信します。
3. Playwright が導入されていれば、台本記事に並べる各スライドの静止画（`dekc shot` と同じく最終ビート）と、リンクプレビュー用の 1 枚目画像を撮影します。
4. `dekc pub status` で公開済みバージョンと手元のソースが一致するか判定できるよう、`dist/` と `.cache/` を除いたデッキ一式をまとめます。

初回公開時に dek.pub 上でデッキが作成され、発行された ID が `script.md` の frontmatter に書き込まれます。

```yaml
---
title: HTML スライドツールを作った話
pub: d_k2m9x4q7w1
---
```

この行は必ずコミットしてください。どのチェックアウトから公開しても同じデッキが更新されるようになります。URL 末尾の slug には既定でフォルダ名の小文字が使われますが、初回公開時に `--slug <slug>` で変更できます。自分のアカウントですでに使っている slug はエラーになるため、別デッキをコピーした場合や `pub:` を消した場合は新しい `--slug` を指定してください。

公開するたびに新しいバージョンへ差し替わり、閲覧者には即座に最新版が表示されます。以前のバージョンは dek.pub からは削除されますが、過去の履歴はすべて手元の Git リポジトリに残っているため、戻したいときはそのコミットから再公開します。前回の公開後に `dekc mv` で改名したセクションにはコメントも自動で追従します。古いバージョンを開いたままのブラウザからコメントしようとすると、ページを再読み込みするよう案内が出ます。

## 共有する

新しく公開したデッキの初期設定はチーム内限定（`team`）で、閲覧できるのは持ち主と、共有相手のうちチーム側のメンバーだけです。ゲストや一般へ公開する準備ができたら、`dekc pub share` で公開範囲や各種設定を切り替えます。

```bash
dekc pub share --visibility link --script shown --comments signed-in
```

| フラグ | 値 |
| --- | --- |
| `--visibility` | `team`：持ち主とチーム側の共有相手のみ／`private`：持ち主と全共有相手（チーム・ゲスト）／`link`：URL を知る全員／`public`：一般公開 |
| `--script` | `shown`：スライドの横にト書き・コメントを除いた台本を表示／`hidden`：スライドのみ |
| `--embed` | `on` にすると他サイトへの埋め込みを許可 |
| `--comments` | `link` / `public` のトーク下部にコメントを書ける範囲：`off`（不可）／`signed-in`（dek.pub にサインイン済みのユーザー） |
| `--new-link` | `link` 用 URL の鍵を再発行（以前渡した URL は無効になる） |

`link` 公開の URL には `/@you/talk?key=…` のように推測困難な鍵が付きます。`dekc pub share` と `dekc pub status` がこの URL を出力し、鍵を持たない人には存在しないページ（404）として扱われます。明示的に共有した相手は鍵なしで開けるため、`dekc pub comments` が出すレビュースレッドの URL や通知メールのリンクには鍵が付きません。いったん `private` へ戻してから再度 `link` にしても鍵は維持され、鍵が変わるのは `--new-link` または管理画面の「リンクを作り直す」を実行したときだけです。

`link` または `public` のトークでは、ページ下部でトーク全体へのコメントといいね（1 アカウントにつき 1 つ）ができます。コメントできる条件は `--comments` で決まり、書き込みには常にサインインが必要です。

一方、スライドや台本に対するレビュースレッドは `--comments` の設定に関係なく、デッキを共有した相手向けの機能です。共有相手は管理画面か `dekc pub grants add` で追加でき、ハンドルまたはメールアドレスに対して「閲覧のみ（`view`）／コメント可（`comment`）」と「チーム側（`team`）／ゲスト側（`guest`）」を指定します。

- チーム側のメンバーは全スレッドを閲覧でき、新しく立てたスレッドは「ゲストにも公開」にチェックしない限りチーム限定になります（チーム限定スレッドを後からゲストへ公開することはできますが、一度公開したスレッドをチーム限定へ戻すことはできません）。
- ゲスト側のメンバーは公開されたスレッドだけが見え、非公開スレッドの存在自体も分かりません。またゲストがデッキを開けるのは公開範囲が `private` 以上のときだけで、`team` の間は 404 として扱われます。

```bash
dekc pub grants add @sato --role comment --side team
dekc pub grants add client@example.com
dekc pub grants
dekc pub grants remove client@example.com
```

`--role` と `--side` を省略して新規追加すると、ゲスト側の閲覧専用（`view` / `guest`）になります。権限を変えるときは同じ相手に対してもう一度 `grants add` を実行してください（指定しなかった項目は維持されます）。

新規に共有すると、ハンドル指定でもメールアドレス指定でも招待メールが届きます（一度外してから再追加した場合も再送されます）。招待メールの送信上限は全デッキ合算で 24 時間に 20 通までで、上限を超えるとエラーになり次回送信可能時刻が表示されます。権限の変更だけではメールは送信されません。

メールアドレスで招待された相手に GitHub アカウントは不要で、サインイン画面からメールリンクでサインインできます（メールリンクが届くのは共有されたアドレス、招待済みアドレス、サインイン履歴のあるアドレスのみ）。スレッドの作成者・返信者・デッキのオーナーには返信や解決の通知メールが届き、オーナーには自分のデッキに立った新規スレッドも通知されます（コメント見出し横のベルアイコンからトーク単位でミュート可能）。なおトークページの全画面ボタンを押すとトーク名とページ番号付きのヘッダーで全画面表示でき、レビューボタンまたは `c` キーでスライドの横にレビューパネルを開けます。

`dekc pub status` で現在の公開設定・公開中のバージョン・手元ソースとの一致状況を確認でき、`dekc pub open` でデッキをブラウザで開けます。

## コメントに答える

```bash
dekc pub comments
```

各コメントがどこに対するものかを表示します。台本の一節なら現在の `script.md` の行と列、スライド上の要素なら該当スライドのファイルパスが出ます。エージェントは `dekc annotations` と同様に `--json` で読み取り、含まれる `shot` コマンドで該当スライドを確認できます。チーム限定スレッドは独立した連番になり、`T2` のように `T` が付きます。対応が済んだら ID または番号を指定して返信し、解決済みにしてください。

```bash
dekc pub comments reply 3 "次のバージョンで言い換えました"
dekc pub comments resolve 3
```

`--status resolved` や `--status all` で解決済みも含めて一覧でき、`dekc pub comments reopen <id>` で再オープンできます。

## トークを削除する

```bash
dekc pub delete --yes
```

削除すると、すべてのバージョン、レビュースレッドと返信、公開コメント、いいね、共有設定が dek.pub から完全に消去されます。以降はその URL・画像・ビルドすべてにアクセスできなくなり、復元もできません。`--yes` を付けずに実行すると削除対象を確認表示するだけで終了します。削除後は `script.md` から `pub:` 行が自動で取り除かれるため、その変更をコミットしてください。次に `dekc pub publish` を実行すると同じ URL で新しいデッキが作られ、以前の情報は引き継がれません。管理画面の下部にも同じ「トークの削除」機能があります（確認のためスラッグ入力が必要です）。

dek.pub の運営者（サーバー側の `DEK_PUB_OPERATORS` に確認済みメールアドレスが登録されたアカウント）は、任意のディレクトリから `dekc pub takedown <talk> --yes` で誰のトークでも取り下げられます（URL またはデッキ ID を指定、実行履歴はすべてログに記録）。同じ運営者が `/settings` から新規アカウントの招待も管理します（メールアドレスには招待メールを送り、`@login` 形式の GitHub ログイン名にはメールを送りません）。API キーはそのアカウントの権限をそのまま持つため、`DEK_TOKEN` に運営者のキーを設定すると誰のトークでも削除できてしまいます。運営者アカウントのキーは CI に置かないでください。

## 別のサーバー

すべてのサブコマンドは `--server <url>` を受け付け、`DEK_PUB_SERVER` でシェル全体に一括指定もできます。開発中にローカルの dek.pub サーバーへ接続したいときなどに使います。API キーは HTTPS かローカルホストへの平文 HTTP でしか送信されず、サーバーごとに別々のキーとして保存されます。全フラグと JSON フィールドの仕様は [CLI リファレンス](/ja/reference/cli#公開) を参照してください。
