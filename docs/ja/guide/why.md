# dek の設計思想

スライドは、喋るためにあります。ところが主流のツールは、どれもその前提で作られていません。PowerPoint でも Keynote でも Google Slides でも、Marp や Slidev でも、最初に空のスライドを用意して中身を埋めていくのが当たり前です。見出しを足し、図を置き、アニメーションを付けるほど資料は立派になりますが、そのぶん本番で喋り切るのは難しくなります。当日は時計を見ながら 3 枚飛ばし、いちばん言いたかったことを言い残して終わってしまいます。

dek は逆の手順を取ります。何を、どの順で、どれだけの時間で喋るかを先に書き、そのうえで「このタイミングで画面に何が出ていればいいか」を考えます。台本が親で、スライドはそこから作ります。

言い換えると、dek は発表のためのビルドシステムです。ソースにあたる `script.md` から、`dekc sync` がスライドの骨格を生成します。`dekc lint` はコンパイラの型チェックのように各スライドをテーマの規約と照らし合わせ、`--visual` はテストのように実ブラウザで描画して崩れを測ります。成果物を書き出すのが `dekc build`・`dekc pdf`・`dekc video` です。ビルドが通れば機械的に検出できる不備はありません。あとは発表として良いかどうかを、作者が決めます。

## dek が解きたい 3 つの問題

### トークは一度きりではない

多くのスライドツールは、1 つのデッキを 1 つのプロジェクトとして扱います。発表のたびに新しいリポジトリを切り、テーマも規約もゼロから積み直すため、前回得た知見が前のリポジトリに置き去りになってしまいます。

dek では、**プロジェクト**が複数の**デッキ**をまとめて管理します。規約はプロジェクト単位で持ち、見た目は前回のデッキを引き継ぎ、台本とスライドはデッキごとに持ちます。過去のトークが、そのまま次のトークの出発点になります。

### エージェントには小さなファイルが要る

3,000 行の `slides.md` から 7 枚目だけを直す作業は、人間には単純でも言語モデルには意外に難しいものです。コンテキストが膨らみ、差分にノイズが乗り、ひとつの編集ミスがデッキ全体を壊してしまいます。

dek では 1 スライドが約 40 行の独立した HTML ファイルです。編集対象が小さく差分も読みやすいため、ミスがあってもその 1 枚だけで済みます。dek を Slidev のテーマではなく独立したツールとして作った最大の理由がここにあります。

### エージェントは自分の描画結果を見られない

HTML を書いたエージェントには、その文字がスライドに収まっているかどうかが分かりません。マークアップとしては完璧に見えても、はみ出しに気づくのは本番 30 分前の人間です。

dek はスライドを実ブラウザで描画し、はみ出し・コントラスト・欠けた画像を機械可読な診断として返します。エージェントは書き、確認し、結果を読み、自分の間違いを自分で直せます。人間を挟まずにこのループを回せるのが強みです。

## 三原則

dek の設計はすべて 3 つの原則に基づいています。どれもドキュメントに書いて終わりではなく、ファイル構造か lint ルールで強制されます。

### 1. `script.md` がすべての元になる

順序、喋る言葉、持ち時間。この 3 つは `script.md` にだけ書きます。各スライドの HTML は台本のセクションに紐づくファイルです。親子関係が構造として固定されているため、台本とスライドのどちらか一方だけが更新されて食い違うことはありません。

スライドのファイル名に連番を振らないのもそのためです。順序を持つのは `script.md` だけです。スライド内部でも考え方は同じで、要素は台本のビートの順に現れ、HTML 側はビートを id で参照するだけです。`data-step` の数値は「このスライドの k 番目のビート」の省略形にすぎません。

### 2. スライドは `<section class="slide">` ひとつ

`slides/` 内の各ファイルは、ルート要素が `<section class="slide">` ひとつだけです。見た目は `theme.css` と、必要に応じて置くそのスライド専用の `slides/<id>.css` が担当し、`<html>` などの外枠とプレイヤーはレンダラーが補います。エージェントに渡すのは約 40 行の HTML フラグメントだけで、必要な文脈はその 1 ファイルで完結します。

この自己完結性はデッキディレクトリ全体にも当てはまります。デッキはその外にあるファイルを一切参照しません。テーマも画像も音声設定もすべてデッキ内に収まります。ディレクトリごとコピーしても、zip で送っても、5 年後に開いても同じように描画されます。プロジェクトはデッキを置く場所であって、デッキが依存する実行環境ではありません。

### 3. 規約は lint で守らせる

「使える CSS クラスはこれだけ」「トークン以外の生の値は書かない」「デッキの外を参照しない」。こうした規約は文章で残すだけでは守られません。dek はすべてを lint ルールとして実装し、SARIF 形式で出力します。

**lint は測れるものだけを判定し、それ以上には踏み込みません。** lint が通らないうちはデッキは未完成です。通れば、ルールで検証できる範囲に問題はありません。開発サーバーは保存のたびに lint を走らせるため、作業中のデッキは常に「通っている」か「どこが通らないかが明示されている」かのどちらかです。スライドのバランスや話の筋といった lint で測れない部分は作者が判断します。dek はその判断材料として、コンタクトシートと台本を差し出します。音声合成を足しても警告が増えるだけで、通っていたデッキがエラーに変わることはありません。

音声と動画は台本から生成される派生物であり、台本自体には見た目も声の指定も書きません。

## 他のツールとの違い

|  | PowerPoint / Keynote | Marp | Slidev | dek |
| --- | --- | --- | --- | --- |
| 作る順序 | スライド先行 | スライド先行 | スライド先行 | 台本先行 |
| 作業の単位 | 1 ファイル = 1 デッキ | 1 ファイル = 1 デッキ | 1 リポジトリ = 1 デッキ | 1 プロジェクト = N デッキ |
| スライドの実体 | バイナリ | Markdown | 単一の `slides.md` | 1 スライド 1 HTML |
| 発表者の台本 | ノート（子） | HTML コメント（子） | HTML コメント（子） | `script.md`（親） |
| 段階表示 | アニメーション | 部分的 | `v-click`（順序はスライド側） | `###` ビート（順序は台本側） |
| 尺 | リハーサル用タイマー | なし | 目標の `duration` + カウントダウン | 台本から見積もる。字数または TTS の実尺を `duration` と比較 |
| チェック | アクセシビリティチェック（PowerPoint） | はみ出し（VS Code のみ、実験的） | 組み込みなし | ソースと描画後の各スライドを lint。はみ出し・コントラスト・改行・揃え |
| 動き | 独自 | CSS | Vue + 独自 DSL | CSS + View Transitions |
| エージェント接点 | 弱い | テキスト | スキル、`llms.txt`、MCP サーバー | `--json` 対応 CLI、`AGENTS.md`、スキル、`llms.txt` |
| 出力 | 独自形式、PDF | HTML、PDF、画像、PPTX（文字編集は実験的） | Web アプリ、PDF、画像、PPTX（文字編集可） | 1 ファイルの HTML、PDF、PPTX（文字編集可）、読み上げ付き動画 |
| 向いている用途 | 汎用 | 手軽な Markdown スライド | デモを含む技術トーク | 喋りが主役のトーク |

Slidev はこの領域で最も成熟したツールであり、dek も発表者ビューの同期、Playwright の任意依存化、CSS のスコープ規約など多くの解法を参考にしています。決定的に違うのは、ファイルの粒度、台本の位置づけ、そして作業の単位です。

出力形式の差はほとんどなくなりました。Slidev は文字を編集できる PowerPoint ファイルを出力できますし、Marp も実験的に対応しています。dek が力を入れているのは出力より手前の工程です。話す内容から持ち時間を見積もり、書いたその場で全スライドの描画を測ります。

dek は Vue も UnoCSS も Monaco も Mermaid も依存に含みません。そのぶん lint とビルドが単純に保たれ、素の HTML と CSS だけで完結することを制約ではなく強みとして活かせます。

## dek が向いていないこと

次のいずれかが必要なら、Slidev を使ってください。

- スライド内のインタラクション（クリックで動くデモや、聴衆の操作に反応するコード）。dek のスライドスクリプトは時間 `t` の関数を描くだけです
- ライブコーディングや埋め込みエディタ
- npm で配布されるテーマのギャラリー
- CSS とシーク可能な `draw(t)` の枠を超えるアニメーション DSL

WYSIWYG 編集や Keynote 形式のファイルが必要なら、PowerPoint か Keynote を使ってください。`dekc pptx` は単純な矩形・画像・SVG・文字を PowerPoint の図形や画像に変換し、台本をノートに入れて出力できますが、グラデーション・影・疑似要素で描いた装飾などは背景画像として残ります。

dek はひとりで保守できる規模を守り、喋りが主役のトークに集中します。細かい線引きは [FAQ](./faq) にまとめています。
