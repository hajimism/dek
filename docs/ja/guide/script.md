# 台本

`script.md` が持つ情報は 3 つだけです。トークの順序、喋る言葉、そして持ち時間。レイアウトや装飾はスライドの HTML に、音声設定は `voice/` に分けます。台本にはどちらも書きません。

## 3 つのルール

覚えるルールは 3 つです。`##` の見出しが 1 枚のスライドになり、その下の内容がそのスライドの台本になり、実際に喋る言葉として扱われるのは段落だけです。

構造として意味を持つ見出しは `##` と `###`（後述のビート）に限られます。`#` や `####` は台本の本文として扱われ、lint が `DEK044` で警告します。コードフェンスや HTML コメントの中の見出しは本文扱いなので、Markdown についての発表でもコードブロックの中に `## 見出し` と問題なく書けます。

```markdown
---
# yaml-language-server: $schema=../../.dek/schema.json
title: HTML スライドツールを作った話
event: Tokyo Frontend Meetup #42
date: 2026-04-18
duration: 20m
---

## intro

こんにちは。今日は、スライドツールを自分で作った話をします。

> 自己紹介は短く。時計を見ない。

## 発表の前日に何をしていますか {#problem}

みなさん、発表の前日に何をしていますか。

聴衆が「自分ごと」だと思うまで喋る。3 つ目が本命。

## architecture

さて、ここが今日いちばん覚えて帰ってほしいところです。

### script.md が親 {#script-parent}

まず script.md がいて、

### スライドがぶら下がる {#slides-hang}

その下にスライドがぶら下がっている。逆ではありません。
```

見出しの文言は自由です。日本語でも疑問文でも、句読点が入っていても構いません。発表者ビューでは各セクションの Markdown が、段落内の改行だけ詰めた状態でそのまま表示されます。

音声合成や読み上げの対象になるのは通常の段落だけです。引用、リスト、コードブロック、表は画面用またはト書きとして扱われ、合成の対象から外れます。インラインの強調・リンク・`code` は、合成前に装飾を外してプレーンテキストになります。これらはライブ発表には一切影響せず、`dekc cues` を実行したときや音声を付けたときにだけ効いてきます。リストはあるのに段落がないビートは、画面には表示されるのにナレーションでは一瞬で通り過ぎてしまうため、`dekc cues` と `voice/` のあるデッキの lint が `DEK042` で警告します。

ト書きには引用（`>`）を使ってください。ナレーションを付けるときだけでなく、`dekc build --public` で公開用ビルドを作るときにも役立ちます（`--public` を付けると発表者ビューから引用と HTML コメントが除かれます。[Web で公開する](./present#web-で公開する)を参照）。dek には「短い命令文をト書きとみなす」ような曖昧な自動判定も、間を取るための専用記法もありません。ナレーションのタイミング調整は `voice/voice.toml` に書きます（[タイミング](./voice#タイミング)を参照）。

## 見出しと id

`slides/` のファイル名や CLI の `<slug>` 引数に使うのがセクションの **id**、発表者ビューに表示されるのが見出しの **文言** です。id は `[a-z0-9-]+` に一致し、英字を 1 文字以上含める必要があります。数字だけの id は数値の `data-step` と衝突するため受け付けません。

表示文言と id は Pandoc 流の `{#id}` 記法で分けます。

- 見出しがそのまま id として有効なら、それが id になります（例：`## intro` → `slides/intro.html`）。
- そうでなければ `{#id}` が必須です（例：`## 発表の前日に何をしていますか {#problem}` → `slides/problem.html`）。付け忘れると行番号付きのエラー（`DEK027`）になり、修正案も提示されます。lint は 1 回の実行で該当箇所をすべて報告し、見出しに英数字が含まれていればそこから候補を作って `## Why dek? {#why-dek}` のように、含まれていなければ `## まとめ {#your-id}` のように提案します。
- そのまま id になる見出しにも `{#id}` を付けられます。表示名とファイル名を分けたいときに使ってください（例：`## intro {#opening}` は「intro」と表示され、`opening.html` になります）。
- id だけの見出しには表示する文言がないため、生成される骨格の `<h2>` は空になります。例外は先頭セクションで、ここにはデッキの `title` が入ります。発表者ビューには id が表示されます。

使える属性は `{#id}` だけです。`{.class}` や `key=value` はエラーになります。セクションの id はデッキ内で一意、ビートの id はセクション内で一意である必要があります。

## 改名と並べ替え

`dekc sync` は既存ファイルのリネームをしません。たとえば `## problem` を `## the-problem` に書き換えると、開発サーバーは `the-problem` 用の骨格を新しく生成します。元の `problem.html` が誰も手を入れていない骨格のままで、横に `problem.css` も `problem.ts` もなければ、台本から再生成できる内容しかないため `sync` が削除します（`dekc init` の直後に自分の台本へ書き換えるとお手本の骨格が自動で片付くのはこの仕組みです）。一方、手を入れた `problem.html` は削除されず、対応するセクションのない孤児ファイル（`DEK002`）として残ります。紐づけが切れるだけで、中身は自動では移りません。

id の変更や順序の入れ替えはミスが起きやすいため、CLI に任せてください。

```bash
dekc mv problem the-problem
dekc mv architecture --after intro
```

前者は `script.md` の id、`slides/problem.html`（および存在すれば `problem.css`・`problem.ts`）、`data-slug`、`voice/voice.toml` の該当キーをまとめて書き換えます。見出しの文言には触れず、移動先のファイルが 1 つでも既にある場合は実行を拒否します。すべて更新されるか、何も変わらないかのどちらかです。後者は台本の中でセクションを移動します。HTML ファイルは順序を持たないため、リネームは発生しません。

見出しを先に書き換えてしまったり、ファイル名を先に変えてしまったりしても、後から `dekc mv` を実行すれば残りの同期を終わらせられます。`script.md` 側がすでに新しい id ならファイルだけを動かし、ファイル側がすでに新しい id なら見出しと残りのファイルだけを更新します。開発サーバーが保存時に生成した骨格がどちらの id にあっても、手書きのスライドが優先されます。実行が拒否されるのは、手書きのスライドが新旧両方の id に存在するときだけで、その場合は 1 つにまとめるよう案内が出ます。

lint が「対応するセクションのない HTML（`DEK002`）」を 1 件と、「手書き HTML のないセクション（HTML が未作成の `DEK001`、または未編集の骨格）」を 1 件だけ見つけたときは、改名と推定します。見出しとファイルのどちらを改名したのかは作者にしか分からないため、hint には 2 通りを両方示します。台本側にファイルを合わせる `dekc mv problem the-problem` と、ファイル側に台本を合わせる `dekc mv the-problem problem` です。どちらもそのまま実行できます。開発サーバーを動かしたままセクションを増やしたときのように候補が 2 件以上ある場合は、1 つに決め打ちせず `dekc mv problem the-problem` や `dekc mv problem qa` のように候補ごとのコマンドを並べます。スライドの削除は勧めません。

## ビート

`##` が 1 枚のスライドなら、`###` はその中の **ビート** です。喋りの区切りであり、画面を 1 段階進めるタイミングを表します。見出しの文言は自由で、発表者ビューの小見出しとして表示されます。

本番で右矢印キーを押すと、まず現在表示中のスライドのビートが順に進み、最後まで進むと次のスライドへ移ります。HTML 側に対応する要素がないビートがあっても構いません。画面を変えずに喋りだけを区切る目印として使えます。

スライドは、どのビートよりも先に表示されます。`##` と最初の `###` のあいだに書いた段落はスライドが表示された直後に喋る部分で、この時点ではビートに紐づけた要素はまだ見えていません。そこから 1 回送るたびに次の `###` へ進むため、最初のビートも含め、すべてのビートが同じ仕組みで自分に紐づく要素を表示します。`###` がないスライドは、表示された直後の状態だけのスライドです。`motion` ではスライド表示直後を `0`、各ビートを id または番号で指定します。ビートがないスライドでは `data-step` の紐づけ先がないため、`data-step` を書くと `DEK003` エラーになります。

*いつ* 出すかは喋りの判断なので台本に書き、*どう* 出すかは見せ方の判断なので `theme.css` に書きます。HTML 側の書き方は[ビート](./steps)を参照してください。

## 尺

frontmatter の `duration: 20m` はこのトークの持ち時間（予算）です。dek は本文の分量から所要時間を見積もります。既定の話速は CJK が 300 字/分、それ以外が 130 語/分で、引用（ト書き）は数えません。どちらの話速も `dek.toml` や frontmatter で調整できます。

`dekc ls` を実行すると、持ち時間・見積もり時間・セクションごとの時間配分が表示されます。各セクションの配分は本文の字数比で `duration` を按分した値です。`duration` を書いていない場合は見積もり時間だけが出ます。音声を合成して Timeline がある場合は、実際のナレーション時間が隣に並んで表示されます（見積もりと実尺は並べて見せるだけで、混同はしません）。

デモが長く台本が短いスライドは、見積もりも短く出ます。デモ中に喋るつもりなら、その言葉も台本に書いておけば見積もりに含まれます。無音の時間を指定する記法は台本にも設定にもありません。

`event` と `date` は `dekc ls` の一覧表示に使われます。スライドへ自動で挿入されることはないため、画面に出したい場合はタイトルスライドの HTML に直接書いてください。
