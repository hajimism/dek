# 台本

`script.md` が持つのは 3 つだけです。トークの順序、喋る言葉、そして持ち時間。レイアウトや装飾はスライドの HTML に、声は `voice/` に属します。台本はどちらも知りません。

## 3 つのルール

覚えるルールは 3 つです。`##` の見出しが 1 枚。その下に書いたものがその枚の台本。喋りになるのは段落だけ。

```markdown
---
# yaml-language-server: $schema=../../.dek/schema.json
title: HTML スライドツールを作った話
event: Tokyo Frontend Meetup #42
date: 2026-04-18
duration: 20m
---

## intro

こんにちは。今日は、スライドツールを自分で作った話をします。

> 自己紹介は短く。時計を見ない。

## 発表の前日に何をしていますか {#problem}

みなさん、発表の前日に何をしていますか。

聴衆が「自分ごと」だと思うまで喋る。3 つ目が本命。

## architecture

さて、ここが今日いちばん覚えて帰ってほしいところです。

### script.md が親 {#script-parent}

まず script.md がいて、

### スライドがぶら下がる {#slides-hang}

その下にスライドがぶら下がっている。逆ではありません。
```

見出しの文言は自由です。日本語でも、疑問文でも、句読点が入っても構いません。プレゼンタービューは各セクションの Markdown をそのまま表示します。

声になるのは段落だけです。引用、リスト、コードブロック、表は画面用かト書きで、合成の対象になりません。インラインの強調、リンク、`code` は合成の前にプレーンテキストに剥がされます。これらはライブの発表には一切影響せず、`dek cues` を叩くか声を付けたときにだけ効きます。リストはあるのに段落がないビートは、画面には出るのにナレーションでは一瞬で通過します。`dek cues` と、`voice/` のあるデッキの lint がそれを `DEK042` で知らせます。

ト書きには引用を使ってください。ナレーションを付けたとき、これは守る価値のある規約になります。dek には「短い命令文を検出する」のような曖昧なト書き判定も、間を取るための特別な記法もありません。

## 見出しと id

`slides/` のファイル名と CLI の `<slug>` 引数が使うのはセクションの **id**、プレゼンタービューが使うのは見出しの **文言** です。id は `[a-z0-9-]+` にマッチし、英字を 1 文字以上含みます。数字だけの id は数値の `data-step` と衝突するので受け付けません。

表示と同一性は Pandoc 流の `{#id}` で分けます。

- 見出しがそのまま id として通るなら、それが id です。`## intro` は `slides/intro.html` になります。
- そうでなければ `{#id}` が必須です。`## 発表の前日に何をしていますか {#problem}` は `slides/problem.html` になります。付け忘れは行番号付きのエラーです。
- id として通る見出しにも `{#id}` は付けられます。表示名とファイル名を分けたいときに使います。`## intro {#opening}` は「intro」と表示され、`opening.html` に保存されます。
- id だけの見出しには表示する文言がありません。生成される骨格の `<h2>` は空になります。例外は先頭のセクションで、デッキの `title` が入ります。プレゼンタービューには id が出ます。

対応する属性は `{#id}` だけです。`{.class}` や `key=value` は拒否されます。セクションの id はデッキ内で一意、ビートの id はセクション内で一意でなければなりません。

## 改名と並べ替え

`dek sync` はファイルをリネームしません。`## problem` を `## the-problem` に書き換えると、サーバは `the-problem` の骨格を新しく生成し、古い `problem.html` は孤児（`DEK002`）になります。紐付けが切れるだけで、中身は移りません。

同一性を付け替える操作は壊れやすいので、CLI が引き受けます。

```bash
dek mv problem the-problem
dek mv architecture --after intro
```

前者は `script.md` の id を書き換え、`slides/problem.html` をリネームします。見出しの文言には触れず、`the-problem.html` がすでにあれば実行を拒みます。後者は台本の中でセクションを動かします。HTML ファイルは順序を持たないので、その場に留まります。

lint が「HTML のないセクション（`DEK001`）」と「セクションのない HTML（`DEK002`）」をちょうど 1 件ずつ見つけたときは、改名だと推定して `dek mv <old> <new>` を提案します。どちらかが 2 件以上あるときは推測しません。

## ビート

`##` が 1 枚なら、`###` はその中の **ビート** です。喋りの区切りであり、画面が進んでもよい瞬間です。文言は自由で、プレゼンタービューの見出しになります。

本番で右矢印を押すと、まずいまの枚のビートが進み、使い切ると次の枚へ移ります。ビートに対応する要素が HTML になくても構いません。画面はそのまま、喋りだけが区切られる場所として使えます。

*いつ* 出すかは喋りの決定なので台本が持ち、*どう* 出すかは見せ方の決定なので `theme.css` が持ちます。HTML 側の書き方は[ビート](./steps)にあります。

## 尺

`duration: 20m` はこのトークの予算です。dek は本文から所要時間を見積もります。CJK は 300 字/分、それ以外は 130 語/分。引用はト書きなので数えません。どちらの速度も `dek.toml` で変えられます。

`dek ls` は予算、見積もり、セクションごとの内訳を出します。各セクションの予算は、本文の字数比で `duration` を按分したものです。`duration` がなければ見積もりだけが出ます。声を合成して Timeline があるときは、実際のナレーションの長さが見積もりの隣に並びます。並べて見せますが、同一視はしません。

デモが長く台本が短い枚は、見積もりが短く出ます。デモの間に喋るつもりなら、その言葉を書いてください。書けば数に入ります。無音の時間を表す記法は、台本にも設定にもありません。

`event` と `date` は `dek ls` に表示され、タイトルスライドから参照できます。
