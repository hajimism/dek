# FAQ

## どうやってインストールしますか

`bunx @hajimism/dek init` でプロジェクトを作成します。そのタイミングで dek 自身がプロジェクトにインストールされるため、以降はプロジェクト内で `bunx dekc` を使います。手順は[はじめる](./getting-started)を参照してください。

## `bunx dek` を実行すると別のツールが動きます

パッケージ名は `@hajimism/dek`、コマンド名は `dek` ではなく `dekc` です。npm 上の `dek` は無関係の別パッケージなので、`bunx dek` を実行するとそちらがダウンロードされてしまいます。プロジェクト内では `bunx dekc`、プロジェクトの外では `bunx @hajimism/dek` を使ってください。

## Slidev を使うべきなのはどんなときですか

ライブコーディング、スライド内の Vue コンポーネント、npm で配布されるテーマ、埋め込みエディタが必要なときです。dek は喋りが主役のトーク向けで、スライドは素の HTML と CSS だけで構成します。比較表は [dek の設計思想](./why#他のツールとの違い)を参照してください。

## HTML を書かなければいけませんか

いいえ。`script.md` を書いて `dekc` を起動すれば、同梱テーマの骨格スライドだけでそのまま発表できます。台本以上の図や表現を画面に載せたくなったタイミングで HTML を書き始めてください。

## 音声機能は必須ですか

いいえ。`voice/` を持たないデッキと持つデッキで、lint が失敗する条件はまったく同じです。音声関連のルール（`DEK040`・`DEK042`・`DEK043`）は `voice/` を有効にしたデッキに警告を追加するだけです。持ち時間と比較する `DEK041` は、`duration` を指定したすべてのデッキが対象になります。

## スライドのファイル名に連番がないのはなぜですか

順序を一元管理するファイルを `script.md` だけに絞るためです。ファイル名に番号を付けると並べ替えのたびに大量のリネームが発生し、Git の差分が読みにくくなります。順序の入れ替えには `dekc mv <slug> --before|--after <other>` を使ってください。

## `sync` は手書きの HTML を上書きしますか

一度でも手を入れたファイルは上書きしません。`sync` が自動管理するのは、まだ HTML がないセクションへの骨格生成と、未編集の骨格の更新・削除だけです。編集済みのファイルには触れず、対応するセクションが台本から消えた場合は lint が孤児ファイル（`DEK002`）として報告します。リネームも自動ではしないため、改名には `dekc mv` を使ってください。

## エージェントは何を実行しますか

人間とまったく同じ CLI です（`dekc help --agent`、`dekc check <slug> --shot`、`dekc lint --format sarif` など）。MCP サーバーは使いません。詳しくは[AI エージェントと作る](./ai)を参照してください。

## PowerPoint を使う人にトークを渡せますか

渡せます。`dekc pptx` を実行すると `dist/<deck>.pptx` が生成されます。`##` 1 つが 1 枚のスライドになり、PDF と同じく各スライドの最終ビートを出力します。単色・実線枠・角丸の単純な矩形は PowerPoint の図形に、画像と SVG は個別の画像に変換され、中の文字とグループ化されるため、受け取った側でテキスト修正・移動・色変更ができます。図形の外の文字はブロック単位のテキストボックスになり、ブラウザの折り返し位置で改行され、スライドの見出しはタイトルに設定されます。色とフォントのトークンは PowerPoint のテーマに、単純な背景はスライド背景に反映されます。グラデーション・影・疑似要素で描いた装飾など PowerPoint で完全再現できない要素は背面の画像として残ります。台本は発表者ノートに入り、`--public` を付けるとト書きが除かれます。生成したファイルは Keynote でも開けます（[発表する](./present#pptx)を参照）。

## 開発サーバーなしで発表できますか

できます。`dekc build` がトーク全体を 1 つの HTML ファイルにまとめるので、USB メモリに入れて持ち運べます。`p` を押すか `?presenter` を付けて開けば発表者ビューになり、同じファイルを別ウィンドウで開くと `BroadcastChannel` で同期します。開発サーバーが必要になるのは、スマートフォンなど別デバイスから操作したいとき（`dekc --remote`）だけです。

## Playwright・ffmpeg・VOICEVOX は必須ですか

いいえ。いずれも任意で、未導入の場合はそのツールを必要とするコマンドだけが導入手順の hint 付きで失敗します。`--visual`・`shot`・`pdf`・`video` は Playwright を、`video` は加えて ffmpeg を、`voice`・`rehearse`・`video` は VOICEVOX 互換エンジンを使います。Playwright は `dekc init --browser` でプロジェクト作成時にまとめて導入できます。音声エンジンの導入手順は[声と動画](./voice#セットアップ)を参照してください。

## 間や無音の時間はどこに書きますか

台本には書きません。段落のないビートは遷移と `pause.beat` の時間だけを通過します。デモの合間に喋るつもりなら、その言葉を台本に書いておけば見積もり時間に含まれます。ナレーションで特定のビートやスライドの後に長めの間を取りたい場合は、`voice/voice.toml` で設定します（[タイミング](./voice#タイミング)を参照）。

## スライド内で JavaScript は動かせますか

HTML の中に `<script>` を書くことはできません（`DEK011` エラーになります）。カウンターやアニメーションするグラフなど CSS だけでは表せない動きは、スライド横の `slides/<id>.ts` に時間 `t` の関数 `draw` として書きます。時計をランタイム側が管理するため、ライブ発表ではリアルタイム再生、`dekc video` では 1 フレームずつのシーク、`dekc shot` と PDF では最終状態の描画が同じコードで動きます。クリックに反応するインタラクティブなデモは対象外です（[スクリプトで動かす](./steps#スクリプトで動かす)を参照）。

## 1 枚だけの CSS はどこに書きますか

HTML の横に `slides/<id>.css` として置きます。そのスライドだけに自動スコープされ、テーマのクラス上限 `max_classes` にも数えられません（[スライドごとの CSS](./slides#スライドごとの-css)を参照）。
