# FAQ

## どうやって入れますか

dek は npm にありません。`bunx github:hajimism/dek` で GitHub から直接実行するか、プロジェクトの中で `bun add github:hajimism/dek` と固定してから `bunx dek` を使います。手順は[はじめる](./getting-started)にあります。

## Slidev を使うべきなのはどんなときですか

ライブコーディング、スライド内の Vue コンポーネント、npm のテーマ、埋め込みエディタが必要なときです。dek は喋りが主役のトークのためのもので、素の HTML と CSS だけを表面に持ちます。比較は [dek の設計思想](./why#他のツールとの違い)にあります。

## HTML を書かなければいけませんか

いいえ。`script.md` を書いて `dek` を叩けば、同梱テーマの骨格スライドで発表できます。画面に台本以上のことを語らせたくなったときに、HTML を書き始めてください。

## 声は必須ですか

いいえ。`voice/` のないデッキの完成の定義はまったく同じで、lint が通れば完成です。声は、オプトインしたデッキにだけ警告（`DEK040`、`DEK041`、`DEK042`）を足します。

## スライドのファイル名に番号がないのはなぜですか

順序を知っていてよいファイルは一つだけで、それは `script.md` です。番号付きのファイル名は並べ替えのたびにリネームを強い、差分を壊します。並べ替えは `dek mv <slug> --before|--after <other>` で行います。

## `sync` は HTML を上書きしますか

しません。HTML のないスライドに骨格を作り、孤児を警告するだけです。リネームもしません。改名は `dek mv` です。

## エージェントは何を叩きますか

人間と同じ CLI です。`dek help --agent`、`dek check <slug> --shot`、`dek lint --format sarif`。MCP サーバはありません。[AI エージェントと作る](./ai)を読んでください。

## 開発サーバなしで発表できますか

できます。`dek build` が HTML を 1 ファイル作ります。USB メモリに入れてください。`p` を押すか `?presenter` を付けて開くと、別ウィンドウが `BroadcastChannel` で追従します。別のデバイスからデッキを操作したいときだけ `dek --remote` を使います。

## Playwright、ffmpeg、VOICEVOX は必須ですか

いいえ。どれも任意で、足りないときはそれを必要とするコマンドだけが、インストール手順の hint 付きで失敗します。`--visual`、`shot`、`pdf`、`video` は Playwright を、`video` は加えて ffmpeg を、`voice`、`rehearse`、`video` は VOICEVOX 互換エンジンを使います。エンジンの入れ方は[声と動画](./voice#セットアップ)にあります。

## 間や無音の時間はどこに書きますか

どこにも書きません。段落のないビートは遷移と設定された `pause.beat` を通過するだけです。デモの間に喋るなら、その言葉を台本に書いてください。書けば見積もりに数えられます。
