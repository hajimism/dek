# 発表する

作業中は開発サーバがブラウザをファイルと同期させます。会場では HTML ファイルが 1 つあれば足ります。このページではその両方に加えて、プレゼンタービュー、別デバイスからのリモート操作、PDF 書き出しを扱います。

## 開発サーバ

デッキの中で `dek` を叩けばそのデッキを、プロジェクト直下で叩けば全デッキの一覧を配信します。

```bash
dek
dek --visual
dek --port 3030
```

`--port` を省くと、空いているポートを OS が選び、`dek` がその URL を表示します。ほかのツールにアドレスを事前に教える必要があるときは固定してください。

保存のたびに次が起きます。

- **`script.md`** — 新しい見出しに骨格が生成され、孤児になった HTML がブラウザに警告表示され、プレゼンターノートが更新されます。デッキに `voice/` があれば、変わった文だけが再合成されます。
- **`slides/*.html`** — 変更された枚だけがその場で差し替わり、lint が走り、診断が端末とブラウザのオーバーレイの両方に出ます。
- **`theme.css`** — 全スライドが再描画され、クラス語彙が再解決されます。
- **`slides/*.css`** — スタイルがその場で当て直され、lint が走ります。
- **`slides/*.ts`** — スライドスクリプトは読み込み時に一度だけ登録されるので、ページが再読み込みされ、lint が走ります。
- **`voice/voice.toml`** — キャッシュ済みのクリップからデッキのタイミングを組み直します。
- `--visual` を付けて Playwright があれば、保存した枚のはみ出しとコントラストも測ります。

プロジェクトごとにサーバは 1 つです。2 つ目の `dek` は `.dek/server.json` にある 1 つ目のロックを見つけ、その URL を案内します。

## プレゼンタービュー

`/presenter` を開くか、プレイヤーで `p` を押します。いまのスライド、次のビートかスライドのプレビュー、いまのセクションの台本が並び、いまのビートがハイライトされます。台本は段落内の改行を詰めて表示するので、エディタではなくプレゼンタービューの幅で折り返されます。日本語は間を空けずに繋ぎます。ト書き、リスト、コードは行を保ちます。上端の進捗バーはデッキ全体の位置を示します。下端には枚数、いまのセクションの予算、そして最初に送ってからの経過時間。経過時間はトーク全体の予算の 80% を超えると黄色、100% を超えると赤になります。もう一度 `p` を押すと、同じウィンドウで観客ビューに戻ります。

接続しているすべてのウィンドウが WebSocket でプレゼンターに追従します。2 台目のモニタでも、別のノート PC でも、スマホでも。サーバの再起動や Wi-Fi の瞬断で接続が切れたウィンドウは自分でつなぎ直し、いま映っているスライドに追いつきます。切れている間にそのウィンドウで進めた位置は、つながった時点で送られます。

```bash
dek goto architecture
dek current
```

サーバが立っている間、端末からブラウザを動かし、いま何の枚が出ているかを尋ねられます。エージェントも同じ 2 つのコマンドを使います。

## キー操作

| キー | 動作 |
| --- | --- |
| `→` `PageDown` `Space` | 次のビート。使い切ったら次のスライド |
| `←` `PageUp` `Backspace` `Shift+Space` | 前のビート。使い切ったら前のスライド |
| `Home` `End` | トークの最初のビート、最後のスライドの最後のビート |
| `p` | プレゼンタービューの切り替え |
| `s` | スライド一覧の表示切り替え |
| `f` | 全画面の切り替え |
| `↑` `↓` | スライド一覧の中を移動 |
| 一覧の端で `←` `→` | スライド一覧の幅を変える |
| `Space` | `dek rehearse` 中の再生 / 停止 |

押したキーはすべて数に入ります。クリッカーで先へ飛ばすときのようにトランジションより速く押しても、再生中のトランジションを切り上げて、押した回数ぶん先へ進みます。別ウィンドウも押すたびにすぐ追従します。`Alt`、`Ctrl`、`Cmd` と組み合わせたキーはブラウザのもので、スライド上の入力欄に打ったキーは入力欄のものです。

スマートフォンやタブレットでは、スライドをタップすると次へ、左 3 分の 1 をタップすると前へ進み、横にスワイプしても移動できます。リンク、ボタン、入力欄へのタップはそれぞれのものです。狭い画面やタッチ画面では、スライド一覧とキーの案内は出しません。

URL はデッキの位置を表します。スライドは `#<slug>`、そのスライドの n 番目のビートは `#<slug>/<n>` です。履歴にはスライドごとに 1 件だけ積むので、ブラウザの「戻る」はビートを一つずつ戻るのではなく、前のスライドへ戻ります。スライドの最後より大きいビート番号を開くと最後のビートで開き、URL もそれに合わせて書き直します。

## 1 ファイル

```bash
dek build
```

`decks/<deck>/dist/<deck>.html` ができます。全スライド、テーマ、data URI 化した画像、プレイヤーのランタイムを minify して 1 ファイルにしたものです。ブラウザで開いて発表します。`--root-dist` を付けると、全デッキのビルドがプロジェクト直下の `dist/` に集まります。

build がやることは 4 つです。各 `<section class="slide">` を抜き出して `data-slug` を付ける、テーマを minify する、`assets/` を data URI にする、ランタイムを埋め込む。外部の HTML minifier は使わないので、入力の書き方がどうであれ出力は一つの形になります。HTML がまだないセクションは、`dek sync` が書くはずの骨格からビルドし、そのことは lint の `DEK001` が伝えます。lint の結果でビルドが止まることはありません。

`?presenter` を付けて開くか `p` を押すとプレゼンタービューになります。同じファイルを別ウィンドウで開けば、`BroadcastChannel` で最初のウィンドウに追従します。観客ビューをプロジェクタに、プレゼンタービューを手元に。サーバもネットワークも要りません。別のデッキのファイルを同時に開いても、そちらは追従しません。観客ビューには左にスライド一覧があり、サムネイルをクリックすればその枚へ飛べます。`s` で隠し、端をドラッグして幅を変えられます。ファイルを開くと、`s` と `p` の案内が下にふわっと出て、しばらくすると消えます。キーを押せばその場で消えます。dev サーバーでは保存のたびに読み込み直すので、この案内は出しません。

印刷はブラウザの「印刷」で構いません。スライドはデッキの大きさとそのレイアウトのまま 1 枚ずつ別のページになり、ビートはすべて表示され、スライドスクリプトは最後のビートの状態で描かれ、スライド一覧や案内は印刷されません。`dek pdf` はダイアログなしで同じページを書き出します。

## 別のデバイスから

会場で開発サーバを使うのは、スマホをリモコンにするなど、別のデバイスからデッキを操作したいときだけです。

```bash
dek --remote
dek --remote --password s3cret
```

LAN に公開します。台本から作られるものはすべて HTTP Basic 認証の後ろにあります。プレゼンタービュー、`goto` と `current`、音声のタイムラインとオーディオ、開発サーバが配信する lint の診断です。観客ビュー、スライド、その素材は開いています。`--password` を省くと dek がパスワードを生成し、URL とともに表示します。

USB メモリの 1 ファイルは、必ず動くフォールバックです。それ以外はすべて任意です。

## PDF

```bash
dek pdf
```

全スライドを最終ビートの状態で `dist/<deck>.pdf` に描き出します。Playwright が必要です。
