# 発表する

制作中は開発サーバーがファイルとブラウザを同期させ、本番の会場では 1 つの HTML ファイルだけで発表できます。このページでは、その両方に加えて発表者ビュー、別デバイスからのリモート操作、PDF・PPTX の書き出しまでを扱います。

## 開発サーバー

デッキの中で `dekc` を実行するとそのデッキを、プロジェクト直下で実行すると全デッキの一覧を配信します。

```bash
dekc
dekc --visual
dekc --port 3030
```

`--port` を省略すると OS が空いているポートを割り当て、`dekc` がその URL を表示します。外部ツールにアドレスを事前に渡す必要があるときは `--port` で固定してください。

URL は通常のブラウザタブで開いてください。開発サーバーは別オリジンからの埋め込み表示を拒否するため、VS Code の Simple Browser のようにページをフレーム内で開くプレビューでは何も表示されません。

ファイルを保存すると、種類に応じて次の処理が走ります。

- **`script.md`** — 新しい見出しに骨格を生成し、孤児になった HTML があればブラウザに警告を出し、発表者ビューの台本を更新します。`voice/` があるデッキでは変更された文だけを再合成します。
- **`slides/*.html`** — 変更したスライドだけをその場で差し替え、lint の結果をターミナルとブラウザのオーバーレイに出します。
- **`theme.css`** — 全スライドを再描画し、有効なクラス一覧を再解決します。
- **`slides/*.css`** — スタイルをその場で当て直し、lint を走らせます。
- **`slides/*.ts`** — スライドスクリプトは読み込み時に一度だけ登録されるため、ページをリロードして lint を走らせます。
- **`voice/voice.toml`** — キャッシュ済みの音声クリップからデッキのタイミングを組み直します。
- `--visual` 指定時（Playwright 導入済み）は、保存したスライドのはみ出し・コントラスト・改行・揃えも計測します。

開発サーバーはデッキごとに 1 つずつ起動でき、別のデッキの `dekc` はそれぞれ別のポートで並行稼働します。プロジェクト直下で起動するサーバーは全デッキを配信するため、他のサーバーが動いていない間だけ起動できます。すでに配信中のデッキに対して 2 つ目の `dekc` を実行すると拒否され、稼働中サーバーの URL が案内されます。ロックファイルはプロジェクト全体のサーバーが `.dek/server.json` に、デッキ専用のサーバーが `.dek/servers/<deck>.json` に置きます。

## 発表者ビュー

`/presenter` を開くか、プレイヤー画面で `p` を押すと発表者ビューになります。現在のスライド、次のビート（またはスライド）のプレビュー、現在のセクションの台本が並び、いまのビートがハイライトされます。台本は段落内の改行を詰めて表示されるため（日本語はスペースを入れずに連結）、エディタではなく発表者ビューの幅に合わせて自然に折り返されます。ト書き・リスト・コードは元の改行を保ちます。

画面上端にはデッキ全体の進捗バー、下端にはスライド番号・現在のセクションの持ち時間・最初にスライドを送ってからの経過時間が表示されます。経過時間はトーク全体の持ち時間の 80% を超えると黄色、100% を超えると赤に変わります。もう一度 `p` を押すと、同じウィンドウで観客ビューに戻ります。

接続しているすべてのウィンドウは WebSocket で発表者ビューに同期します（2 台目のモニタ、別のノート PC、スマートフォンなど）。サーバーの再起動や Wi-Fi の瞬断で切断されても自動で再接続し、現在表示中のスライドへ追いつきます。切断中に手元で進めた位置があれば、再接続したタイミングで反映されます。

```bash
dekc goto architecture
dekc current
```

開発サーバーが動いている間は、ターミナルからブラウザの表示スライドを切り替えたり、現在の表示位置を取得したりできます。AI エージェントも同じ 2 つのコマンドを使います。

## キー操作

| キー | 動作 |
| --- | --- |
| `→` `PageDown` `Space` | 次のビートへ進む（最後なら次のスライドへ） |
| `←` `PageUp` `Backspace` `Shift+Space` | 前のビートへ戻る（最初なら前のスライドへ） |
| `Home` `End` | 最初のスライド表示直後／最後のスライドの最終ビートへ移動 |
| `p` | 発表者ビューの切り替え |
| `s` | スライド一覧の表示切り替え |
| `f` | 全画面表示の切り替え |
| `/` | 全スライドを検索 |
| `l` | レーザーポインターの切り替え |
| `m` | 表示中のビートに修正マークを付ける／外す（開発サーバー） |
| `a` | 注釈モードの切り替え（開発サーバー） |
| `↑` `↓` | スライド一覧の中を移動 |
| 一覧の端で `←` `→` | スライド一覧の幅を変更 |
| `Space` | `dekc rehearse` 中の再生／停止 |

キー入力は取りこぼさずに処理されます。クリッカーで連打するときのようにトランジションより速く押しても、再生中のトランジションを切り上げて押した回数ぶん進み、別ウィンドウも即座に追従します。`Alt`・`Ctrl`・`Cmd` と組み合わせたショートカットはブラウザ本来の動作になり、スライド内の入力欄にフォーカスがあるときの入力はその入力欄に入ります。

画面をタップまたはクリックすると次へ進み、左 3 分の 1 を押すと前へ戻ります。スマートフォンやタブレットでは横スワイプでも移動できます。ドラッグによるテキスト選択、選択解除のクリック、右クリック、修飾キー付きのクリックでは移動しません。リンク・ボタン・入力欄への操作はそれぞれの要素へ届きます。狭い画面やタッチデバイスでは、スライド一覧とキー操作ガイドは表示されません。

### レーザーポインター

`l` を押すか、発表者ビューのバー端にある丸いボタンを押すとレーザーポインターが有効になります。ポインターや指を置いた位置に、接続中の全ウィンドウで赤い点が表示されます（ウィンドウサイズによらず、スライド上の同じ座標に出ます）。レーザーがオンの間は画面のタップ・クリックでスライドが進まなくなるため、安心して指し示せます（キー操作では進みます）。

赤い点は、ポインターがスライドの外に出たとき、指を離したとき、別スライドへ移ったとき、レーザーをオフにしたときに消えます。位置通知が途絶えてから数秒後にも自動で消えるため、ノート PC を閉じてもプロジェクターに点が残りません。開発サーバーでは発表者だけがレーザーを共有でき、観客ウィンドウ側のレーザーはそのウィンドウ内だけに出ます。動画と PDF には映りません。

### リハーサル中のマーク

開発サーバーで声に出してリハーサルしながら、言いよどんだビートで `m` を押すか発表者バーの鉛筆ボタンを押すと、ビート一覧に鉛筆マークが付きます。マークは消すまで `.dek/marks.json` に保存されます。後から `dekc marks` を実行すると、マークしたビートが `script.md` の行番号と当時の文面つきで一覧表示されるため、自分で言い換えることもエージェントに書き直しを頼むこともできます（[リハーサルのあとで](./ai#リハーサルのあとで)を参照）。ビルドした HTML には保存先のサーバーがないため、マーク機能はありません。

### 注釈モード

エージェントに修正してほしい要素を直接伝えるには、開発サーバーで `a` を押すか、発表者ビューのバーにある ⌖ ボタンから注釈モードに入ります。

- **要素を選ぶ**：ポインターを乗せた要素が枠で囲まれ、`slides/<slug>.html` の該当行が表示されます。クリックで選択し、`Cmd` / `Ctrl` を押しながらクリックすると 1 つの注釈に複数要素をまとめられます。`pointer-events: none` の図形も選べますが、まだ表示されていないステップの要素は選べません。何もない場所をクリックすると、スライド上の座標に注釈が付きます。
- **注釈を書く**：ポップアップは選択した要素の横に重ならない位置で開き、クリック地点付近の要素が内側から順に並びます（文字 → それを囲む矢羽 → レーンなど）。対象を選んで修正内容を書き、`Enter` で確定します（`Cmd` / `Ctrl` を押している間はポップアップの下にある要素もそのままクリックできます）。
- **確認と共有**：各注釈には番号付きマーカーが付き、クリックで書き直しや削除ができます。**Copy** の横の件数を押すと全注釈がスライド・ビートごとに一覧表示され、クリックで該当スライドへ飛べます（編集で要素が消えた注釈にもここからアクセスできます）。**Copy** を押すと全注釈がエージェントへ貼り付けやすいテキストとしてコピーされます（LAN 経由でクリップボード API が使えない環境では、選択状態のテキストを表示します）。同じプロジェクトのエージェントなら、コピーせずとも `dekc annotations` で直接読み取れます（[指差しは双方向](./ai#指差しは双方向)を参照）。
- **保存と範囲**：注釈は `.dek/annotations.json` に保存されるため、リロードやサーバー再起動をまたいでも消えず、同じデッキを開いている全タブ・全端末で共有されます。編集で要素が動いても位置を追従します。すべて消した後でも、次の注釈を書くかモードを抜ける前ならバーの **Undo** で元に戻せます。モードがオフの間は何も表示されません。注釈モードは開発サーバーの発表者ページ専用で、LAN 上の観客ページ・ビルド済みファイル・動画には出ません。

### 検索と URL

`/` を押すとデッキ全体を検索できます。対象は全スライドの文字（未表示のステップも含む）、スライドタイトル、ファイルに含まれている場合は台本です。一致したスライドごとに番号・タイトル・前後文脈が一覧表示されます。全角と半角は同一視され、空白と改行は無視されます。`↑` `↓` で選び、`Enter` かクリックで該当文字が出るビートへジャンプし、そのスライドを離れるまで一致箇所がハイライトされます。`Esc`・× ボタン・パネル外クリックで閉じます（全画面時は最初の `Esc` で全画面が解除されます）。dek.pub のビューアのように別ページのフレーム内に埋め込んだデッキでも同様に検索できます。

URL ハッシュは現在位置を表します（スライドは `#<slug>`、n 番目のビートは `#<slug>/<n>`）。ブラウザ履歴にはスライド単位で 1 件だけ積まれるため、「戻る」ボタンでビートを 1 つずつ戻るのではなく前のスライドへ戻ります。存在しない大きいビート番号を開いた場合は最終ビートへ丸められ、URL もそれに合わせて更新されます。

## 1 ファイル

```bash
dekc build
```

`decks/<deck>/dist/<deck>.html` が生成されます。全スライド、テーマ、data URI 化した画像、プレイヤーのランタイムを 1 ファイルにまとめて minify したものです。ブラウザで開くだけで発表できます。`--root-dist` を付けると、全デッキのビルド結果がプロジェクト直下の `dist/` にまとまります。

`dekc build` が担当する処理は、各 `<section class="slide">` の抽出と `data-slug` 付与、テーマの minify、`assets/` の data URI 化、ランタイムの埋め込みの 4 つです。外部の HTML minifier を使わないため、入力の書き方によらず出力形式が安定します。HTML が未作成のセクションは骨格からビルドされ、その旨は lint の `DEK001` で通知されます（lint エラーがあってもビルド自体は止まりません）。

`?presenter` を付けて開くか `p` を押すと発表者ビューに切り替わります。同じファイルを別ウィンドウで開くと `BroadcastChannel` で同期するため、観客ビューをプロジェクターに、発表者ビューを手元のノート PC に置けば、サーバーもネットワークも不要です（別デッキのファイルを同時に開いても干渉しません）。

観客ビューの左にはスライド一覧があり、サムネイルをクリックして好きなスライドへ飛べます。`s` で表示を切り替え、端をドラッグして幅を調整できます。ファイルを開いた直後は画面下部に `s`・`/`・`p` の操作ガイドが一瞬だけ表示され、数秒後またはキー入力で消えます（`--no-script` ビルドでは発表者ビューがないため `s` と `/` のみ表示）。別ページのフレーム内に埋め込んだ場合や、保存のたびにリロードされる開発サーバーでは操作ガイドを出さず、埋め込み時はスライド一覧も閉じた状態で始まります。

## Web で公開する

ビルドした 1 ファイルは、そのまま任意の静的ホスティングへ公開できます。SNS などでリンクを共有したときにタイトル・説明・プレビュー画像のカードを出したい場合は、`dist/` を公開するベース URL を `dek.toml` に書きます。

```toml
# dek.toml
url = "https://example.com/talks/"
```

この設定があると、ビルド時に Open Graph と Twitter カードのメタタグが埋め込まれ、1 枚目のスライドを最終ビート状態で撮った `dist/<deck>.png` も隣に書き出されます。HTML と PNG の両方をアップロードしてください。クローラーは絶対 URL の画像しか取得できないため、`og:url` と `og:image` には設定した URL と各ファイル名を連結したアドレスが入ります。タイトルには frontmatter の `title`、説明には `description`（なければ `event` と `date`）が使われます。画像の生成には Playwright が必要ですが、Playwright や URL がない場合でもタイトルと説明のタグは出力され、不足している項目がビルド出力に表示されます。

プレビューデプロイのようにデプロイごとに URL が変わるホスティングでは、`dek.toml` の代わりに環境変数から `--url` で渡してください（`--url` は `dek.toml` より優先されます）。

```bash
dekc build --root-dist --url "https://$DEPLOY_HOST/"
```

アップロード後でないと URL が決まらない環境では絶対 URL を埋め込めないため、共有カードには画像なしでタイトルと説明だけが表示されます。

通常のビルドは発表用なので、URL 設定の有無にかかわらず発表者ビューに台本全文が含まれます。不特定多数へ公開するページには `dekc build --public` を使ってください。`--public` を付けると、発表者ビューには声に出す部分だけが残され、ト書き（引用）と HTML コメントが取り除かれます（コードブロックはそのまま残ります）。Web 公開用は `--public` 付き、本番発表用は `--public` なしまたは開発サーバー、と使い分けてください。

紙への印刷はブラウザの「印刷」メニューからそのままできます。スライドはデッキの縦横比とレイアウトを保ったまま 1 枚ずつ 1 ページになり、全ビートが表示され、スライドスクリプトは最終ビートの状態で描画されます。スライド一覧や操作ガイドは印刷されません。ダイアログなしで、どの PDF ビューアでも見た目が変わらないファイルを作りたい場合は `dekc pdf` を使ってください（[PDF](#pdf) を参照）。

## 別のデバイスから

会場で開発サーバーを使うのは、スマートフォンをリモコンにするなど、別デバイスからスライドを操作したいときだけです。

```bash
dekc --remote
```

LAN 内でサーバーを公開します。台本に関わるエンドポイント（発表者ビュー、`goto`・`current`、音声タイムラインとオーディオ、lint 診断）はすべて HTTP Basic 認証で保護されます。観客ビュー・スライド・アセットは認証なしで開けます。パスワードは起動のたびにランダムな 10 文字が生成され、URL と一緒にターミナルへ表示されます。認証ダイアログが出たらユーザー名には任意の文字、パスワードにその 10 文字を入力してください（任意のパスワードを指定できない仕様にすることで、弱いパスワードやシェル履歴への残留を防いでいます）。

スマートフォンで手入力を省きたいときは、パスワードの下に表示される QR コードを読み取ってください。サインイン済みの発表者ビューがそのまま開きます。QR コードに含まれるトークンは 1 回限り・5 分間有効なので、画面に映り込んだターミナルを撮影されても悪用されにくくなっています。別のデバイス向けに新しいコードを出したいときは、ターミナルで Enter を押してください。複数デッキがある場合はデッキ一覧が開き、各デッキから発表者ビューへ入れます。一度サインインしたスマートフォンは、サーバーを止めるまでセッションが維持されます。

開発サーバーは自身の IP アドレスとホスト名へのリクエストしか受け付けないため、外部サイト経由の DNS rebinding 攻撃は成立しません。また、同じブラウザで開いている別サイトから音声を再生したり、スタイルシートを適用したり、フレームに埋め込んだりすることもできません。`dekc <deck> --remote` で起動すると指定したデッキだけを公開し、プロジェクト内の他のデッキは見せません。ただしパスワード自体は平文の HTTP で送信されるため、信頼できるネットワーク内で使ってください。

USB メモリの 1 ファイル HTML は、ネットワークに一切依存しない確実なフォールバックです。それ以外の機能はすべて任意です。

## PDF

```bash
dekc pdf
```

全スライドを最終ビートの状態で `dist/<deck>.pdf` に書き出します。Playwright が必要です。

各ページは、ブラウザで 2 倍の解像度で描画したスライド画像の上に、選択・検索・コピー可能な透明テキストを重ねて構成します。リンクもそのまま機能します。ベクターのまま PDF 印刷すると、Chromium が出力するぼかし付き `box-shadow` や `background-clip: text` のグラデーションが、macOS のプレビュー・Quick Look・Safari・iPhone・iPad でベタ塗りの四角に化けてしまうことがあります。画像ベースにすることでどのビューアでも同じ見た目を保証しています。画像形式は輪郭が崩れない PNG が基本で、写真がスライド面積の 1 割以上を占め、かつ画質 90 の JPEG のほうが小さくなる場合だけ JPEG を選びます。代償として、大きく拡大すると文字がわずかにぼやけ、ファイルサイズもベクター PDF よりスライド 1 枚につき画像 1 枚分ほど増えます。

ブラウザの「印刷」ダイアログから保存した PDF は今もベクター出力のため、Apple 製ビューアで上記の四角が出ることがあります。外部へ配布する PDF には `dekc pdf` を使ってください。

## PPTX

```bash
dekc pptx
dekc pptx --public
```

PowerPoint や Keynote を使う相手（スライドを集める主催者、共同発表者、社内テンプレートへ流し込む担当者、受け取った後に編集を続けたい相手）向けに、`dist/<deck>.pptx` を書き出します。`##` 1 つが 1 枚になり、PDF と同じく各スライドの最終ビートを出力します。台本は発表者ノートに入り、`--public` を付けると `dekc build --public` と同様にト書きと HTML コメントを除きます。Playwright が必要です。

PDF と同じく実ブラウザで描画した結果をもとに、PowerPoint で忠実に再現できる要素をネイティブの図形や画像として取り出します。

- **単色・実線枠・角丸だけで描かれた要素は図形になります。** カード、チップ、セルを並べた表などが該当します。行の罫線のように辺ごとに異なる枠線は、辺ごとの線オブジェクトになります。
- **`<img>`・`<canvas>`・最外周の `<svg>` は、回転や切り抜きがなければ個別の画像になります。** 透明背景に影や枠線ごと描き出します。インライン SVG はテーマ色を書き込んだ SVG データも併せて埋め込むため、PowerPoint 上で図形へ変換できます（ただし padding・枠線・フィルター・クリッピング・属性で表せない CSS を含む SVG は、再現性を優先して画像のみにします）。
- **図形の中の要素は、その図形とグループ化されます。** カードを動かすと中のアイコンや文字も一緒に追従します。
- **図形の中の文字は、その図形のテキストになります。** 上下に並ぶブロックは段落になり、`disc`・`circle`・`square`・`decimal` のリストマーカーは箇条書き記号に変換されます。文字はブラウザの配置位置から上揃えで置かれ、flexbox / grid で中央寄せされた文字は中央揃えになります。
- **それ以外の文字は、ブロックごとに 1 つのテキストボックスになります。** 幅はブロックの幅に一致し、リストは各項目を段落にした 1 つのテキストボックスにまとまります。スライドで最上位の見出しは PowerPoint のスライドタイトルとして設定され、一覧表示にも使われます（見出し前に `::before` で付けた番号や記号はタイトルに含みません）。
- **段落はブラウザが折り返した位置で改行します。** 各行末に改行を入れるため、文節区切りなどの折り返しが維持されます。行末に余裕がある段落は幅に合わせて自動折り返しし、文字幅ぴったりに描かれたチップは折り返しません。
- **通常の行に収まらないテキストは、1 行ずつのテキストボックスになります。** 途中にチップを含む行、行送りが不ぞろいな行、インデント付きのコードブロックの行などが該当し、ブラウザが配置した座標に置かれます。
- **`::before`・`::after` の生成テキストも文字として出力します。** ノンブルやランニングヘッドなどが該当し、CSS カウンターは計算済みの数字が入ります（スライド順を動かしても自動では振り直されません）。
- **文字間隔はブラウザの描画位置に合わせて調整します。** PowerPoint は OpenType 機能を適用しないため、`font-feature-settings: "palt"` で詰めたかな・約物や、連続する約物の半角詰めなど差が出る箇所は 1 文字ずつ字間を書き込みます（欧文同士のカーニングは PowerPoint 側に任せます）。
- **テーマトークンが PowerPoint のテーマにマッピングされます。** `--fg`・`--bg`・`--muted`・`--accent` が配色の「濃色 1」「淡色 1」「濃色 2」「アクセント 1」に、`--font-title` と `--font-body` が見出し・本文フォント（そのトークンで組まれた文字の大半を描画した書体名）になります。トークンを使った図形・線・文字はテーマを参照するため、PowerPoint のデザインタブから配色やフォントを一括変更できます。
- **スライド背景も PowerPoint の背景になります。** 単色、または水平・垂直の sRGB 線形グラデーションが対象で、`--bg` ならスライドマスターの背景に、それ以外はそのスライド個別の背景に設定されます。背景画像・テクスチャ・グラデーション罫線が重なっている場合も下地の色は PowerPoint の背景にし、上の要素だけを画像に残します（ぼかした光など下地を抜くとファイルサイズが大きく膨らむ要素が重なる場合は、背景全体を画像に残します）。

**上記以外の要素はすべて、背面の画像にまとまります。** 2 倍解像度で描き、背景色が PowerPoint 側で表現できる場合は透明背景にします（画像に残る要素が何もないスライドには背面画像を差し込みません）。背面画像に残るのは、グラデーション・影・フィルター・背景画像やテクスチャ・疑似要素で描いた箱や影・PowerPoint にないリストマーカー・図ではない `aria-hidden` の装飾・`transform` で回転させた文字・`text-shadow`・負の `z-index`・カスタム要素など、PowerPoint でブラウザと同一に描けない要素です。また、背面画像に残る要素を覆ってしまう箱や、描画順序が崩れる恐れのある重なりを持つ箱も背面画像側に残します。蛍光ペン風のグラデーションや `::before` マーカーを持つカードは背面画像として描き、その上に編集可能なテキストだけを置きます。こうしたカードを図形として出力したい場合は、単色背景と通常のリストマーカーで書いてください。

コマンド出力には、取り出した図形・画像の件数と、何も取り出せなかったスライド名が表示されます。相手側で編集してほしいスライドがそこに挙がっていたら、単純な矩形構成へ見直す目安になります（`--json` は `outs` のみを返します）。

```text
wrote dist/talk.pptx
  laid 19 shapes and 4 pictures over the picture; nothing on cover, close
```

テキストには Chromium が実際に描画した欧文・和文それぞれのフォント名（フォントトークン経由ならテーマフォント）を指定し、フォントファイル自体は埋め込みません。相手環境にそのフォントがない場合は代替フォントで同じ位置に表示されますが、字間は元のフォントに合わせたままです（1 行テキストボックスでは行長が少し変わるだけで済みますが、折り返す段落では改行位置が変わることがあります）。標準と太字以外にもウェイトを持つファミリー（W0〜W9 がある Hiragino Sans など）では、PowerPoint と Quick Look で標準・太字の解釈が異なり Chromium とも一致しないため、「Hiragino Sans W6」のように具体的なウェイト名を指定します。フォントトークンで組んだ段落内の太字など大半と太さが異なる部分にも個別のウェイト名が入り、テーマフォントを変更しても変わりません（こうした書体に PowerPoint で太字を適用すると擬似太字になるため、別のウェイトを使いたい場合はフォントメニューから選んでください）。編集してほしい文字は SVG ではなく HTML で書いてください。各画像の代替テキストには `alt`・`aria-label`・`<title>`（いずれも `DEK034` が求める属性）が設定され、背面画像にはそこに残った要素の代替テキストが入ります。

### 編集するために作り直す

```bash
dekc pptx spec
dekc pptx --from decks/talk/pptx.json --shot
```

`dekc pptx` の出力は見た目を忠実に保つため、PowerPoint で再現できない要素を背面の画像として残します。しかし受け取った側が自分のテンプレート上で作り直すときには、その背面画像が邪魔になります。編集用途では、文字ブロックは折り返す 1 つのテキストボックス、カードや箱は文字入りの図形とし、背後に余分な画像が残らないファイルが求められます。これにはスライドごとの設計判断が必要なため、dek は計測データをエージェントに渡し、エージェントが再構築した結果を検証する流れを採っています。手順は任意スキルの `dek-pptx` が案内します（[AI エージェントと作る](/ja/guide/ai)）。

`dekc pptx spec` を実行すると、デッキの `.cache/pptx/` に以下のファイルが書き出されます。

- **`deck.pptx.json`**（および隣のスキーマ）— `dekc pptx` の出力を JSON 化した初期ベース
- **`spec.json`** — 各スライドの要素を読み順に並べた計測データ（位置・塗り・文字・各行の配置・表の格子とセル位置・スライドのスクリーンショット・発表者ノート）
- **`parts/`** — 個別画像、およびグラデーションや `clip-path` など図形化できない部分を文字抜きで切り出した画像

エージェントは通常、`spec.json` を読むスクリプトを書いてデッキを JSON 形式に組み直します。

`dekc pptx --from <file>` はその JSON から `dist/<deck>.pptx` を生成します。デッキのテーマを適用し、スライド見出しを PowerPoint のタイトルに、表を編集可能な PowerPoint の表（セル入力に応じて行高が伸びる形式）にし、全スライド共通の背景画像はスライドマスターへ配置します。生成後、`spec.json` と突き合わせて以下の項目を検査します。

| id | 重要度 | 検出する問題 |
| --- | --- | --- |
| `pptx-slides` | error | スライドの不足・過剰・順序の不一致 |
| `pptx-title` | error | タイトルがない、複数ある、または空のスライド |
| `pptx-text` | error | 元のスライドにあるのに PPTX に含まれていない文字 |
| `pptx-bounds` | error | スライドの端からはみ出したレイヤー |
| `pptx-place` | warning | 元の配置位置から大きくずれた文字 |
| `pptx-fit` | warning | 1 行テキストに対し、PowerPoint 描画時に幅が不足する恐れのあるボックス |
| `pptx-picture` | warning | 残存したスライド背面画像や、スライドの大半を覆う画像 |
| `pptx-lines` | warning | 1 行ずつテキストボックスに分割された文字 |
| `pptx-notes` | warning | 台本があるのに空の発表者ノート |

グラフはまだ JSON で表現できないため該当部分の画像のままになります。error がある場合は `dekc lint` と同様に終了コード 1 で失敗しますが、確認用に PPTX ファイル自体は書き出します。`spec.json` がないかデッキより古い場合は検査を行わず、`skipped` で `dekc pptx spec` の再実行を案内します。`--shot` を付けると macOS の Quick Look で各スライドを描画し、ブラウザのスクリーンショットと並べて差分を赤く塗った比較画像と差分値を出力します（Quick Look の描画は PowerPoint 本体と完全には一致しないため、受け渡し前に PowerPoint で最終確認してください）。
