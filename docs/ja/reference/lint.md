# Lint ルール

lint がワークフローにどう組み込まれるかは [Lint](/ja/guide/lint) にあります。このページは ID と条件の表です。

| ID | 条件 | `--fix` |
| --- | --- | --- |
| `DEK001` | `script.md` のセクションに対応する HTML が `slides/` にない | 骨格を作る |
| `DEK002` | `slides/` の HTML、スタイルシート、スクリプトに対応するセクションが `script.md` にない | — |
| `DEK003` | `data-step` がその枚のビート id でも有効な位置でもない | — |
| `DEK004` | セクション id がデッキ内で重複、またはビート id がセクション内で重複 | — |
| `DEK005` | 同じ枚に `data-morph` 名が重複、または予約された名前（`slide`、`root`、`none`、`auto`、`match-element`） | — |
| `DEK006` | `data-slug` がセクション id と一致しない | — |
| `DEK010` | テーマにも、その枚のスタイルシートにも定義のないクラス | — |
| `DEK011` | スライド内の `<style>`、`style=`、`<script>` | — |
| `DEK012` | テーマにトップレベルセレクタ、またはスライドのスタイルシートにスライドの外まで届くルール（`::view-transition-*`、`@font-face`、`@import`、`:root`、`html`、`body`） | — |

| `DEK014` | トークンへの代入の外にある生の色、`font-family`、絶対単位。テーマでもスライドのスタイルシートでも | — |
| `DEK015` | 必須トークンが `.slide` に無い | — |
| `DEK016` | 動かせないスライドのスクリプト。import、名前付き export、default export がない、構文エラー、トップレベルの await や例外、スライドのビートにない `motion` のキー、終わらないトップレベル、`.ts` ではなく `.js` で置かれたスクリプト | — |

## 条件

- `DEK030` と `DEK031` は `--visual` のときだけ動き、Playwright が必要です。どちらも各ビートの終わり、つまりアニメーションとトランジションをすべて最後まで進めた姿を測ります。[静止画に写るもの](/ja/guide/steps#静止画に写るもの)を参照してください。
- `DEK040`、`DEK042`、`DEK043` は `voice/` のあるデッキだけに適用されます。`dek cues` は `voice/` の有無に関わらず `DEK042` を報告します。
- `DEK041` は `duration` のあるデッキに適用されます。Timeline があればナレーションを測り（許容幅 20%）、なければ字数からの見積もりを使います（許容幅 35%）。
- `DEK040` から `DEK043` は警告です。`"severity": "warning"` として報告し、lint を失敗させません。それ以外のルールはすべて error です。ライブ専用デッキの完成の定義は変わりません。

## 補足

### DEK001 / DEK002

`DEK001` は `script.md` の該当する見出しを指し、`data.expected` に探した HTML のパスが入ります。`--fix` は骨格を作り、既存ファイルには触れません。セクションのない HTML が 1 件、自分の HTML を持たないセクション（HTML がないか、生成された骨格のまま）が 1 件なら改名を疑い、両方の診断に `` run `dek mv <old> <new>` `` を hint として付けます。このコマンドは、`script.md` を先に書き換えていてもいなくても動きます。候補が 2 件以上あれば推測しません。

### DEK003

解決できない参照です。要素のないビートは問題なく、位置が連続している必要もありません。hint には、そのスライドで使える id と位置が並びます。

### DEK005

`data-morph` の名前は同じ枚の中で一意でなければなりません。`view-transition-name` になるので、ブラウザは遷移の両側にちょうど 1 つずつの要素を必要とします。別々の枚に同じ名前を付けるのが本来の使い方です。

使えない名前もあります。プレイヤーはスライドの枠に `slide`、ブラウザはページ全体に `root` という名前を付けているので、どちらかを付けるとページの切り替えそのものとぶつかります。`none`、`auto`、`match-element` は `view-transition-name` のキーワードなので、その要素は引き継がれません。

### DEK010

`theme.css` にそのクラスを定義すれば解消します。その枚でしか使わないなら `slides/<id>.css` に定義します。共有の語彙を増やすのは設計判断で、lint はそれを目に見える一手にします。`DEK013` がその一手の回数に上限を置きます。スライドのスタイルシートは数えません。hint には定義済みのクラスが並びます。`slides/<id>.ts` から要素を探すためだけのクラスなら、代わりに `data-*` 属性を使ってください。

### DEK014 / DEK015

hint には、その値の代わりに使えるテーマのトークンが入ります。色なら色のトークン、`font-size` なら `--size-*` といった具合です。合うものがなければ、`theme.css` にトークンを足すよう案内します。

生の値は `--*` プロパティへの代入にだけ書けます。単位なしの `0`、`thin`、`em` は通ります。生のフォールバック付き `var()` は通りません。契約の 13 トークンはすべて `.slide` に公開する必要があります。追加のトークンは歓迎します。

### DEK016 / DEK017

`DEK016` はスクリプトが動かないこと、`DEK017` は動くものの `t` 以外に依存している、またはテーマが名前を変えうるクラスで要素を探していることを表します。どちらもスクリプトのファイルを指し、`DEK017` は行も示します。import のあるスクリプトも import を除いて評価するので、`motion` のキーは同じ実行の中で検査されます。

### DEK020 / DEK021 / DEK022 / DEK023

自己完結の規約です。リモートも、プロジェクト直下も、隣のデッキも参照できません。ローカルの `src` は `assets/` で始めます。`dek build` が全アセットをインライン化でき、プロジェクト直下で立てた開発サーバがそれらを配信できるのは、この制約があるからです。

### DEK030

hint は、そのスライドの中で直す方法だけを示します。内容を削る、ビートやスライドに分ける、`slides/<id>.css` で大きさを調整する、のいずれかです。すべてのスライドに効くテーマのトークンの変更は勧めません。

メッセージには、要素、そのテキストの冒頭、越えた辺、何ピクセル越えたかが入ります。子は親が収まっている辺についてだけ報告されるので、下にはみ出したリストは 1 件です。複数のビートで同じ指摘は、ビートを並べた 1 件の診断になります。箱だけでなく文字列も測るので、URL のように折り返せない文字列は箱が収まっていても数えます。

### DEK031

閾値は WCAG AA に従います。本文は 4.5:1、大きな文字は 3:1。大きな文字とは、計算後の `font-size` が 24px 以上、または 18.66px 以上で `font-weight` が 700 以上のものです。淡い色の大きな数字は通り、同じ色の本文は落ちます。閾値は変更できません。メッセージには要素、そのテキスト、前景色と背景色が入ります。

コントラストは、スタイルではなく描画されたピクセルから測ります。各ビートを 4 通りに描きます。文字をそのままにしたもの、すべての文字を透明にしたもの、白で塗ったもの、黒で塗ったものです。白と黒の描画の差から、文字の色に関係なくグリフのある場所がわかり、その中の画素ごとに、文字の色と下にある色を比べます。グラデーション、背景画像、光の装飾、重なった要素、`opacity`、どの書き方の色も、描かれたとおりに測られます。

読むのは、グリフがいちばん濃く覆っている画素だけです。それぞれ、画素全体を覆ったときの色に戻してから比べるので、アンチエイリアスで比が下がることはなく、細いハイフンも本来の色で測れます。報告する比は、それらの画素のうち、悪い方から 2% を除いたすべてが達している値です。グラデーションの上の文字は、いちばん読みにくい部分で判定されます。`fg` と `bg` はその画素での 2 色です。2 つの文字が重なっている部分は、ほかに画素がない場合を除いて、どちらの判定にも使いません。`::before` と `::after` が描くものは背景として扱い、`DEK030` の対象にもなりません。

### DEK042

喋りになるのは段落だけです。リスト、コード、表しかないビートは、ナレーションでは `pause.beat` ミリ秒で通過します。空のビートと引用だけのビートは意図的な間として扱い、警告しません。
