# Lint ルール

lint がワークフローにどう組み込まれるかは [Lint](/ja/guide/lint) にあります。このページは ID、スコープ、条件の表です。

## スコープ

指摘はそれぞれ次の 3 つのどれかについてのもので、どのコマンドが報告するかもそこから決まります。

- **`slide`**: 1 枚のファイル、または `script.md` のそのセクション。指摘にはその枚の `slug` が入ります。`dek check <slug>` が報告するのはこれだけで、その枚の分だけです。
- **`deck`**: デッキの全スライドが共有するファイル。`theme.css`、フロントマター、`voice/voice.toml`、`script.md` 全体（長さ、最初のスライドより上の見出し）です。`slug` は入りません。
- **`project`**: `dek.toml`。コマンドが対象にするデッキがいくつあっても、プロジェクトで 1 回だけ見つかります。

`dek lint` は 3 つすべてを報告します。共有ファイルと各スライドのファイルの両方を読むルールはスコープを 2 つ持ちます。`theme.css` の `DEK014` はデッキの指摘、`slides/<id>.css` の `DEK014` はスライドの指摘です。`dek build` と `dek ls` が数えるのは `dek lint` と同じ指摘から rumdl を除いたものです。rumdl の Markdown スタイルのチェックは `dek lint` でだけ動きます。`dek ls` はプロジェクトの指摘を各デッキの行ではなく専用の `project` 行に出します。

## 条件

- `DEK030`、`DEK031`、`DEK032` は `--visual` のときだけ動き、Playwright が必要です。どちらも各ビートの終わり、つまりアニメーションとトランジションをすべて最後まで進めた姿を測ります。[静止画に写るもの](/ja/guide/steps#静止画に写るもの)を参照してください。
- `DEK040`、`DEK042`、`DEK043`、`DEK045` は `voice/` のあるデッキだけに適用されます。`DEK044` はすべてのデッキに適用されます。`dek cues` は `voice/` の有無に関わらず `DEK042` を報告します。
- `DEK041` は `duration` のあるデッキに適用されます。Timeline があればナレーションを測り（許容幅 20%）、なければ字数からの見積もりを使います（許容幅 35%）。`data` には `actualSeconds`、`budgetSeconds`、`source`（`timeline` か `estimate`）が入ります。
- `DEK008`、`DEK024` から `DEK026`、`DEK040` から `DEK045` は警告です。`"severity": "warning"` として報告し、lint を失敗させません。それ以外のルールはすべて error です。声のせいでライブ専用デッキが失敗することはありません。

## 補足

### DEK001 / DEK002

`DEK001` は `script.md` の該当する見出しを指し、`data.expected` に探した HTML のパスが入ります。`--fix` は先に sync します。骨格を作り、手付かずの骨格のままで横に何もない孤児は消し、手を入れたスライドには触れません。残った `DEK002` は、あなたの手が入ったファイルです。セクションのない HTML が 1 件、自分の HTML を持たないセクション（HTML がないか、生成された骨格のまま）が 1 件なら改名を疑い、両方の診断に `` run `dek mv <old> <new>` `` を hint として付けます。このコマンドは、`script.md` を先に書き換えていてもいなくても動きます。候補が 2 件以上あれば推測しません。

### DEK003

解決できない参照です。要素のないビートは問題なく、位置が連続している必要もありません。hint には、そのスライドで使える id と位置が並びます。

### DEK005

`data-morph` の名前は同じ枚の中で一意でなければなりません。`view-transition-name` になるので、ブラウザは遷移の両側にちょうど 1 つずつの要素を必要とします。別々の枚に同じ名前を付けるのが本来の使い方です。

使えない名前もあります。プレイヤーはスライドの枠に `slide`、ブラウザはページ全体に `root` という名前を付けているので、どちらかを付けるとページの切り替えそのものとぶつかります。`none`、`auto`、`match-element` は `view-transition-name` のキーワードなので、その要素は引き継がれません。

### DEK010

`theme.css` にそのクラスを定義すれば解消します。その枚でしか使わないなら `slides/<id>.css` に定義します。共有の語彙を増やすのは設計判断で、lint はそれを目に見える一手にします。`DEK013` がその一手の回数に上限を置きます。スライドのスタイルシートは数えません。hint には定義済みのクラスが並びます。定義済みのクラスの打ち間違い（2文字以内の違い）と見なせるときは、先頭に `did you mean slide-title?` が付き、`data.suggestion` にその名前が入ります。`slides/<id>.ts` から要素を探すためだけのクラスなら、代わりに `data-*` 属性を使ってください。

### DEK014 / DEK015

hint には、その値の代わりに使えるテーマのトークンが入ります。色なら色のトークン、`font-size` なら `--size-*` といった具合です。挙げるのは `.slide` に公開されたトークンだけです。テーマのもの、スライドのスタイルシートではそのファイル自身のものも含みます。1 つのレイアウトや 1 つの要素、`@media` の中でだけ設定したトークンは、すべてのルールには届かないからです。`theme.css` で合うものがなければ、`.slide` にトークンを足すよう案内します。スライドのスタイルシートでは、この枚のトークンにする書き方も案内します。`slides/<id>.css` の先頭に `.slide { --<name>: 260px; }` と書く形で、1 枚でしか使わない値をテーマに入れる必要はありません。

値は CSS が読むとおり、構成要素ごとに読みます。なので `-12px` は `12px` と同じ長さで、色名は色を取るプロパティでだけ色として数えます。`grid-area` の `tan` は領域の名前です。生の値を書けるのは、`.slide`、`.slide[data-layout="split"]` のような `.slide` の複合セレクタ、`::view-transition-*` 疑似要素の上での `--*` プロパティへの代入だけです。それ以外のルールで設定したカスタムプロパティは、生の値をルールの外へ運んでしまうので、hint は `.slide` へ移すよう案内します。単位なしの `0`、`thin`、`%`、`fr`、要素自身のフォントに従う単位（`em`、`ch`、`lh`、`ex`）は通ります。`ease-out` のようなイージングのキーワードも通ります。`cubic-bezier()`、`steps()`、`linear()` はトークンにする必要があり、hint はイージングを持つトークンを挙げます。生のフォールバック付き `var()` は通りません。契約の 13 トークンはすべて `.slide` に公開する必要があります。追加のトークンは歓迎します。

### DEK011

見つけた箇所ごとに一件ずつ、行と列つきで報告するので、一度の実行でインラインのスタイルとスクリプトがすべて並びます。`data` は見つけたものを表します。要素なら `{ "kind": "element", "name": "style" }`、属性なら `{ "kind": "attribute", "name": "onclick", "value": "go()" }` です。スライドは入力を受け取らないので、イベントハンドラには移し先がありません。動きは `slides/<id>.ts` に書きます。

### DEK016 / DEK017

`DEK016` はスクリプトが動かないこと、`DEK017` は動くものの `t` 以外に依存している、またはテーマが名前を変えうるクラスで要素を探していることを表します。どちらもスクリプトのファイルを指し、`DEK017` は行も示します。import のあるスクリプトも import を除いて評価するので、`motion` のキーは同じ実行の中で検査されます。

### DEK020 / DEK021 / DEK022 / DEK023

自己完結の規約です。リモートも、プロジェクト直下も、隣のデッキも参照できません。ローカルのファイルは `assets/` で始めます。シンボリックリンクはリンク先で判定します。`assets/` にあってもデッキの外を指すものは `DEK022` で、ビルドも開発サーバもそれを読みません。`dek build` が全アセットをインライン化でき、プロジェクト直下で立てた開発サーバがそれらを配信できるのは、この制約があるからです。

URL を持つ属性と、ページがその URL をどう扱うかは一つの表で決まります。リソースはスライドを描くために読み込まれるもので、`src`、`srcset` の各候補、`poster`、`<object>` の `data`、SVG の `<image>` と `<use>` の `href` です。リソースは存在し（`DEK021`）、`assets/...` と書く（`DEK023`）必要があります。リンクはたどられるだけのもので、`<a>`、`<area>`、`<link>` の `href` です。リンクもローカルかつデッキの中でなければなりません（`DEK020`、`DEK022`）。スライドを読む 2 つの場所、デッキと `slides/` のどちらから見てもです。なので `<a href="../other-deck/">` は `DEK022` です。`http:` と `https:` は、スラッシュがあってもなくてもリモートです。`file:` の URL は 1 台のマシンにしかないファイルを指し、どのデッキの外でもあります（`DEK022`）。スタイルシートでは、`image-set()` が文字列で取るアドレスも `url()` と同じく扱います。どの URL も、それぞれの行と列で報告します。

### DEK024

`dek sync` は section id をスライドに書きません。そのため id だけの `##` 見出し（`## architecture`）は、スケルトンの `<h2 class="slide-title">` が空になります。最初のスライドだけはデッキのタイトルが入ります。ファイルがまだそのスケルトンのままなら、hint は `script.md` で `## アーキテクチャ {#architecture}` のように見出しにタイトルを書き、`dek sync` を実行するよう示します。sync がスケルトンを書き直し、id とファイル名はそのままです。スライドを編集した後なら、hint は見出しのテキストを書くか、要素を消すよう示します。スライドのスクリプトが描画時に見出しを埋めることもあるので、警告です。

### DEK025

`data-step` の数字は「この枚の k 番目のビート」という意味なので、その上にビートを挿入すると、エラーもなく別のビートに紐付きます。その位置のビートに id があれば、id は同じものを指したまま動かないので、hint がその id を示します（`use data-step="turn"`）。lint が見られるのは今の台本だけです。挿入したあとなら、示される id はいまその位置にあるビートなので、狙ったビートかどうか確かめてください。id のないビートには位置以外の名前がないので、何も報告しません。安定させたいときは `{#id}` を付けてください。`data` には `step` と `id` が入ります。

### DEK026

3 枚がそれぞれ自分のスタイルシートに書いた宣言は、テーマに足りていない直しです。1 枚ずつ受け持つエージェントは、次の枚でも同じ直しをします。セレクタは、その枚のスコープが読むとおりに比べるので、`.card` と `.slide .card` は同じセレクタ、`.slide > .card` は別のセレクタです。`@media` の中のルールは、同じ `@media` の中の同じルールとだけ比べます。指摘は各枚の `dek check` に、セレクタごとに 1 件出ます。その枚がそこで共有している宣言と、そのどれかを共有しているすべての枚を挙げ、`data` には `selector`、`declarations`、`slides` が入ります。hint は、ルールを `theme.css` が持つべき形、つまり `.slide` の下に書いて示します（`.card` は `.slide .card` になり、テーマのスコープの規則 `DEK012` を通ります）。そのうえで、各枚から消すよう案内します。移すと、そのセレクタのクラスを使っていて自分では設定していない枚も変わります。hint はそうした枚を名指しし、`data.alsoReaches` にも並べます。3 枚が打ち消している既定値と、それに頼っている枚とを見比べて決められます。キーフレームは枚ごとに改名されて別物になるので、対象外です。

### DEK027

読めない台本に照らしてデッキのほかの部分は確かめられないので、読めるようになるまでは、これがそのデッキの診断のすべてです。問題は 1 回の実行ですべて、それぞれの行と直し方つきで報告します。フロントマターと見出しは別々に読み、読めない見出しもスライドを開くので、その下のビートまで報告されることはありません。`dek lint` は、デッキの中でもプロジェクトのルートでも、どこで実行しても報告し、開発サーバもすべて表示します。`dek build` のようにデッキがないと動けないコマンドは、同じメッセージと hint で最初の 1 件で止まります。

### DEK030

診断は、原因のある場所に向けます。原因はコントラストと同じやり方で探します。まずスライドスクリプトの `draw` の変更を戻し、次にその枚の CSS を外し、そのたびに測り直します。`draw` を戻すと収まる要素はスクリプトの問題で、パスは `slides/<id>.ts`、`data.origin` は `"script"` です。CSS を外すと収まる要素はそのスタイルシートの問題で、`slides/<id>.css`、`"slide"` です。どちらを外してもはみ出す要素は、内容そのものがスライドに対して多すぎます。`slides/<id>.html`、`"content"` で、hint はそのスライドの中で直す方法だけを示します。内容を削る、ビートやスライドに分ける、`slides/<id>.css` で大きさを調整する、のいずれかです。すべてのスライドに効くテーマのトークンの変更は勧めません。文字のない要素は、わざとはみ出す装飾かもしれないので、そうなら `aria-hidden="true"` を付けるよう hint が添えます。

メッセージには、要素、そのテキストの冒頭、越えた辺、何ピクセル越えたかが入ります。子は親が収まっている辺についてだけ報告されるので、下にはみ出したリストは 1 件です。複数のビートで同じ指摘は、ビートを並べた 1 件の診断になります。箱だけでなく文字列も測るので、URL のように折り返せない文字列は箱が収まっていても数えます。

#### 装飾

`aria-hidden="true"` を付けた要素は、中身と疑似要素も含めて装飾とみなし、`DEK030` も `DEK031` も測りません。スライドの外へわざとはみ出す光彩や、読めないほど薄い文字の見本を見せるスライドは、こう書きます。この印には、乱用を防ぐ代償があります。スクリーンリーダーが読み飛ばすので、聞き手に読んでほしい文字には付けません。

### DEK031

閾値は WCAG AA に従います。本文は 4.5:1、大きな文字は 3:1。大きな文字とは、計算後の `font-size` が 24px 以上、または 18.66px 以上で `font-weight` が 700 以上のものです。淡い色の大きな数字は通り、同じ色の本文は落ちます。閾値は変更できません。メッセージには要素、そのテキスト、前景色と背景色が入ります。

コントラストは、スタイルではなく描画されたピクセルから測ります。各ビートを 4 通りに描きます。文字をそのままにしたもの、すべての文字を透明にしたもの、白で塗ったもの、黒で塗ったものです。白と黒の描画の差から、文字の色に関係なくグリフのある場所がわかり、その中の画素ごとに、文字の色と下にある色を比べます。グラデーション、背景画像、光の装飾、重なった要素、`opacity`、どの書き方の色も、描かれたとおりに測られます。

読むのは、グリフがいちばん濃く覆っている画素だけです。それぞれ、画素全体を覆ったときの色に戻してから比べるので、アンチエイリアスで比が下がることはなく、細いハイフンも本来の色で測れます。報告する比は、それらの画素のうち、悪い方から 2% を除いたすべてが達している値です。グラデーションの上の文字は、いちばん読みにくい部分で判定されます。`fg` と `bg` はその画素での 2 色です。2 つの文字が重なっている部分は、ほかに画素がない場合を除いて、どちらの判定にも使いません。`counter()` から描くノンブルやランニングヘッドのように、`::before` や `::after` が描く文字も、ほかの文字と同じように測り、`section.slide::after` のように報告します。`content` に文字か数字があるか、`counter()`・`counters()`・`attr()` から作るときに文字とみなします。引用符や矢印だけのもの、光彩、罫線は背景として扱います。疑似要素は `DEK030` の対象になりません。

基準に届かない文字があると、ページを 1 層ずつ外しながら測り直し、下げた層に診断の `path` と hint を向けます。まず、スライドスクリプトの `draw` が属性に加えた変更、とくにインラインの色を元に戻します。それで基準を超えるなら原因は `draw` です。`draw` がインラインで付けた色はどのスタイルシートにも勝つので、直し先は `slides/<id>.ts` になり、`data.origin` は `"script"` です。次に、その枚の `slides/<id>.css` を外します。それで超えるなら直し先は `slides/<id>.css` のままで、`data.origin` は `"slide"` です。それでも届かなければ、テーマだけでそう描かれています。直し先は `theme.css` で、`data.origin` は `"theme"` です。そこで一度直せば、同じ組み合わせを使うすべての枚に届きます。スクリプトも自分の CSS も持たない枚は、色をすべてテーマに任せています。

### DEK032

スクリーンショット、サムネイル、PDF、`--visual` が測るページなど、静止画はどれも各スライドをビートの終わりの姿で描きます。そこで `draw` が例外を投げると、スライドは `draw` が走る前のままになります。画素を測っても、そういう見た目を意図したスライドと区別できないので、例外そのものを報告します。エラーと、それが起きるすべてのビートです。発表中の画面はスライドが何をしても止まりません。直す場所は `slides/<id>.ts` です。`data` には `message` と `steps` が入ります。

### DEK042

喋りになるのは段落だけです。リスト、コード、表しかないビートは、ナレーションでは `pause.beat` ミリ秒で通過します。空のビートと引用だけのビートは意図的な間として扱い、警告しません。
