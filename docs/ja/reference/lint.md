# Lint ルール

lint が制作フローにどう組み込まれるかは [Lint](/ja/guide/lint) を参照してください。このページでは各ルールの ID・スコープ・検出条件と詳細な仕様をまとめています。

## スコープ

各診断は次の 3 つのスコープのいずれかに属し、どのコマンドが報告するかもこれで決まります。

- **`slide`**：1 枚のスライドファイル、または `script.md` の該当セクション。診断に `slug` が入ります。`dekc check <slug>` が報告するのは基本的に対象スライドの診断だけです（例外として、[プラグイン](/ja/reference/plugins#プラグインが走らないとき)のどのスライドにも属さない error、つまりデータ読み込み失敗や `DEK046` 等も報告します）。
- **`deck`**：デッキ内の全スライドが共有するファイル（`theme.css`・frontmatter・`voice/voice.toml`・`script.md` 全体の尺や先頭より上の見出し）。`slug` は入りません。
- **`project`**：`dek.toml`。対象デッキがいくつあってもプロジェクト全体で 1 回だけ報告します。

`dekc lint` は 3 つすべてを報告します。共有ファイルとスライド専用ファイルの両方を検査するルールは 2 つのスコープを持ちます（例：`theme.css` の `DEK014` は `deck`、`slides/<id>.css` の `DEK014` は `slide`）。`dekc build` と `dekc ls` が数えるのは `dekc lint` から rumdl と[プラグイン](/ja/reference/plugins)を除いた dek 本体のルールだけです（rumdl は `dekc lint` 専用、プラグインは `dekc lint` と `dekc check` で動作）。`dekc ls` は `project` の指摘を各デッキ行には混ぜず、専用の `project` 行に表示します。

## 適用条件

- `DEK030`〜`DEK033`・`DEK035`・`DEK036` は `--visual` 指定時のみ実行され、Playwright が必要です。いずれも各ビートの完了状態（アニメーションとトランジションを最後まで進めた姿）を計測します（[静止画に写るもの](/ja/guide/steps#静止画に写るもの)を参照）。
- `DEK040`・`DEK042`・`DEK043`・`DEK045` は `voice/` を持つデッキにだけ適用されます。`DEK044` は全デッキが対象です。`dekc cues` は `voice/` の有無にかかわらず `DEK042` を報告します。
- `DEK041` は `duration` を持つデッキが対象です。Timeline があれば実尺（許容幅 20%）、なければ字数見積もり（許容幅 35%）で判定し、`data` に `actualSeconds`・`budgetSeconds`・`source`（`timeline` または `estimate`）を返します。
- `DEK008`・`DEK024`〜`DEK026`・`DEK028`・`DEK029`・`DEK035`・`DEK036`・`DEK040`〜`DEK045` は警告（`"severity": "warning"`）で、lint を失敗させません。それ以外はすべて `error` です。音声関連のルールでライブ専用デッキがエラーになることはありません。

## 補足

### DEK001 / DEK002

`DEK001` は `script.md` の該当見出し行を指し、`data.expected` に期待する HTML パスが入ります。`--fix` は先に `sync` を実行し、不足分の骨格を生成し、手付かずの骨格かつ横に関連ファイルがない孤児だけを削除します（手を入れたファイルには触れません）。残った `DEK002` は手書きのファイルです。

孤児 HTML が 1 件、かつ手書き HTML のないセクション（未作成または未編集の骨格）が 1 件だけある場合は改名と推定し、双方の診断に `` run `dekc mv <old> <new>` `` の hint を付けます（`script.md` とファイルのどちらを先に変えていても動作します）。候補セクションが 2 件以上ある場合は削除を勧めず、孤児の hint に候補ごとの `dekc mv` を台本順で並べます（候補が 1 件以上あれば孤児の `data.renames` に候補一覧が入ります）。

### DEK003

存在しないビートを参照している `data-step` です。HTML 要素の紐づかないビート自体は正常であり、番号が連番である必要もありません。hint にはそのスライドで有効なビート id と位置番号が一覧表示されます。

### DEK005

`data-morph` の名前は同じスライド内で一意である必要があります。ランタイムが `view-transition-name` へ変換するため、遷移元と遷移先のそれぞれに要素が 1 つずつ対応している必要があります（異なるスライドに同じ名前を付けるのが本来の使い方です）。

プレイヤーがスライド領域に `slide`、ブラウザがページ全体に `root` を使用しているため、これらは予約名として禁止しています。また `none`・`auto`・`match-element` は `view-transition-name` の CSS キーワードであり、モーフ対象として機能しないためエラーになります。

### DEK010

`theme.css` にクラスを定義するか、1 枚限定なら `slides/<id>.css` に定義して解消します。共有クラスを増やすのは設計判断であり、lint はその判断を可視化します（総数は `DEK013` で制限し、スライド専用 CSS は数えません）。hint には定義済みクラス一覧が入り、2 文字以内の打ち間違い候補があれば先頭に `did you mean slide-title?` を添えて `data.suggestion` に返します。`slides/<id>.ts` から要素を探す目印としてクラスを付けた場合は、代わりに `data-*` 属性を使ってください。

`is-current` と `is-shown` はテーマのクラスではなくプレイヤーが動的に付け外しする状態クラスです。HTML に直書きするとプレイヤーの制御より先に状態を固定してしまうため、`data.state: true` 付きで `DEK010` になり、削除を案内します。CSS 側で `.slide.is-current [data-step].is-shown` のようにセレクタとして参照してください（`dekc theme` でも通常のクラスとは分けて表示されます）。

### DEK014 / DEK015

hint には生の値の代わりになるテーマトークン（色なら色トークン、`font-size` なら `--size-*` など）を提示します。候補に挙げるのは `.slide` に公開されているトークン（スライド専用 CSS ではそのファイル自身の `.slide` を含む）だけで、特定レイアウトや `@media` 内に閉じたトークンは全ルールから参照できないため除外します。合うトークンがない場合、`theme.css` では `.slide` への追加を、スライド専用 CSS では先頭に `.slide { --<name>: 260px; }` のようにそのスライド専用トークンを定義する書き方を案内します。

値は CSS パーサーと同様にトークン単位で解析するため、`-12px` も `12px` と同じ長さとして扱い、色名は色を取るプロパティだけで色と判定します（`grid-area: tan` は色ではありません）。生の値を書けるのは、`.slide`・`.slide[data-layout="split"]` などの複合セレクタ・`::view-transition-*` 疑似要素上での `--*` 代入だけです。それ以外のルール内でカスタムプロパティへ生の値を入れると、hint は `.slide` へ移すよう案内します。ただし `.chance { --seal-box: 120px }` のように既存トークンを部品単位で上書きしている場合は、そのまま `.slide` へ移すと上書きが失われるため、`.slide` に `--seal-box-chance: 120px` を置いて部品側で `--seal-box: var(--seal-box-chance)` と受ける形を案内します（`data.token` にトークン名が入ります）。

単位なしの `0`、`thin`、`%`、`fr`、要素自身のフォント基準の単位（`em`・`ch`・`lh`・`ex`）、`ease-out` などのイージングキーワードは生の値とみなさず通ります。`cubic-bezier()`・`steps()`・`linear()` はトークン化が必要で、生のフォールバック付き `var()` は不可です。必須の 13 トークンはすべて `.slide` に公開してください（追加トークンは自由です）。

### DEK011

該当するインラインスタイルやスクリプトを行・列つきですべて一括報告します。`data` には要素なら `{ "kind": "element", "name": "style" }`、属性なら `{ "kind": "attribute", "name": "onclick", "value": "go()" }` が入ります。スライドはユーザー入力を受け付けないためイベントハンドラの移し先はなく、時間ベースのアニメーションは `slides/<id>.ts` へ書きます。属性値や URL はブラウザのパーサーと同じく文字参照を展開し、前後の制御文字・空白や途中のタブ・改行を無視して判定するため、`&#106;avascript:` や `java&#x09;script:` なども `javascript:` として検出します（`data` には展開後の値が入ります）。

### DEK016 / DEK017

`DEK016` はスクリプトが実行できない構文・構造エラー、`DEK017` は実行できても `t` 以外に依存しているかクラスで要素検索している問題を表します（`DEK017` は行番号つき）。`import` を含むスクリプトでも `import` 行を除いた形で評価を続行するため、`motion` キーの誤りも 1 回の実行で同時に報告されます。

### DEK020 / DEK021 / DEK022 / DEK023

デッキの自己完結性を守るルール群です。リモート URL、プロジェクト直下、隣のデッキはいずれも参照できず、ローカルファイルは `assets/` 配下に限ります。シンボリックリンクは解決先で判定するため、`assets/` 内からデッキ外を指すリンクは `DEK022` になり、ビルドも開発サーバーも読み込みません。この制約により、`dekc build` が全アセットを安全にインライン化できます。

URL を取る属性は役割ごとに 2 種類へ分かれます。スライド描画のために読み込むリソース（`src`、`srcset` の各候補、`poster`、`<object data>`、SVG の `<image>`・`<use>` の `href`）は実在（`DEK021`）かつ `assets/...` 形式（`DEK023`）である必要があります。一方、遷移用のリンク（`<a>`・`<area>`・`<link>` の `href`）もローカルかつデッキ内に収める必要があります（`DEK020`・`DEK022`）。デッキルートと `slides/` のどちらから解決しても外に出ないことを確認するため、`<a href="../other-deck/">` は `DEK022` です。`http:`・`https:` はスラッシュの有無を問わずリモート扱い、`file:` は端末依存のためデッキ外（`DEK022`）扱いです。CSS の `image-set()` の文字列アドレスも `url()` と同様に検査し、HTML 属性の文字参照も展開して判定します（`assets/Q&amp;A.png` → `assets/Q&A.png`）。

### DEK024

`dekc sync` はセクション id をそのまま見出し文言には入れないため、id だけの `## architecture` からは空の `<h2 class="slide-title">` が生成されます（先頭スライドだけはデッキの `title` が入ります）。まだ未編集の骨格であれば、hint は `script.md` に `## アーキテクチャ {#architecture}` のように文言を足して `dekc sync` する手順と、引用スライドのように見出し不要なら `<h2>` 要素自体を消す手順の 2 通りを示します。手書きスライドの場合は見出し文言の記入か要素の削除を案内します。スライドスクリプトが描画時に見出しを埋めるケースもあるため警告扱いです。

### DEK025

数値の `data-step` は「そのスライドの k 番目のビート」を意味するため、手前にビートを挿入するとエラーにならないまま別のビートへずれてしまいます。対象位置のビートに id がある場合は、ずれない id 指定（例：`use data-step="turn"`）を hint で案内します。ただし lint が見られるのは現在の台本だけなので、すでに挿入した後であれば意図したビートと一致しているか確認してください。id のないビートには位置以外の指定方法がないため報告しません（安定させたいときは `{#id}` を付けてください）。`data` には `step` と `id` が入ります。

### DEK026

3 枚以上のスライド専用 CSS に同じ宣言が繰り返し書かれている場合、テーマ側へ昇格させるべきスタイルが漏れている合図です（1 枚ずつ作業するエージェントが同じ修正を繰り返すのを防ぎます）。セレクタはスコープ展開後の形で比較するため、`.card` と `.slide .card` は同一、`.slide > .card` は別セレクタとして扱います（`@media` 内は同じ `@media` どうしでのみ比較）。

指摘は各スライドの `dekc check` でセレクタごとに 1 件ずつ出て、`data` に `selector`・`declarations`・`slides` が入ります。hint には `theme.css` へ移す際の `.slide` 配下の形（`DEK012` を満たす形）と、各スライド CSS からの削除手順を示します。テーマへ移すと自前で上書きしていない他スライドにも波及するため、影響を受けるスライドがあれば hint と `data.alsoReaches` に列挙します。また、テーマに未定義のクラスを含み移動すると `max_classes` を超える場合は、`max_classes` の引き上げ行か各スライドに残す選択肢を示し（`data` に `themeClasses`・`limit`）、hint に従った結果 `DEK013` エラーを踏む事態を避けます（ただし未定義クラスを足す別々の指摘 2 件に両方従うと合計で上限を超えることはあり、その場合は `DEK013` が整理候補を示します）。`@keyframes` はスライドごとにリネームされるため対象外です。

### DEK027

`script.md` 自体がパースできないとデッキ全体の整合性を検証できないため、解消されるまでこの診断だけを報告します。frontmatter と見出しは独立して解析し、1 回の実行で全箇所を行番号と修正案つきで報告します（不正な見出しもセクション開始として扱うため、その配下のビートまで連鎖エラーにはなりません）。`dekc build` などデッキ構造が必須のコマンドは最初の 1 件で停止します。

### DEK028

モーフは直前または直後のスライドにある同名要素との間でのみ発生します（2 枚以上離れたスライドどうしは同時に画面へ出ません）。前後どちらにもない名前は通常のフェードになり、打ち間違いと区別がつかないため警告します。前後のスライドに 1〜2 文字違いで未使用の候補名があれば `did you mean "p-99", as in slides/b.html?` のように提案し、なければ相手を置くべき前後ファイルか属性削除を案内します。予約名は `DEK005` で扱います。`data` には `morph` と前後スライドの slug 配列 `neighbors` が入ります。

### DEK030

原因の切り分けはコントラスト（`DEK031`）と同じ手順で進めます。まずスライドスクリプトの `draw` による変更を戻して再計測し、それで収まれば `slides/<id>.ts`（`data.origin: "script"`）、次にスライド専用 CSS を外して収まれば `slides/<id>.css`（`data.origin: "slide"`）へ指摘を向けます。どちらを外してもはみ出す場合は内容過多として `slides/<id>.html`（`data.origin: "content"`）を指し、そのスライド内で完結する対処（文章削減、ビート・スライド分割、`slides/<id>.css` でのサイズ調整）だけを案内します（全スライドへ影響するテーマトークンの変更は勧めません）。テキストのない要素は意図的にはみ出させた装飾の可能性もあるため、`aria-hidden="true"` を付ける選択肢も案内します。

メッセージには要素・テキスト冒頭・越えた辺・超過ピクセル数が入ります。親が収まっている辺についてだけ子要素を報告するため、下へはみ出したリストはリスト 1 件にまとまります。複数ビートの同一指摘も 1 件へ集約します。URL のような折り返せない文字列は、親ボックスが収まっていてもはみ出しとして検出します。

基準はスライドの論理サイズです。CSS で高さを伸ばしたり拡大したりしても、プレイヤーが表示するのは論理サイズの範囲内だけです。スライド内の祖先要素（`overflow: hidden` 等）によって文字が切れている場合も、`p.note "…" is cut off by div.card past its bottom edge by 40px` のように切った祖先（`data.clip`）つきで報告します。省略記号や行数制限（`text-overflow: ellipsis`・`-webkit-line-clamp` 等）は意図的な切り詰めとして許容します。

#### 装飾

`aria-hidden="true"` を付けた要素（中身と疑似要素を含む）は装飾とみなし、`DEK030` も `DEK031` も計測しません。スライド端からはみ出す光彩や、わざと読みにくくした見本テキストなどに使います。スクリーンリーダーにも読み飛ばされるため、聴衆に伝えたい情報へ安易に付けることへの歯止めになっています。

### DEK031

基準は WCAG AA（本文 4.5:1、大きな文字 3:1）で固定です。大きな文字とは計算後の `font-size` が 24px 以上、または 18.66px 以上かつ `font-weight` 700 以上を指します。

コントラストは CSS プロパティの推測ではなく、実際に描画されたピクセルから測ります。各ビートを 4 通り（通常・文字透明・白文字・黒文字）でレンダリングし、白と黒の差分からグリフの画素位置を特定したうえで、各画素の前景色と背景色を比較します。そのためグラデーション、背景画像、光彩、重なり、`opacity`、ブレンドモードのいずれを使っていても聴衆の目に映るとおりに測れます。

`text-shadow` は視認性を高める用途のみを評価し、影のせいでコントラスト比を下げることはしません（影あり・影なしの双方を比較し、各画素でより読みやすい側を採用します）。`mix-blend-mode` で下の色と混ざった文字は混色後の見た目で判定します。

計測対象はグリフが最も濃く覆う画素に絞り、背景色との合成を逆算して本来の文字色を復元するため、アンチエイリアスや細いハイフンで不当に低い値が出ることはありません。報告されるコントラスト比は、対象画素のうちワースト 2% を除いたすべてが満たす値です（グラデーション上の文字は最も読みにくい箇所で判定）。2 つの文字が重なっている領域は、他に有効画素がない場合を除き判定から外します。`counter()` 等で描画される `::before` / `::after` の文字（引用符や矢印・罫線のみの飾りは除外）や SVG の `<text>` も同様に計測します（疑似要素は `DEK030` の対象外）。

基準未満の文字が見つかると、層を 1 つずつ外しながら再計測して原因箇所を特定します。`draw` の変更を戻して改善すれば `slides/<id>.ts`（`"script"`）、`slides/<id>.css` を外して改善すれば `slides/<id>.css`（`"slide"`）、それでも基準未満ならテーマ自体の配色問題として `theme.css`（`"theme"`）を指摘します。スライド CSS を外すと要素自体が画面外へ消えて測れない場合は、`data.origin` を付けず `slides/<id>.css` と `theme.css` の両方を案内します。

### DEK032

静止画（スクリーンショット・サムネイル・PDF・`--visual`）を描画する際に `draw` 関数の健全性も検証します。ピクセルだけを見ても意図したデザインかバグか区別できないため、発生した異常種別を全該当ビートとあわせて `data.kind` で報告します。

- `throw`：`draw` が例外を投げた（スライドは `draw` 実行前の状態のままになる）。
- `reach`：スライド外の DOM を書き換えた（単一スライドのページでは見逃すため、`--visual` ではビルド済みと同じ全スライド一括ページでも描画して検出する）。
- `seek`：ビート開始時点を描いてから終了時点を描いた結果が、終了時点を直接描いた結果と一致しない（呼び出しをまたぐ状態を持っており、動画・静止画・シークで再現できない）。

本番再生中に例外で画面全体が止まることはありません。修正箇所は `slides/<id>.ts` で、`data` に `kind`・`message`・`steps` が入ります。

### DEK033

2 つの文字行が縦横とも数ピクセル以上、かつ小さいほうの 1/5 以上重なっていると読めない重なりとして報告します（1 文を複数要素へ分けた隣接行は対象外）。`::before` / `::after` のノンブルやランニングヘッドも対象で、レイアウト上のボックスではなく実際のグリフ領域で判定します。

ボックスが重なった候補どうしはそれぞれ単独描画して可視ピクセルを確認します。下の文字が 1 画素も見えず、上の文字がほぼ同じ領域を置き換えている場合（同じ枠内で数字を塗りつぶしてカウントアップする演出など）は意図的な差し替えとして許容します。一方、ラベルの上に吹き出しが被って文字が隠れたり一部が欠けたりしている場合は重なりとして報告します。`data` には `box`・`other`・各テキスト・`steps` が入ります。

### DEK034

画像や図は「スクリーンリーダーが読み上げる意味のあるコンテンツ」か「装飾」かのどちらかを明示する必要があります。lint は言葉の妥当性までは判定せず、どちらかが宣言されていることだけを検証します。設定した代替テキストはビルド済み HTML でスクリーンリーダーへ渡され、`dekc pptx` でも各画像や背景画像の代替テキストになります。

- `<img>` には `alt`（装飾なら `alt=""`）、または `aria-label`・`aria-labelledby`・`title` を付けます。
- `<svg>` は中に `<text>` や `<title>` があればそのまま通過します。テキストを含まない SVG には `role="img"` と `aria-label`、装飾なら `aria-hidden="true"` を付けます（`aria-hidden` を案内するのは文字のない SVG だけなので `DEK029` とは衝突しません）。
- `role="img"` を付けた要素（SVG 含む）は内部テキストが読み上げられなくなるため、`aria-label`・`aria-labelledby`・`<title>` のいずれかが必須です（中に文字がある場合は `role="img"` を外す選択肢も提示します）。
- `aria-hidden="true"` 配下、および `role="presentation"` / `role="none"` の要素は装飾として通過します。ネストされた SVG は外側の図の一部とみなします。

`<video>`・`<iframe>`・`<object>` は検査対象外です（動画の代替は字幕であり属性では検証できないため）。`data` には `tag`、および該当すれば `src` や `role` が入ります。

### DEK035

2 行以上に折り返す可視テキストを対象に、読みにくい改行を検出します（`<strong>` や `<a>` 等のインライン要素も含めて 1 つの行として計測。`<pre>`・`<code>`・`<kbd>`・`<samp>`・SVG・MathML・`aria-hidden` 配下は除外）。検出種別は `data.kind` で区別します。

- `split`：日本語の行が文節の途中で切れている。`word-break: auto-phrase` だけを当てた比較描画と行頭位置を比べ、差異があれば報告します（`lang` が `ja` などの文節言語のみ対象。英語は報告しません）。すでに `word-break` が `normal` 以外になっている要素や、1 行に収まらない長い文節は比較結果が同じになるため報告しません。同梱テーマのように `.slide` へ `auto-phrase` が入っていれば `split` は出ず、残る微調整はスクリーンショットで確認します。`.slide` に指定がない場合は 1 行で全スライドを直せる `theme.css` へ、個別ルールで打ち消している場合は該当スライドへ指摘を向けます。`data.phrased` に文節折り返し後の行一覧が入ります。
- `short`：段落の最終行が「す。」や `AI` のように 2 文字以下しか残っていない（英数字と文字をカウント。`inline-block` チップ等は中の文字数を合算）。`<br>` やブロック区切り、`white-space` による明示改行は対象外です。`text-wrap` が `pretty` でも `balance` でもない場合はその指定を、すでに指定済みなら文言調整を hint で案内します。`data.tail` に最終行が入ります。

`split` がある要素では文節折り返し後に後続行がすべて動くため、`split` だけを報告します。改行の最適解は文言変更か改行位置の選択であり作者にしか決められないため、警告扱いです。`data` には `kind`・`box`・`text`・`lines`・`phrased`（または `tail`）・`steps` が入ります。

### DEK036

数ピクセルだけずれた端は意図ではなく崩れに見え、HTML 上では気づきにくい問題です。同じ親要素内にあるボックスどうしを対象に、横並び（上端・中央・下端）と縦積み（左端・中央・右端）の揃えを検査します。インラインボックス、`aria-hidden` の装飾、未表示ビート、`transform` で回転・傾斜した要素、SVG 図形部品は除外します。要素の下に横一列に並ぶ群や横に縦積みされた群は、そのまとまり単位で比較します。

端の差が 0.5px 未満なら一致、1.5px 未満なら視覚的に揃っているとみなし、**2〜8px** の差を「揃え損ね」、それ以上を意図的なオフセットとして扱います。いずれか 1 辺でも共有していれば揃っているとみなし（広いリストの上の見出しは左端、行横のアイコンは中央など）、横並びの文字どうしがベースラインを共有している場合も許容します（双方が視認できる塗り・枠付きボックスの場合を除く）。報告するのは次の 4 パターンです。

- どの端も共有しておらず、最も近い端が 2〜8px ずれている 2 要素。
- 横並びで文字を持ち、下端は揃っているのに上端がわずかにずれている要素（文字のない棒グラフの棒は除外）。
- 同種の塗りボックスが横並び（カード列など）で、上端は揃っているのに下端がわずかにずれている要素（縦積みは内容幅に依存するため幅差は不問）。
- 同種カードが同じ開始線から並んでいるのに、1 行目の文字の開始位置がわずかにずれている（padding 不一致等。`data.of: "text"`。中央揃えテキストは中央基準で揃っているとみなす）。

ずれている 2 要素のうち、他の要素と揃っている数が少ない側（同数なら後ろ側）を原因要素として 1 辺につき 1 回報告します。`data` には `box`・`other`・各テキスト・`edge`（`top`/`middle`/`bottom`/`left`/`center`/`right`）・`of`（`"box"`/`"text"`）・`by`（最大ずれ px）・`steps` が入ります。わずかなずれを意図的な表現に使うケースもありうるため警告扱いです。

### DEK042

読み上げ対象になるのは段落だけです。リスト・コード・表だけを含むビートはナレーション時に `pause.beat` ミリ秒で通過してしまいます。空のビートや引用（ト書き）だけのビートは意図的な間として扱い、警告しません。

### DEK046

プラグイン固有の診断は `STUDY001` のようにプラグイン自身のルール ID とマニフェストの重要度で報告されます（[プラグイン](/ja/reference/plugins)を参照）。`DEK046` はデッキの不備ではなくプラグイン側の実行失敗を表し、メッセージにプラグイン名とロック済みバージョン、`path` に `dek.toml`、`data` に `plugin` と `version` が入ります。未インストール・未ロック・ロック不一致・dek バージョン不足によって実行されなかったケースは `DEK046` ではなく `skipped` として報告されます。
