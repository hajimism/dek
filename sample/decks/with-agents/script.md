## スライドをエージェントに任せる {#cover}

今日は、AI エージェントにスライド作りを任せる話をします。コードを
書かせるのはもう当たり前になりました。でも、スライドを任せると
なぜかうまくいきません。その理由と dek での解き方を、六分で話します。

## エージェントがスライドでつまずく三つの理由 {#why}

### 画面が見えない {#why-blind}

ひとつめ。エージェントには自分が書いた画面が見えません。HTML と
しては正しくても、描画すると文字が枠からはみ出している。書いた本人には
それに気づけません。

### ファイルが大きすぎる {#why-big}

ふたつめ。資料全体がひとつの大きなファイルになっていることです。
一枚を直したいだけなのに何千行も読むことになり、関係ないところまで
崩してしまいます。

### 終わりがわからない {#why-done}

みっつめ。どこまでやれば完成なのかが決まっていません。いい感じに、
と頼まれても、エージェントには止めどきがわかりません。

## dek の答えは三つの約束 {#answer}

dek はこの三つに、三つの約束で応えます。画面は描画して数字で返す。
一枚は小さなファイルに分ける。止めどきは lint が決める。順に見て
いきます。

## 画面は数字で返す {#measure}

### 描画して測る {#measure-render}

dek はスライドを実際にブラウザで描画して測ります。

### 返ってくる診断 {#measure-json}

はみ出していれば、どの要素がどの辺から何ピクセル出たかを決まった形の
JSON で返します。スクリーンショットを見せて収まっていますかと聞くより、
ずっと確実です。

## 一枚は小さなファイル {#small}

スライドは一枚ずつ HTML ファイルに分かれています。長くても百行
ほどです。

### 必要なぶんだけ読む {#small-show}

dekc show を使うと、その一枚に関わる台本、HTML、CSS、それにテーマの
中で実際に使われている規則だけをまとめて受け取れます。テーマ全体を
読む必要はありません。

## 止めどきは lint が決める {#done}

使ってよいクラス、色の指定のしかた、画像の置き場所。dek の規約は
すべて lint のルールになっています。エラーがひとつもなければ、測れる
問題は残っていません。最後に全部のスライドを一枚の画像に並べて、
全体の釣り合いを見ます。エージェントはそこで止まり、自分では判断
できなかったことを人に渡します。

## 一往復で、書いて、見て、直す {#loop}

三つの約束がそろうと、作業はひとつのループになります。

### 書く {#loop-write}

エージェントが一枚の HTML を書きます。

### 確かめる {#loop-check}

dekc check を実行すると、その一枚の診断が返ってきます。
スクリーンショットを頼めば、その保存先も返ってきます。

### 直す {#loop-fix}

診断には直し方の手がかりが付いているので、エージェントはそれを読んで
直し、もう一度確かめます。エラーがなくなるまで人の手はいりません。

## 失敗しても次の一手を返す {#hints}

エラーの返し方も工夫しています。失敗したときは、何が起きたかと一緒に
次に実行すべきコマンドを返します。確かめられなかった検査は成功扱いに
せず、飛ばしたと明記します。エージェントが飛ばした検査を合格と取り
違えることはありません。

## 指さしは両方向 {#point}

人とエージェントは同じ画面を指させます。人がこのスライドの図を小さく
してと言えば、エージェントは dekc current でいま映っているスライドを
特定します。直し終えたら dekc goto で、人のブラウザをその一枚に
移します。

## 矢印一本まで指して頼む {#annotate}

細かい工程表では、このスライドの、だけではどの矢印のことか伝わり
ません。

### 指して、書く {#annotate-pick}

開発サーバーで a を押し、矢印をクリックして、その場で修正メモを書き
ます。

### 貼って、渡す {#annotate-paste}

コピーして貼れば、書かれたファイルと行、その場面を撮るコマンドまで
渡ります。エージェントが該当箇所を探す必要はありません。

## お手本はよその発表から {#refs}

エージェントは説明書より実例から学ぶほうが得意です。dekc ref を
使うと、公開されている dek のデッキを、コミットを固定して手元に取って
こられます。

あの発表の尺のグラフみたいに作ってと頼めば、エージェントはその一枚を
読み、自分のテーマで書き直します。取ってきたデッキは読み取り専用
なので、自分のデッキがよそに依存することはありません。

## 準備は何もいらない {#setup}

エージェント側の準備は何もいりません。専用のサーバーも、ツールの
定義も不要です。dekc init が作る短い AGENTS.md と dekc help を
読めば、どのエージェントでもすぐに作業を始められます。

## 任せる前に決めること {#close}

エージェントに任せる前に決めることはひとつだけです。何を話すか。
台本さえ書けば、画面はエージェントと一緒に仕上げられます。ありがとう
ございました。
