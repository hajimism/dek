## うまい発表は、借りていい。 {#cover}

dek に足したい新しい機能、dek ref の話を六分でさせてください。
ひとことで言うと、公開されている発表を手元に取ってきて、自分の
資料作りの参考にできるようにする機能です。

> 明るく、テンポよく。タイトルが出そろうまで待つ。

## いい発表は、見られても使えない {#problem}

### うまい発表に出会う {#meet}

勉強会で、うまい発表に出会ったとします。あの構成を真似したい。
あのグラフの動きを使いたい。ところが手に入るのは、たいてい
PDF か画像です。

### 見た目しか残らない {#flat}

共有されるのは画面の絵だけです。マークアップも、動きも残って
いません。

### 尺が残らない {#pace}

何を、どの順で、何分かけて話したのか。いちばん知りたいことが、
どこにも書かれていません。

### エージェントも読めない {#blind}

絵しか無ければ、エージェントに「これみたいに作って」と頼んでも
手がかりがありません。

## dek のデッキは、発表そのもの {#insight}

dek のデッキは事情が違います。台本も、尺も、スライドの HTML も、
動きのスクリプトも、ぜんぶテキストで一つのディレクトリに入って
います。

### 四つがそろっている {#layers}

共有できるのはスライドの束ではありません。何をどう話したかまで
含めた、発表そのものです。

## コマンドひとつで、手元に {#product}

### 取ってくる {#fetch}

そこで dek ref です。GitHub にある dek のプロジェクトを、
オーナー、リポジトリ、デッキの順に書くだけで、手元の refs
ディレクトリに取ってきます。

### 版を固定する {#pin}

取ってきた版は dek.toml に記録します。相手があとで更新しても、
こちらの参考資料が勝手に変わることはありません。

## 覚えるコマンドは増えない {#readonly}

### 読み取り専用のデッキ {#lock}

取ってきた ref は、読み取り専用のデッキとして扱います。
デッキ名を受け取るコマンドなら、どれにでも渡せます。

### 構成と尺を見る {#ls}

dek ls に渡せば、十二分をどう配分したかがわかります。

### 台本とマークアップを読む {#show}

dek show に渡せば、その節で何を話し、どう組んだかが出てきます。

### 描画して確かめる {#shot}

dek shot に渡せば、描画した画像が手に入ります。

## 気に入った一枚を、自分のデッキへ {#take}

### 台本にある節へ {#target}

気に入ったスライドがあれば、dek take で自分のデッキに移せます。
移せるのは、自分の台本にある節だけです。台本が親という原則は、
ここでも変わりません。

### テーマの差を埋める {#classes}

自分のテーマに無いクラスは、そのスライド専用の CSS に抜き出します。

### ビートを付け替える {#beats}

ビートの id は、自分の節のビートに順番で割り当て直します。

### 出どころを残す {#credit}

どこから借りたかは、クレジットとして記録に残ります。

## 借りたスライドが、自分の色になる {#reskin}

### 同じ名前のトークン {#tokens}

ここがいちばん気持ちいいところです。dek のテーマはどれも、色や
文字の大きさを同じ名前のトークンで出しています。

### 移すだけで馴染む {#after}

だから移したスライドは、何もしなくても自分のテーマの色と文字で
描かれます。借りてきた感じが残りません。

## エージェントにとっては、実例集 {#agents}

### 説明書より実例 {#examples}

この機能がいちばん効くのは、エージェントと作るときです。
エージェントは説明書より、実例から学ぶほうがずっと得意です。

### 読む、見る、移す、直す {#loop}

「あの timing みたいに作って」と頼めば、台本とマークアップを
読み、画像で確かめ、自分のデッキに移し、直すところまで一人で
進められます。

## サーバーは作らない {#how}

仕組みは小さく保ちます。置き場も、認証も、版の管理も GitHub に
任せて、中央のサーバーは作りません。取ってきた本体は refs に置き、
どの版かだけを dek.toml に書きます。refs が消えても、dek sync で
元に戻ります。

## 他人のものを、安心して {#trust}

他人の発表を扱う以上、安心して使えることも大事です。版は固定し、
ref のスクリプトはネットワークに触れられない場所で描画し、
ライセンスが無いものには警告を出します。

## 三段階で届ける {#roadmap}

進め方は三段階です。

### 見る {#see}

まずは、取ってきて見るところまで。

### 借りる {#borrow}

次に、一枚ずつ借りる dek take。

### 見つける {#find}

最後に、発表の最後に映っていた URL から直接取ってこられるように
して、探す仕組みを整えます。

## 決めたいことが、三つ {#ask}

最後に、決めたいことが三つあります。取ってきた ref を git に
入れるかどうか。移すコマンドの名前。そして、ビルドした HTML に
台本を含めてよいか。ここは一緒に決めさせてください。

## 次のいい発表の、素材になる {#close}

いい発表は、次のいい発表の素材になります。dek ref で、それを
借りられるようにしましょう。ありがとうございました。

> 最後のコマンドを映したまま、質問を受ける。
