Ⅱ　仕組み

エージェントは、画面を見られない

HTML としては完璧でも、描画すると枠からはみ出していることがある。書いた本人には見えない。
dek はスライドをブラウザで描画して測り、どこが何ピクセル出たかを、直し方と一緒に返す。

1エージェントが読むもの

slides/features.html<section class="slide">
  <h2 class="slide-title">開発体験を支える、
    5 つの仕組みと、それぞれの…</h2>
  <ul>
    <li>台本から骨格を生成する</li>
    <li>ビートで画面を進める</li>
    … li があと 8 行
  </ul>
</section>

タグは閉じていて、クラスも正しい。テキストとして読む限り、問題は見つからない。

2描画すると

下端を 28px はみ出し

最後の 1 行が下端で切れている。本番の 30 分前に、人が見て気づくことが多い。

3dek lint --visual --json が返すもの

{
  "id": "DEK030",
  "severity": "error",
  "path": "slides/features.html",
  "hint": "cut it, split it across beats or slides, or give it a smaller size in slides/features.css",
  "data": {
    "box": "ul",
    "edges": { "bottom": 28 },
    "steps": ["1"]
  }
}

どの要素が、どの辺から、何ピクセル。エージェントはこれを読んで直し、もう一度測る。
