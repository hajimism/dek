## 喋る順に、スライドを組み立てる {#cover}

こんにちは。今日は dek という、台本からスライドを組み立てるツールの話を
します。

話は三つに分かれます。いまのスライド作りのどこで困っているか。dek が
それをどういう仕組みで解くか。そして、どう使い続けるか。

この資料は、あとから読み返しても話の筋を追えるように作っています。
聞き逃したところは、手元の資料で補ってください。

> 落ち着いて始める。目次は読み上げない。

## 前日の夜に、尺が合わないと気づく {#night-before}

発表の前日の夜を思い出してください。スライドは三十枚そろっていて、
見た目も悪くない。ところが通しで喋ってみると、二十分の枠で三十分
かかる。そこから削り始めると、削りやすいところから消えていきます。
たいていそれは、いちばん言いたかった部分の説明です。

### 箱から作る {#box-first}

いまの道具は、まず空の箱を出してきます。テンプレートを選び、箱を並べ、
中身を埋める。喋ってみるのは最後です。尺が合うかどうかは、前日の夜まで
わかりません。

### 台本から作る {#script-first}

dek は順番を逆にします。先に喋ることを書き、その場で尺を見積もり、
画面はそのあとに決める。喋り切れるかどうかは、書き始めた日にわかります。

> 聴衆がうなずくまで待つ。

## 台本が親で、スライドは子 {#parent}

dek の中心にあるのは、この親子関係です。script.md がひとつあって、
見出しがひとつ増えるたびに、スライドのファイルがひとつ増えます。

左は、いまご覧の資料そのものの台本です。右は、そこから生まれた
スライドのファイルです。順番を持っているのは台本だけで、ファイル名に
番号は付きません。並べ替えたいときは、台本の見出しを入れ替えるだけです。

## script.md の書き方 {#anatomy}

台本は普通の Markdown で、覚えることは多くありません。

### 見出しがスライドとビート {#headings}

シャープ二つの見出しがスライド一枚、三つの見出しがその中のビートです。
ビートは喋りの区切りで、画面を一段進めるきっかけにもなります。見出しの
文章は自由に書けて、ファイル名には波かっこの中の id を使います。

### 段落が喋り、引用はト書き {#paragraphs}

段落が、実際に喋る言葉です。尺の見積もりにも、音声合成にも使われます。
引用は自分へのメモで、尺にも声にも入りません。先頭の duration が、
トーク全体の持ち時間です。

## 保存すると、骨格ができる {#skeleton}

台本を保存すると、開発サーバが見出しごとにスライドの骨格を作ります。
見出しがタイトルになり、ビートは箇条書きになって、どの行がどのビートで
出てくるかも、最初から結び付いています。

この時点で、もう通しの練習ができます。画面は素っ気ないですが、順番と尺は
本番と同じです。

### 骨格は出発点 {#not-the-end}

ただし、骨格はあくまで出発点です。右は、同じ見出しから仕上げたこの資料の
一枚です。台本は一文字も変えていません。変えたのは、そのスライドの HTML と
CSS だけです。

## 1 枚は、小さな 1 ファイル {#one-file}

仕上げの作業は、AI エージェントと一緒にやることが増えました。そのとき
効いてくるのが、ファイルの小ささです。

一枚のスライドは HTML ひとつで、この資料では長いものでも百行に届きません。
その一枚でしか使わない装飾は、隣の CSS に置きます。数字を動かしたいときは、
隣に TypeScript を置きます。

直すときに開くのはこの数ファイルだけで、差分もそのまま読めます。仮に
壊しても、壊れるのはその一枚だけです。

## 喋りが画面を進める {#beats}

画面を段階的に見せる仕組みも、台本から決まります。

### いつ出すかは台本 {#when}

いつ出すかは喋りの都合なので、台本のビートが決めます。本番で矢印キーを
押すと、まずビートが進み、ビートを使い切ると次のスライドに移ります。

### どう出すかはテーマ {#how}

どう出すかは見せ方の都合なので、テーマの CSS が決めます。スライドの HTML は、
要素に data-step を付けて、どのビートで出るかを書くだけです。アニメーション
のための専用の記法はありません。

## 尺は、書いた時点でわかる {#timing}

台本があれば、尺はその場で計算できます。日本語なら一分に三百文字、英語なら
百三十語で見積もります。

右は、この資料に dek ls をかけた結果です。十二分の持ち時間を、各スライドの
文章量に応じて割り振っています。長すぎるスライドは、書いているうちに目に
入ります。前日の夜を待つ必要はありません。

音声合成を使えば、見積もりの隣に、実際に読み上げた長さも並べて出せます。

## エージェントは、画面を見られない {#blind}

AI にスライドを書かせると、よく起きることがあります。HTML としては完璧
なのに、描画すると文字が枠からはみ出している。エージェントには、自分が
書いた画面が見えないからです。

### 描画して、測る {#render}

dek は、スライドを実際にブラウザで描画して測ります。はみ出しとコントラスト
不足は、どの要素が、どの辺から、何ピクセル出たかまで、機械が読める形で
返します。

### 直す場所まで返す {#report}

診断には、ファイルの場所と直し方の手がかりが付いてきます。エージェントは
それを読んで直し、もう一度測る。本番の三十分前に人が気づくより先に、この
繰り返しで片付きます。

## 規約は、lint が守る {#rules}

使ってよいクラスは、テーマにあるものだけ。色や大きさは、トークンを通して
指定する。デッキの外は参照しない。こうした規約は、ドキュメントに書いておく
だけでは守られません。

dek では、規約をすべて lint のルールにしています。ルールは構造、語彙、素材、
描画、音声の五つに分かれていて、エラーがひとつもなければ完成です。何を
もって完成とするかを、人とエージェントで同じ基準にそろえられます。

## テーマは、コピーして引き継ぐ {#themes}

トークは一度きりではありません。dek のプロジェクトには、いくつものデッキを
溜めていけます。

新しいデッキを作ると、プロジェクトのテーマがそのデッキにコピーされます。
前回のデッキから引き継ぐこともできます。共有ではなくコピーなので、九月に
テーマを直しても、四月に話したデッキの見た目は変わりません。

気に入った変更は、プロジェクトのテーマに書き戻します。過去のデッキが、
そのままテーマの見本帳になります。

## 1 ファイルで持っていく {#outputs}

本番の会場には、サーバもネットワークも要りません。dek build が、テーマも
画像も動きも含めて、トークをひとつの HTML に固めます。USB メモリに入れて、
ブラウザで開けば発表できます。

発表者ビューも、このファイルだけで開けます。同じ台本から、配布用の PDF と、
字幕とチャプターの付いた動画も書き出せます。スマホをリモコンにしたいとき
だけ、開発サーバを LAN に出します。

## 始めかた {#start}

始めるのに要るのは Bun だけです。プロジェクトを作り、台本を書き、開発
サーバを立ち上げる。配るときは build を実行します。

最初は、骨格のままで構いません。通しで喋れるようになってから、必要な
スライドだけを仕上げてください。

## まとめ {#recap}

最後に、持ち帰ってほしいことを三つにまとめます。

### 台本が親 {#recap-script}

順番も、喋る言葉も、尺も、script.md が持ちます。スライドはそこから
生えてきます。

### 1 枚は 1 ファイル {#recap-file}

スライドは小さなファイルに分かれていて、人もエージェントも一枚ずつ
直せます。

### lint が通れば完成 {#recap-lint}

規約はすべて lint が確かめます。通れば完成です。ご清聴ありがとう
ございました。
