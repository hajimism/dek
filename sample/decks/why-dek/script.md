## 台本から、発表まで {#cover}

こんにちは。今日は、dek というスライドの道具を紹介します。dek は、
喋る台本を先に書き、そこからスライドを組み立てる道具です。

十二分で、三つのことを話します。いまのスライド作りで何が後回しに
なっているか。dek がそれをどう前に持ってくるか。そして、人と AI
エージェントが同じやり方で仕上げていく流れです。

> 落ち着いて始める。目次は読み上げない。

## いまのスライド作りでは、三つのことが後回しになる {#later}

スライドを作るとき、たいてい順番はこうです。テンプレートを選び、
枠を並べ、中身を埋め、最後に喋ってみる。この順番だと、大事なことが
三つ、最後まで後回しになります。

### 尺 {#later-time}

ひとつめは尺です。喋って初めて長さがわかるので、二十分の枠に三十分
ぶん作ってしまったことに、前日の夜に気づきます。

### 見た目の確認 {#later-look}

ふたつめは見た目の確認です。文字が枠からはみ出していないか、色が
読めるかは、目で見て確かめるしかありません。見落としは、本番の
スクリーンで見つかります。

### 次の発表 {#later-next}

みっつめは次の発表です。作り込んだ部品がそのトークの中に閉じ込め
られて、次はまたゼロから作ることになります。

## dek は、台本を最初に書く {#order}

dek は、この順番を入れ替えます。最初に書くのは、喋る台本です。
台本を書いた時点で尺がわかり、画面はそのあとに組み立て、見た目は
機械が測ります。

大事なのは、台本がいちばん上にいることです。スライドの枚数も、
並び順も、どこで画面を進めるかも、すべて台本から決まります。

## ひとつの発表は、ひとつのディレクトリ {#deck}

dek では、ひとつの発表をデッキと呼び、ひとつのディレクトリに
まとめます。

中身はこれだけです。台本の script.md、スライドを一枚ずつ入れた
slides、見た目を決める theme.css、画像を置く assets。音声を付ける
なら voice も加わります。

デッキの外にあるものは、何も参照しません。ディレクトリごとコピー
すれば、何年後に開いても同じように描画されます。

## 台本は、普通の Markdown で書く {#script}

台本の書き方は、三つだけ覚えれば足ります。

### シャープ二つがスライド {#script-slide}

シャープ二つの見出しが、スライド一枚です。波かっこの中の id が、
スライドのファイル名になります。

### シャープ三つがビート {#script-beat}

シャープ三つの見出しは、ビートと呼ぶ喋りの区切りです。発表中に
矢印キーを押すと、まずビートが進み、使い切ると次のスライドに移り
ます。

### 段落は喋る言葉、引用はト書き {#script-words}

段落は、実際に喋る言葉です。尺の見積もりにも、音声の読み上げにも
使われます。引用は自分へのメモなので、どちらにも数えません。先頭の
duration には、持ち時間を書きます。

## 保存すると、骨格のスライドができる {#skeleton}

台本を保存すると、開発サーバが見出しごとにスライドの骨格を作り
ます。見出しがタイトルになり、ビートは箇条書きになって、どの行が
どのビートで出てくるかも、最初から結び付いています。

### 骨格のまま、通しで練習できる {#skeleton-raw}

この時点で、もう通しで練習できます。画面は素っ気ないですが、枚数と
順番と尺は、本番と同じです。

### 仕上げても、台本は変わらない {#skeleton-done}

画面を仕上げるのは、そのあとです。右は、同じ骨格から仕上げた一枚
です。変えたのはスライドの HTML と CSS だけで、台本は一文字も
変えていません。

## 一枚のスライドは、小さなファイル {#files}

仕上げの単位は、スライド一枚です。一枚は HTML のファイルひとつで、
この資料では長いものでも百行ほどです。

その一枚だけで使う装飾は、隣に同じ名前の CSS を置きます。数字を
数え上げたり、グラフを描いたりする動きは、隣に TypeScript を置き
ます。

直すときに開くのはこの数ファイルだけなので、差分がそのまま読め
ます。壊しても、壊れるのはその一枚だけです。

## いつ出すかは台本、どう出すかはテーマ {#beats}

画面を段階的に見せる仕組みも、役割を分けています。

### いつは、台本のビート {#beats-when}

いつ出すかは、喋りの都合です。だから台本のビートが決めます。
スライドの HTML は、要素に data-step を付けて、どのビートで出るかを
書くだけです。

### どうは、テーマの CSS {#beats-how}

どう出すかは、見せ方の都合です。フェードでも、下から滑り込むので
も、テーマの CSS が決めます。アニメーションのための独自の記法は
ありません。

## 動きは、時間の関数として書く {#motion}

CSS で書けない動きは、スクリプトで書きます。書き方の約束は
ひとつだけです。経過時間を受け取って、その瞬間の画面を描く関数と
して書くことです。

同じ時刻を渡せば、必ず同じ画面になる。この約束があるので、発表中は
滑らかに動き、PDF やスクリーンショットには動き終わった姿が写り、
動画にはコマ送りで正確に記録されます。一つのスクリプトが、どの
出力でも同じように振る舞います。

## 尺は、書いているうちにわかる {#timing}

台本があれば、尺はその場で見積もれます。日本語なら一分に三百文字、
英語なら百三十語で数えます。

右は、この資料に dek ls をかけた結果です。十二分の持ち時間を、
各スライドの文章量に応じて割り振っています。どのスライドが長すぎる
かは、書いている途中で目に入ります。前日の夜を待つ必要はありません。

## 見た目は、描画して測る {#measure}

見た目の確認も、目に頼りません。dek は、スライドを実際にブラウザで
描画して測ります。

### はみ出しは、何ピクセルかまで {#measure-overflow}

文字が枠からはみ出していれば、どの要素が、どの辺から、何ピクセル
出たかを返します。すべてのビートで測るので、途中で出てくる要素も
見逃しません。

### 読みにくい色は、比で返す {#measure-contrast}

文字と背景のコントラストも、描画された画素から測ります。基準に
届かなければ、どこの文字かと、その比率を返します。

## 規約は、すべて lint が確かめる {#lint}

使ってよいクラスは、テーマにあるものだけ。色や大きさは、トークンと
呼ぶ変数を通して指定する。画像はデッキの中に置く。こうした規約は、
書いておくだけでは守られません。

dek は、規約をすべて lint のルールにしています。ルールは構造、語彙、
素材、描画、音声の五つの層に分かれ、全部で三十一あります。エラーが
ひとつもなければ完成です。何をもって完成とするかが、はっきり決まって
います。

## エージェントとも、同じループを回す {#agents}

このはっきりした基準が、AI エージェントと一緒に作るときに効いて
きます。

### 一枚ぶんを、まとめて読む {#agents-read}

エージェントは dek show で、一枚のスライドに関わる台本、HTML、CSS、
そこで使っているテーマの規則を、まとめて受け取ります。テーマ全体を
読む必要はありません。

### 描いて、測って、直す {#agents-check}

書き終えたら dek check で、診断とスクリーンショットを受け取ります。
結果は決まった形の JSON で返り、直し方の手がかりも付いています。
エージェントはそれを読んで直し、もう一度測ります。人が画面を確かめる
前に、この繰り返しで片付きます。

## ほかの人の発表からも、学べる {#refs}

お手本は、手元のデッキに限りません。dek ref を使うと、GitHub に
公開されている dek のデッキを、版を固定して手元に取ってこられます。

取ってきたデッキは読み取り専用で、構成や尺を見たり、一枚の作りを
読んだり、描画して確かめたりできます。使いたい部分は、自分のテーマで
書き直して取り込みます。自分のデッキが、よそのデッキに依存することは
ありません。

## テーマはコピーして、そのまま凍らせる {#themes}

発表は、一度きりでは終わりません。一つのプロジェクトに、いくつもの
デッキを溜めていけます。

新しいデッキを作ると、プロジェクトのテーマがそのデッキにコピー
されます。共有ではなくコピーなので、秋にテーマを直しても、春に
話したデッキの見た目は変わりません。終わった発表は、終わったときの
姿のまま残ります。

## 本番に持っていくのは、HTML がひとつ {#outputs}

本番の会場には、サーバもネットワークも要りません。dek build が、
テーマも画像も動きも含めて、発表をひとつの HTML ファイルにまとめ
ます。ブラウザで開けば、そのまま発表できます。

同じファイルから、発表者ビューも開けます。同じ台本からは、配布用の
PDF も、音声合成で読み上げた字幕付きの動画も書き出せます。

## 始めるのに要るのは、Bun だけ {#start}

始めるのに必要なのは、Bun だけです。プロジェクトを作り、台本を書き、
開発サーバを立ち上げる。配るときは build を実行します。

最初は骨格のままで構いません。通しで喋れるようになってから、必要な
スライドだけを仕上げてください。

## 持ち帰ってほしい、三つのこと {#recap}

最後に、三つだけ持ち帰ってください。

### 台本がいちばん上 {#recap-script}

順番も、喋る言葉も、尺も、台本が持っています。スライドはそこから
生まれます。

### 一枚は、小さなファイル {#recap-files}

スライドは一枚ずつの小さなファイルなので、人もエージェントも、
一枚ずつ直せます。

### lint が通れば、完成 {#recap-lint}

規約はすべて lint が確かめます。通れば完成です。ご清聴ありがとう
ございました。
