## 台本から、発表まで {#cover}

こんにちは。今日は、dek というスライドツールを紹介します。dek は、
喋る台本を先に書き、そこからスライドを組み立てるツールです。

十二分で三つのことを話します。いまのスライド作りで何が後回しに
なっているか。dek がそれをどう前に持ってくるか。そして、人と AI
エージェントが同じやり方で仕上げていく流れです。

> 落ち着いて始める。目次は読み上げない。

## いまのスライド作りでは、三つのことが後回しになる {#later}

スライドを作るとき、たいてい順番はこうです。テンプレートを選び、
枠を並べ、中身を埋め、最後に喋ってみる。この順番だと、大事な三つの
ことが最後まで後回しになります。

### 尺 {#later-time}

ひとつめは尺です。喋って初めて長さがわかるので、二十分の枠に三十分
ぶん作ってしまったことに前日の夜に気づきます。

### 見た目の確認 {#later-look}

ふたつめは見た目の確認です。文字が枠からはみ出していないか、色が
読めるかは、目で見て確かめるしかありません。見落としは本番の
スクリーンで見つかります。

### 次の発表 {#later-next}

みっつめは次の発表です。作り込んだ部品はそのトークの中でしか使えず、
次はまたゼロから作ることになります。

## dek は台本を最初に書く {#order}

dek はこの順番を入れ替えます。最初に書くのは喋る台本です。台本を
書いた時点で尺がわかり、画面はそのあとに組み立て、見た目は機械が
測ります。

台本がいちばん上にあることが大事です。スライドの枚数も並び順も、
どこで画面を進めるかも、すべて台本から決まります。

## ひとつの発表はひとつのディレクトリ {#deck}

dek では、ひとつの発表をデッキと呼び、ひとつのディレクトリに
まとめます。

中身はこれだけです。台本の script.md、スライドを一枚ずつ入れた
slides、見た目を決める theme.css、画像を置く assets。音声を付ける
なら voice も加わります。

デッキの外にあるものは何も参照しません。ディレクトリごとコピー
すれば、何年後に開いても同じように描画されます。

## 台本は普通の Markdown で書く {#script}

台本の書き方は三つだけ覚えれば足ります。

### シャープ二つがスライド {#script-slide}

シャープ二つの見出しがスライド一枚です。波かっこの中の id が、
スライドのファイル名になります。

### シャープ三つがビート {#script-beat}

シャープ三つの見出しは、ビートと呼ぶ喋りの区切りです。発表中に
矢印キーを押すと、まずビートが進み、使い切ると次のスライドに移り
ます。

### 段落は喋る言葉、引用はト書き {#script-words}

段落は実際に喋る言葉です。尺の見積もりにも、音声の読み上げにも
使われます。引用は自分へのメモなので、どちらにも数えません。先頭の
duration には持ち時間を書きます。

## 保存すると骨格スライドができる {#skeleton}

台本を保存すると、開発サーバーが見出しごとにスライドの骨格を作り
ます。見出しがタイトルになり、ビートは箇条書きになります。どの行が
どのビートで出てくるかも最初から決まっています。

### 骨格のまま通しで練習できる {#skeleton-raw}

この時点で、もう通しで練習できます。画面は素っ気ないですが、枚数と
順番と尺は本番と同じです。

### 仕上げても台本は変わらない {#skeleton-done}

画面を仕上げるのはそのあとです。右は、同じ骨格から仕上げたスライド
です。変えたのはスライドの HTML と CSS だけで、台本は一文字も
変えていません。

## 一枚のスライドは小さなファイル {#files}

仕上げの単位はスライド一枚です。一枚は HTML ファイルひとつで、
この資料では長いものでも百行ほどです。

そのスライドだけで使う装飾は、隣に同じ名前の CSS を置きます。数字を
数え上げたりグラフを描いたりする動きは、隣に TypeScript を置き
ます。

直すときに開くのはこの数ファイルだけなので、差分がそのまま読め
ます。書き間違えても、崩れるのはその一枚だけです。

## いつ出すかは台本、どう出すかはテーマ {#beats}

画面を段階的に見せる仕組みも役割を分けています。

### いつは台本のビート {#beats-when}

いつ出すかは喋りの都合なので、台本のビートが決めます。スライドの
HTML は、要素に data-step を付けてどのビートで出るかを書くだけ
です。

### どうはテーマの CSS {#beats-how}

どう出すかは見せ方の都合です。フェードでも下から滑り込むのでも、
テーマの CSS が決めます。アニメーションのための独自の記法は
ありません。

## 動きは時間の関数として書く {#motion}

CSS で書けない動きはスクリプトで書きます。書き方の約束はひとつだけ
です。経過時間を受け取って、その瞬間の画面を描く関数として書くこと
です。

同じ時刻を渡せば必ず同じ画面になる。この約束があるので、発表中は
滑らかに動き、PDF やスクリーンショットには動き終わった姿が写り、
動画にはコマ送りで正確に記録されます。ひとつのスクリプトが、どの
出力でも同じように振る舞います。

## 尺は書いているうちにわかる {#timing}

台本があれば、尺はその場で見積もれます。日本語なら一分に三百文字、
英語なら百三十語で数えます。

右は、この資料に dekc ls を実行した結果です。十二分の持ち時間を、
各スライドの文章量に応じて割り振っています。どのスライドが長すぎる
かは書いている途中でわかります。前日の夜を待つ必要はありません。

## 見た目は描画して測る {#measure}

見た目の確認も目に頼りません。dek はスライドを実際にブラウザで描画
して測ります。

### はみ出しは何ピクセルかまで {#measure-overflow}

文字が枠からはみ出していれば、どの要素がどの辺から何ピクセル出たか
を返します。すべてのビートで測るので、途中で出てくる要素も見逃し
ません。

### 読みにくい色は比で返す {#measure-contrast}

文字と背景のコントラストも描画された画素から測ります。基準に届か
なければ、どこの文字かとその比率を返します。

## 規約はすべて lint が確かめる {#lint}

使ってよいクラスはテーマにあるものだけ。色や大きさはトークンと呼ぶ
変数を通して指定する。画像はデッキの中に置く。こうした規約は書いて
おくだけでは守られません。

dek は規約をすべて lint のルールにしています。ルールは構造、語彙、
素材、音声、描画の五つの層に分かれ、全部で四十三あります。エラーが
ゼロになれば、測れる問題は残っていません。何を満たせばよいかが
はっきり決まっています。

## エージェントとも同じループを回す {#agents}

合否の基準がはっきりしていると、AI エージェントと一緒に作るときに
役に立ちます。

### 一枚ぶんをまとめて読む {#agents-read}

エージェントは dekc show で、一枚のスライドに関わる台本、HTML、CSS、
そこで使っているテーマの規則をまとめて受け取ります。テーマ全体を
読む必要はありません。

### 描いて、測って、直す {#agents-check}

書き終えたら dekc check で診断とスクリーンショットを受け取ります。
結果は決まった形の JSON で返り、直し方の手がかりも付いています。
エージェントはそれを読んで直し、もう一度測ります。人が画面を確かめる
前に、この繰り返しで片付きます。

## ほかの人の発表からも学べる {#refs}

お手本は手元のデッキに限りません。dekc ref を使うと、GitHub に公開
されている dek のデッキを、コミットを固定して手元に取ってこられます。

取ってきたデッキは読み取り専用で、構成や尺を見たり、スライドの作りを
読んだり、描画して確かめたりできます。使いたい部分は自分のテーマで
書き直して取り込みます。自分のデッキがよそのデッキに依存することは
ありません。

## テーマはコピーして凍結する {#themes}

発表は一度きりでは終わりません。ひとつのプロジェクトにいくつもの
デッキを溜めていけます。

新しいデッキを作ると、プロジェクトのテーマがそのデッキにコピーされ
ます。共有ではなくコピーなので、秋にテーマを直しても、春に話した
デッキの見た目は変わりません。終わった発表は終わったときの姿のまま
残ります。

## 本番に持っていくのは HTML がひとつ {#outputs}

本番の会場には、サーバーもネットワークも要りません。dekc build が、
テーマも画像も動きも含めて発表をひとつの HTML ファイルにまとめます。
ブラウザで開けば、そのまま発表できます。

同じファイルから発表者ビューも開けます。同じ台本からは配布用の
PDF も、音声合成で読み上げた字幕付きの動画も書き出せます。

## 始めるのに要るのは Bun だけ {#start}

始めるのに必要なのは Bun だけです。プロジェクトを作り、台本を書き、
開発サーバーを立ち上げる。配るときは build を実行します。

最初は骨格のままで構いません。通しで喋れるようになってから、必要な
スライドだけを仕上げてください。

## 持ち帰ってほしい三つのこと {#recap}

最後に、三つだけ持ち帰ってください。

### 台本がいちばん上 {#recap-script}

順番も喋る言葉も尺も、すべて台本が基準です。スライドはそこから作ら
れます。

### 一枚は小さなファイル {#recap-files}

スライドは一枚ずつの小さなファイルなので、人もエージェントも一枚ずつ
直せます。

### 測れるものは lint が決める {#recap-lint}

規約はすべて lint が確かめます。通れば、測れる問題は残っていません。
ご清聴ありがとうございました。
